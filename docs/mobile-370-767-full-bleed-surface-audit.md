# 370~767px 모바일 Full-bleed·거터·보더·Radius 전수조사

> 작성일: 2026-07-14  
> 대상: 공개 사용자 페이지 전체  
> 제외: `/admin/**`, `/records/**`, 내부 실험용 `/lab/**`  
> 적용 범위: **370px 이상 767px 이하**  
> 범위 제외: 369px 이하, 768px 이상  
> 상위 화면 보호: 768px 이상에서는 이 문서의 모바일 전용 변경을 적용하지 않는다.  
> 문서 성격: 화면 기획 및 구현 판단서. 이 문서 작성 시 UI 코드는 수정하지 않았다.

## 1. 목적

현재 모바일 화면은 페이지 공통 컨테이너에 가로 패딩이 적용되고, 그 내부에서 다시 보더·라운드·패딩을 가진 카드가 중첩되는 경우가 많다. 그 결과 370~767px 화면에서 실제 콘텐츠 폭이 지나치게 좁아지고, 게시글·댓글·경기 목록·데이터 표처럼 본래 연속적으로 읽어야 할 콘텐츠까지 작은 카드 안에 갇힌다.

이 문서는 모든 콘텐츠를 무조건 full-bleed로 바꾸자는 제안이 아니다. 각 블록을 다음 세 종류로 분류하고 모바일 표현을 다르게 적용하기 위한 기준이다.

| 유형 | 대표 콘텐츠 | 370~767px 가로 처리 | 외곽 보더·Radius |
|---|---|---|---|
| 페이지 문맥 | 제목, 설명, 필터, 폼 | 좌우 16px | 필요할 때만 유지 |
| 연속 콘텐츠 | 목록, 게시글, 순위, 경기 데이터 | 화면 끝까지 확장 | 제거, 행 divider 사용 |
| 독립 기능 | 미디어, 선택 카드, 입력 컨트롤 | 좌우 16px 또는 의도적 스크롤 | 유지 |

핵심 원칙은 **페이지 전체에 패딩을 주지 않고, 패딩이 필요한 자식 블록만 거터를 갖게 하는 것**이다.

## 2. 현재 구조에서 확인된 공통 문제

### 2.1 공통 컨테이너의 일괄 가로 패딩

`layout-wide`, `layout-reading`, `layout-form`, `fan-page-container` 같은 공통 컨테이너가 모바일에서도 페이지 전체에 거터를 적용한다. 제목과 폼에는 적절하지만, 목록·본문·표·탭·미디어까지 동일한 폭으로 좁아진다.

### 2.2 SurfacePanel의 일괄 카드화

`components/ui/surface-panel.tsx`는 보더, 배경, overflow hidden, 카드 radius를 한 번에 적용한다. 커뮤니티 상세처럼 문서형 화면에도 이 컴포넌트를 사용하면서, 페이지 전체가 큰 카드 한 장으로 표현된다.

### 2.3 모바일 DataTable의 외곽 카드

`components/ui/data-table.tsx`는 모바일 행 표현을 이미 별도로 제공하지만, 그 목록 전체를 다시 rounded border 컨테이너로 감싼다. 팀 기록·순위·선수 기록처럼 연속된 데이터는 외곽 카드 없이 행 divider만 사용하는 편이 적합하다.

### 2.4 중첩 Radius

다음 형태가 반복된다.

```text
페이지 거터
└─ rounded 외곽 카드
   ├─ rounded 내부 카드
   └─ rounded 입력창/버튼
```

모바일에서는 최상위 외곽 카드부터 제거하고, 실제 조작 대상이나 독립 미디어에만 radius를 남겨야 한다.

## 3. 370~767px 공통 수치

| 항목 | 기준값 |
|---|---:|
| 일반 텍스트·제목 거터 | 16px |
| 조밀한 데이터 행 내부 패딩 | 12px |
| 전체 폭 목록 행 좌우 패딩 | 16px |
| 섹션 간 세로 간격 | 24~32px |
| 연속 목록 외곽 radius | 0 |
| 독립 카드 radius | 10~12px |
| 이미지·영상 radius | 8~12px |
| 입력창·버튼 radius | 8~12px |
| 바텀시트 radius | 위쪽 20~24px |
| 일반 터치 영역 | 최소 44×44px |
| 섹션·행 구분 | 1px 수평 divider |

16px보다 큰 radius는 브랜딩 히어로, 명확한 독립 기능, 바텀시트처럼 시각적 경계가 반드시 필요한 경우에만 사용한다.

## 4. 적용 범위와 공통 구현 구조

### 4.1 Breakpoint 계약

이 문서의 변경은 `370px <= viewport <= 767px`에서만 활성화한다.

| 화면 폭 | 처리 |
|---|---|
| 0~369px | 지원·검수 대상에서 제외 |
| 370~767px | 이 문서의 모바일 전용 구성 적용 |
| 768px 이상 | 기존 태블릿·PC 레이아웃 유지 |

767px까지는 같은 모바일 정보 구조와 컴포넌트 규칙을 사용한다. 화면이 넓어졌다는 이유로 600~767px 구간에서 갑자기 데스크톱 카드나 2단 사이드바를 복원하지 않는다. 다만 선수·미디어처럼 카드 폭이 과도하게 넓어지는 콘텐츠는 동일한 모바일 구조 안에서 열 수만 조정할 수 있다.

### 4.2 공통 shell 구조

370~767px의 페이지 shell은 전체 폭을 기본으로 하고, 필요한 블록에만 거터를 적용해야 한다.

```text
page (width: 100%)
├─ page heading                    → 좌우 16px
├─ filter/tabs                     → 전체 폭, 내부 정렬 16px
├─ continuous content/list         → 전체 폭, 외곽 radius 0
│  └─ row/text                     → 내부 좌우 16px
├─ independent interactive module  → 좌우 16px, radius 유지
└─ media rail                      → 첫 항목 16px 정렬, 우측 끝까지 스크롤
```

full-bleed는 문서 전체의 `overflow-x: hidden`으로 문제를 감추는 방식으로 구현하면 안 된다. 부모가 16px 패딩을 강제하는 기존 구조를 분리하거나, 370~767px에서만 활성화되는 제한적인 모바일 full-bleed 유틸리티를 사용해야 한다. 768px 이상 스타일에는 이 유틸리티가 영향을 주면 안 된다.

## 5. 첨부 예시: 커뮤니티 게시글 상세

첨부 화면의 게시글 외곽 보더와 radius는 제거하는 편이 적합하다.

현재 폭 손실 구조:

```text
페이지 16px 거터
→ 게시글 SurfacePanel
→ SurfacePanel 내부 16px
→ 댓글 입력 카드
→ 댓글 입력 내부 16px
```

권장 구조:

- `게시글` 페이지 제목: 좌우 16px 유지
- 광고: 독립 광고 모듈이면 좌우 16px와 radius 유지 가능
- 게시글 본문: 전체 폭
- 게시글 외곽 보더와 radius: 제거
- 제목·작성자·본문: 내부 좌우 16px
- 본문 영역 구분: 수평 divider
- 추천·비추천·신고 행: 전체 폭, 위아래 divider
- 댓글 제목과 댓글 목록: 전체 폭
- 댓글 목록 외곽 카드: 제거
- 댓글 입력창: 좌우 16px 안에서 radius 유지
- 대댓글 들여쓰기: 최대 16~24px
- 푸터: 전체 폭 배경과 상단 divider, 내부 텍스트만 좌우 16px

본문과 댓글을 감싸는 큰 카드는 없애고, 댓글 입력처럼 실제 조작하는 컨트롤에만 radius를 남긴다.

## 6. 페이지별 화면 기획

### 6.1 메인 `/`

| 영역 | 가로 처리 | 보더·Radius 판단 |
|---|---|---|
| 대표 비주얼·미디어 | 전체 폭 | 모바일 외곽 radius 제거 |
| 섹션 제목·전체보기 | 16px | 없음 |
| 다음 경기 | 전체 폭 한 줄/두 줄 스트립 | 외곽 카드 제거, divider |
| 순위표 | 전체 폭 행 목록 | 외곽 카드 제거 |
| 최신 커뮤니티 | 전체 폭 행 목록 | 외곽 카드 제거 |
| 영상 캐러셀 | 첫 카드 16px 정렬, 우측 full-bleed | 썸네일 radius 유지 |
| 팀·선수 탐색 카드 | 16px | 10~12px 유지 |

다음 경기와 순위는 작은 카드 여러 개보다 한 화면에서 빠르게 훑는 정보 스트립으로 구성한다.

### 6.2 경기 일정 `/schedule`

- 페이지 제목과 필터 버튼: 좌우 16px
- 연도·대회·팀 필터: 전체 폭 sticky strip
- 날짜 제목: 좌우 16px
- 날짜별 경기 목록: 전체 폭
- 날짜 묶음 외곽 보더와 radius: 제거
- 경기 사이: 행 divider
- 오늘 경기: 둥근 2px 외곽선 대신 배경 강조 또는 왼쪽 3px 강조선
- 달력: 본문 대형 카드 대신 아이콘 버튼 → 바텀시트
- 필터·달력 버튼: radius 유지
- 빈 상태: 좌우 16px의 독립 박스 허용

### 6.3 대회 목록·상세 `/tournaments`, `/tournaments/[segment]`

- 대회 브랜딩 카드: 좌우 16px와 radius 유지
- 연도·상태 필터: 전체 폭 가로 스크롤
- 상세 상단 탭: 전체 폭 sticky strip, 외곽 radius 없음
- 순위표: 전체 폭 행 목록
- 일정: `/schedule`과 동일한 divider 목록
- 대진표: 화면 전체 폭의 지역 가로 스크롤
- 대진 노드: 독립 단위이므로 radius 유지
- 소개문: 좌우 16px

### 6.4 팀 목록·상세 `/teams`, `/teams/[teamSlug]`

팀 목록:

- 전체 폭 행 목록으로 구성
- 팀별 외곽 카드와 radius 제거
- 로고·팀명·약칭·화살표를 한 행에 배치
- 팀 사이 divider
- 팬페이지 이동을 별도의 카드 하단처럼 분리하지 않음

팀 상세:

- 팀 히어로: 전체 폭, 외곽 radius 제거
- 히어로 내부 텍스트: 좌우 16px
- 로스터 이미지 카드: radius 유지
- 주요 지표 2열 타일: 8~12px radius, 굵은 외곽 보더 제거
- 경기 이력·수상 기록: 전체 폭 행 목록
- 빈 상태: 독립 rounded 박스 허용

### 6.5 선수 목록·상세 `/players`, `/players/[playerSlug]`

선수 목록은 이미지 탐색 특성이 있으므로 카드 유지 대상이다.

- 목록 그리드: 좌우 16px
- 2열 선수 이미지 카드: radius 10~12px
- 카드 외곽 보더: 약하게 하거나 제거
- 필터·검색 컨트롤: radius 유지
- 선수 상세 히어로: 전체 폭, 외곽 radius 제거
- 선수 정보: 좌우 16px
- 지표 타일: 작은 radius 유지
- 챔피언 기록·최근 경기: 전체 폭 행 목록
- 소속·수상 이력: 외곽 카드 제거
- SNS 아이콘·필터 칩: radius 유지

### 6.6 승부예측 `/predictions`

- 주차·날짜·대회 선택부: 전체 폭 sticky strip
- 필터 전체를 감싸는 rounded card: 제거
- 날짜 제목: 좌우 16px
- 개별 예측 경기: 좌우 16px 독립 카드 유지
- 팀 선택·LP 입력·금액 버튼: radius 유지
- 리더보드: 전체 폭 행 목록, 외곽 카드 제거
- 모바일 예측 다이얼로그: 중앙 모달 대신 바텀시트
- 바텀시트: 위쪽 radius만 유지

경기 예측은 하나의 완결된 상호작용 단위이므로 full-bleed 목록으로 평면화하지 않는다.

### 6.7 매치 상세 `/matches/[matchId]`

- 페이지 제목: 좌우 16px
- 양 팀·점수 요약: 전체 폭
- 점수 요약 외곽 좌우 보더와 radius: 제거
- 요약 상하 divider 유지
- 탭: 전체 폭 sticky strip
- 세트 선택: 전체 폭 가로 스크롤
- 미리보기·상대 전적: 전체 폭 행 목록
- 승부예측: 좌우 16px 독립 카드 유지
- POM·팬 평점: 전체 폭 목록 또는 작은 타일
- VOD: 전체 폭, 모바일 radius 제거
- 영상 설명·외부 링크: 좌우 16px

### 6.8 세트 상세·스냅샷

대상:

- `/matches/[matchId]/sets/[setId]`
- `/matches/[matchId]/sets/[setId]/snapshot`

판단:

- KDA·골드·오브젝트 비교: divider 비교 행
- 피해량 비교: 전체 폭
- 팀별 선수 스탯 외곽 rounded card: 제거
- 선수별 행: divider 사용
- 챔피언·아이템·룬 아이콘: 작은 radius 유지
- 밴픽: 전체 폭, 픽·밴 이미지에만 radius 유지

이 페이지군은 외곽 카드 안에 내부 카드가 반복되는 현재 구조를 가장 우선적으로 평면화해야 한다.

### 6.9 주간 리포트 `/reports`, `/reports/[week]`

- 리포트 커버 히어로: 전체 폭, 모바일 radius 제거
- 커버 내부 텍스트: 20px 안팎 패딩
- 주차 선택 칩: 좌우 16px 영역에서 가로 스크롤
- 핵심 수치 2×2 타일: radius 유지
- 경기 리뷰·선수 순위·챔피언 순위: 전체 폭 목록
- 순위 항목별 반복 rounded card: 제거
- 편집 특집·스포트라이트: 독립 콘텐츠이므로 radius 유지
- 장문 본문: 좌우 16px

### 6.10 일반 커뮤니티 `/community/**`

목록:

- 페이지 제목: 좌우 16px
- 카테고리 탭: 전체 폭
- 게시글 목록 외곽 보더와 radius: 제거
- 게시글 행: 전체 폭, 내부 좌우 16px
- 썸네일: radius 유지
- 검색창: 좌우 16px, radius 유지
- 글쓰기: FAB 또는 하단 주요 액션 검토

상세:

- 큰 `SurfacePanel` 제거

- 댓글 입력 컨트롤만 radius 유지

글쓰기·수정:

- 에디터 전체를 `SurfacePanel`로 다시 감싸지 않음
- 페이지는 전체 폭
- 제목·카테고리·툴바: 좌우 16px
- 에디터 본문 외곽 radius 제거 또는 최대 8px
- 등록 버튼: 좌우 16px
- 모바일 툴바: 한 줄 가로 스크롤, 여러 줄 wrapping 금지

## 7. 공통 컴포넌트 변경 방향

이 문서는 구현하지 않았지만, 실제 작업 시 다음 공통 컴포넌트부터 분리해야 페이지별 예외가 안정적으로 적용된다.

### 7.1 페이지 shell과 콘텐츠 거터 분리

- 페이지 shell: 모바일 `width: 100%`
- `mobile-gutter` 역할: 제목·설명·폼에만 16px
- `mobile-full-bleed` 역할: 목록·본문·미디어
- 데스크톱 width 토큰은 이 변경과 분리하여 유지

### 7.2 SurfacePanel variant 분리

필요한 variant 예시:

- `card`: 독립 카드, 보더/radius 유지
- `section`: 모바일 외곽 보더/radius 제거
- `list`: 외곽 없이 행 divider
- `media`: 모바일 full-bleed

### 7.3 DataTable 모바일 shell 분리

- 모바일 outer border/radius 제거 가능 옵션
- 행 좌우 16px
- 행 divider 유지
- 데스크톱 table shell은 기존 표현 유지

### 7.4 모바일 미디어 rail 규칙

- section heading: 16px
- scroll container: 전체 폭
- 첫 항목 앞 여백: 16px
- 마지막 항목 뒤 여백: 16px
- 문서 수준 가로 스크롤은 금지

## 9. 구현 후 370~767px 검수 항목

필수 고정 검수 폭은 `370px`, `390px`, `430px`, `600px`, `767px`다. 또한 370px에서 767px까지 브라우저 폭을 연속으로 드래그해 중간 구간에서 갑작스러운 wrapping, 겹침, 레이아웃 전환이 발생하지 않는지 확인한다.

- 문서 수준 가로 스크롤이 없는가
- 의도한 캐러셀·대진표만 지역 가로 스크롤을 사용하는가
- 큰 외곽 카드 안에 작은 카드가 중첩되지 않는가
- 연속 목록이 화면 폭을 충분히 사용하는가
- 제목·본문·행 텍스트는 16px 기준선에 정렬되는가
- 이미지와 영상이 비율을 유지하는가
- 긴 팀명·선수명·게시글 제목이 버튼과 겹치지 않는가
- 탭이 줄바꿈되지 않고 스크롤 또는 축약 규칙을 사용하는가
- sticky 탭과 하단 작성창이 헤더·푸터와 겹치지 않는가
- 모달·바텀시트의 닫기 및 주요 액션이 화면 안에 남는가
- 버튼과 입력 컨트롤의 터치 영역이 최소 44px인가
- 댓글·대댓글이 지나친 들여쓰기로 좁아지지 않는가
- 빈 상태·오류·로딩 상태에도 동일한 폭 규칙이 적용되는가

## 10. 완료 판정 조건

이 문서는 구조 기획서이며 반응형 구현 완료를 의미하지 않는다. 실제 완료 판정은 다음 조건을 모두 충족해야 한다.

1. 위 공통 구조를 적용한다.
2. 공개 페이지를 370px, 390px, 430px, 600px, 767px 실제 브라우저에서 페이지별로 확인한다.
3. 겹침, 불필요한 줄바꿈, 잘림, 중첩 카드, 의도하지 않은 가로 스크롤을 수정한다.
4. 수정 후 370~767px 구간을 다시 확인한다.
5. 768px 경계와 대표 PC 화면에서 기존 스타일이 변경되지 않았는지 회귀 확인한다.
