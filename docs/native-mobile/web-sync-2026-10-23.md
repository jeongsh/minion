# 웹 변경의 앱 통합

사용자가 2026-10-23 감사에서 확인한 6개 누락의 웹 일치 구현을 요청했다.

## 범위와 계약

- 홈 잠금 파일 `mobile/app/(tabs)/index.tsx`는 웹 `components/domain/home-dashboard.tsx`, `home-match-card.tsx`, `celebration-banner.tsx`, `celebration-slides.tsx`, `components/news/home-news-section.tsx`를 근거로 뉴스, 대회 로고, 축하 배너 순서와 슬라이드만 통합 변경한다. 폰트 자산, 헤더, 독바, 인증과 프로필 수정은 제외한다.
- 홈 API는 웹의 `getHomeNewsFeed(6)`, `ALL_SEGMENTS`와 `matchesTournamentSegment`, `getTodayCelebrations`를 재사용한다. 축하 배너의 팀 색상과 로고, 문구와 목적지를 선택 필드로 추가한다. 기존 v1 필드를 유지한다.
- 매치 API는 웹과 같은 `matchBriefingSample`, `getPlayerBenchmarkStatLines`, `buildMatchBriefingStats`, `getPowerRankings`, `teamPowerRanking`을 사용한다. 참가 팀이 확정된 프리뷰 조회에만 부가 데이터를 가져온다. 기존 프리뷰 필드를 유지하고 선택적 `briefing` 데이터를 추가한다.
- 챔피언 API는 기존 `buildChampionAnalysis`의 15분 CS, 표본 수, 선수 조합과 상대 조합을 선택 필드로 전달한다. 원본 데이터의 정렬, 수치와 표본 기준을 유지한다.
- 이적시장 앱은 웹의 거피셜 제외 조건, 재계약 노출 기간과 다음 로스터 합성 규칙을 그대로 적용한다. 기존 원문 기사 링크 변경을 보존한다.

## 구현과 검증

- 홈 뉴스 6개와 기사 제목/썸네일 보완 조회, 대회별 로고, 축하 배너 순서와 자동 슬라이드를 연결했다. 기사 보완 조회는 모바일 CORS 응답을 제공하는 `/api/mobile/v1/news/article`에서 기존 웹 서비스를 재사용한다.
- 이적시장의 거피셜, 재계약과 다음 로스터 합성 규칙을 반영했다. 다른 채팅의 원문 기사 링크와 합류/이탈 목록 배치 변경을 보존했다.
- 매치 브리핑의 8축 레이더와 파워 랭킹 추이, 팀 수치, 이슈와 출처를 연결했다. 두 팀 프로필은 사용자의 추가 요청에 따라 웹과 앱 모두 세로로 배치했다. 다른 채팅에서 추가한 해외팀 보완 서비스도 유지한다.
- 챔피언 상대별 15분 CS, 선수 조합과 상대 조합 펼치기, 프로 선수 표, 경기별 8개 아이템 슬롯과 20행 페이지 이동을 반영했다. 기존 대회 표와 공유하는 네이티브 표를 추출했다.
- 웹 및 앱 타입 검사, 앱 린트, 웹 타이포그래피 검사와 변경 파일 ESLint를 통과했다. 앱 린트의 기존 경고 2개는 유지한다. 키보드 계약 4개를 통과했다. 모바일 계약은 5개 중 4개 통과하며, 기존 GET matches 공개/선택 인증 기대값 불일치 1개가 남는다.
- 실제 데이터의 웹/Expo Web 브리핑을 390, 768, 1440px 라이트/다크에서 확인했다. 두 프로필의 세로 배치와 280px 차트 높이, 문서 가로 넘침 없음을 확인했다. 홈 뉴스와 대회 로고, 축하 배너, 이적시장 거피셜, 챔피언 조합 펼치기와 경기 다음 페이지를 실행 확인했다. 캡처는 `.tmp/mobile-web-sync-20261023/screens`에 있다.
- Android Hermes 번들 내보내기는 성공했다. APK/AAB 빌드와 Android 스토어 제출은 수행하지 않았다. iPhone/Android 실기기, 네이티브 safe area 및 1px 전체 비교는 미실행이므로 해당 완료 조건 통과를 주장하지 않는다.

## iOS TestFlight

- EAS production iOS 1.0.2 빌드 5: `68d82bd7-0f23-4552-8c58-9f24f0617e4b`, 빌드 성공.
- TestFlight 제출: `6babd3ab-07cf-4a5c-843d-5bd8c7b94341`, 업로드 성공. App Store 심사 제출은 수행하지 않는다.
- Apple 상태 조회에서 빌드 5의 `processingState=VALID`, `internalState=IN_BETA_TESTING`을 확인했다. App Store Connect 실제 화면에서도 `1.0.2 (5)`와 내부 그룹 `Team (Expo)`의 테스터 2명을 확인했다.
- 최초 자동 제출의 테스트 설명 등록은 Expo Enterprise 제한으로 실패해, 동일 빌드를 설명 옵션 없이 다시 제출했다. 사용자는 이후 필요한 테스트 설명을 직접 작성해 App Store Connect에 등록하는 방식을 승인했다.
- 원격 buildNumber 4는 첫 업로드 중단 과정에서 예약됐으며 완료 빌드는 5다. EAS 업로드에서 웹 소스와 자격 증명 파일 등을 제외하는 `.easignore`를 추가했다.
- 운영 웹 배포는 최신 커밋 `8bd888d1`의 별도 소스에 이번 홈/매치/기사 API, 챔피언 DTO, 공용 모바일 계약과 웹 프로필 세로 배치 파일만 더해 수행한다. 다른 채팅의 미완료 변경은 이 배포본에 포함하지 않는다.
- 운영 배포 `dpl_EtxbkWRSe249q7sUmfNTSyjLXRiE`는 Next.js production 빌드와 타입 검사, 186개 정적 페이지 생성을 통과하고 `https://minion.fan`에 연결됐다. 운영 홈 API에서 뉴스 6개, 데마시아컵 축하 배너와 Worlds 로고를 확인했다.
- 운영 매치 API에서 브리핑 8축과 두 팀, 챔피언 API의 추가 상세 필드를 확인했다. 새 기사 API의 잘못된 URL 요청은 400이고 CORS 헤더는 `*`다. 운영 웹에서도 두 프로필이 같은 x=16 위치에 위아래로 배치되고 각각 372px 높이로 렌더링됨을 확인했다.
