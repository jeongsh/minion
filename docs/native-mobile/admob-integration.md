# Android AdMob 통합 기록

2026-10-10 사용자 요청에 따라 기존 광고 지면을 실제 Android 배너로 연결했다. 설치된 기존 앱에는 네이티브 SDK가 없어 새 앱 빌드가 필요하다.

화면당 320×50 배너 한 곳을 사용한다. 고정 배너, 전면 광고, 보상형 광고는 추가하지 않았다. 빈 콘텐츠, 검색 결과, 신고 등 팝업, 키보드 표시 중에는 해당 지면을 숨긴다. 포커스된 Android 화면이 전경에 있고 배너가 헤더와 하단 조작 영역을 벗어난 위치에 들어왔을 때 요청한다. 스크롤 중에는 이미 요청한 배너를 유지하고 가시성만 변경한다. 로드 실패 시 지면을 숨긴다. 웹, iOS, Expo Go와 SDK가 없는 기존 바이너리는 광고를 요청하지 않는다.

## SDK와 동의

- Expo 54 / React Native 0.81.5에 맞춰 `react-native-google-mobile-ads` 15.8.3 고정. Android 네이티브 컴파일 확인.
- 앱 ID: `ca-app-pub-7060554754100656~8115086249`.
- 배너 ID: `ca-app-pub-7060554754100656/3660217360`.
- development / preview는 테스트 광고, production은 실제 배너 ID. 개발 런타임도 테스트 광고를 강제한다.
- UMP 동의 상태의 `canRequestAds`를 확인한 뒤 SDK를 초기화한다. 비개인 맞춤 광고를 요청한다.
- 동의 설정 재진입이 필요한 지역에는 하단에 광고 개인정보 설정 버튼이 표시된다.
- AdMob 메시지 `MINION Android 광고 동의`를 앱 및 `https://minion.fan/privacy`에 연결했다. 사용자가 최종 게시 버튼을 눌렀으며 목록의 `게시됨` 상태를 확인했다.
- 메시지 기본 언어는 제공 목록의 English다. 한국어 옵션은 해당 목록에 없었다. 앱 내 광고 및 설정 문구는 한국어다.

## 확인 결과와 남은 조건

통과: 웹 및 모바일 TypeScript 검사, 모바일 ESLint(기존 경고 2개), 웹 타이포그래피 검사, 수정한 약관/개인정보 페이지 ESLint, 키보드 계약 테스트 4개, 동의 초기화 및 플랫폼 차단 로직 모의 실행, Expo 설정의 Android App ID/지연 초기화 반영, Android debug APK 빌드, Android Hermes 번들 export.

연결된 실기기와 에뮬레이터가 없어 실제 광고 노출, 스크롤, 키보드, 뒤로가기 및 390×844 라이트/다크 화면 검증은 미완료다. debug APK는 개발 클라이언트 검증용이며 배포본이 아니다.

배포 전 새 네이티브 빌드에서 테스트 광고와 배치 간격을 실기기로 확인한다. 변경한 개인정보/약관 웹 페이지를 게시하고 Google Play 데이터 보안 및 광고 포함 항목을 확인한다. 배포용 AAB는 기존 업로드 키를 사용하며 Play의 현재 versionCode보다 큰 값으로 빌드한다. 현재 설치된 앱 및 스토어에는 이 작업으로 업데이트를 배포하지 않았다.

## 2026-10-10 승인 후 신고 완료

- 사용자가 IARC 약관 동의와 AdMob 데이터 보안/광고 ID 신고를 명시적으로 승인했다.
- 실제 커뮤니티 기능에 맞춰 소셜 유형, 차단/신고 있음, 정확한 위치 공유/디지털 구매/데이트/노출/생생한 현실 폭력 허용/친구 전용 상호작용 없음으로 IARC 설문 작성. 한국 Google Play의 12세 이상 결과를 확인하고 저장했다. 콘텐츠 등급 개요에서 IARC 완료됨 및 대한민국 12세 이상 확인. 스토어 반영은 심사 전송 대기다.
- 광고 ID 사용을 예로 변경하고 애널리틱스, 광고 또는 마케팅, 사기 예방/보안/규정 준수 목적을 저장했다. 광고 ID 사전 검사 오류는 해소됐다.
- 대략적인 위치, 비정상 종료 로그, 진단, 기타 앱 성능 데이터의 수집/공유와 비임시/필수 처리, 광고/분석/사기 예방 목적을 반영했다. 기존 앱 상호작용 및 기기 ID 목적은 유지하면서 AdMob 수집/공유 목적을 추가했다. 다른 기존 개인정보/검색/콘텐츠 신고는 유지했다. 미리보기에서 암호화 및 삭제 링크를 확인하고 최종 저장 성공을 확인했다.
- 게시 개요에서 1.0.1 전체 출시, 콘텐츠 등급, 개인정보처리방침, 광고 선언, 데이터 보안의 5개 변경사항이 전송 대기다. 공개 개발자 전화번호가 인증 및 저장됐고 웹사이트도 인증됐지만 한국 개발자 추가 정보 오류 한 가지가 여전히 제출을 차단한다. Google 공식 안내는 사업자/통신판매 정보 추가 요구를 유료 앱/IAP에 한정하고 있어 공란에 임의 값을 입력하지 않는다. 지원 경로 확인 중이며 심사 제출 및 배포 완료로 처리하지 않는다.
- Play Console 지원 티켓 양식에 계정 ID, 앱 이름, 버전, 오류 문구와 인증 완료 상태를 설명하는 초안을 준비했다. 실제 전화번호/주소를 본문에 포함하지 않았다. 사용자에게 지원팀 메시지 전송을 별도로 요청했으며 승인 전에는 제출하지 않는다.

## 2026-10-10 무료/광고 계정 설정 감사

- 사용자 요청으로 Play 및 AdMob의 유료 판매 관련 오설정을 점검했다. 외부 설정 변경이나 지원 메시지 제출은 하지 않았다.
- Play 앱 가격: ‘앱이 Google Play에서 무료로 제공되고 있으므로 유료로 변경할 수 없습니다’ 확인.
- Play 일회성 제품 및 정기 결제: 상품과 구독 모두 없음. 일회성 상품 화면도 결제 권한 추가가 필요하다고 안내한다. 실제 release merged manifest에는 AD_ID 권한만 있으며 `com.android.vending.BILLING`은 없다.
- Play 앱 수익 창출 설정: 실시간 결제 알림 꺼짐, 개발자 제공 결제 사용 안 함, 외부 제공/콘텐츠 링크/결제 선택 프로그램 미등록.
- Play 개발자 계정: 개인 계정, 연락처/공개 전화번호와 이메일 인증됨, 웹사이트 인증됨. 계정 생성 ‘앱 정보’ 응답은 수익 창출 ‘예’, 방법 ‘광고’만 표시한다. 유료 앱/IAP를 선택한 흔적은 발견하지 못했다. 계정 정책 상태도 문제 없음이다.
- Play 수익 창출 결제 프로필 화면에는 ‘Google Play 앱’ 지급 계정이 생성돼 있고 거래/판매 잔액은 0이다. 프로필 존재 자체가 오설정 또는 한국 정보 오류의 원인이라는 근거는 확인되지 않았다. 내장 결제 화면의 설정 관리 버튼은 브라우저 도구에서 조작되지 않아 프로필 내부 상세 설정 확인은 미완료다. 개발자 신원 결제 프로필과 판매자 계정은 역할이 다를 수 있으므로 해지/삭제로 해결하려 하지 않는다.
- AdMob은 동일한 `com.minion.app`을 무료 Android 앱으로 연결하며 준비됨, 계정 운영중, 정책 위반 및 광고 게재 제한 없음이다. 지급 계정은 별도 AdSense(대한민국), 잔액/거래 0. Google Ads/Firebase 연결도 없음이며 광고 SDK 사용에 필수인 유료 판매 연결은 발견하지 못했다.
- 결론: 점검한 범위에서 무료 앱을 유료/IAP로 잘못 설정한 값은 발견되지 않았다. 한국 개발자 추가 정보 오류는 여전히 남아 있으므로 Google의 계정 검증/판매자 분류 적용 여부를 확인해야 한다. 내부 원인으로 확정하지 않는다.

## 2026-10-10 Google Play 지원 문의 제출

- 사용자가 무료 앱의 추가 정보 오류에 대해 지원 문의 전송을 명시적으로 요청했다.
- 무료 앱/AdMob 광고만 사용, 일회성 및 구독 상품 없음, Billing 권한 없음, 공개 전화번호 인증/저장 완료, 기존 버전 정상 출시와 새 27 제출 차단을 구체적으로 설명했다. 계정 ID와 앱/버전/오류를 포함하고 실제 전화번호/주소는 보내지 않았다.
- Play의 AI 추천은 전화번호 확인과 무료 앱의 사업자/통신판매 필드 공란 유지라는 이미 확인한 내용을 안내했다. 공개 전화번호 인증이 완료됐는데 동일 오류가 지속된다는 사유를 추가하고 지원 담당자 티켓을 생성했다.
- 도움말 화면의 ‘티켓 제출됨’, ‘대기 중’, ‘케이스 ID 대기 중’을 확인했다. 화면 안내는 영업일 기준 2일 이내 이메일 답변이며 일부 티켓은 더 오래 걸릴 수 있다. 새 버전 심사 제출/배포는 계정 오류가 해소될 때까지 미완료다.
