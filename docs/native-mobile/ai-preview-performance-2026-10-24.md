# AI 프리뷰 조회 성능 개선

## 변경 범위

- 모바일 매치 API의 팀, 선수, 대회, 스테이지 조회와 명시적 프리뷰 요청의 경기 기록 조회를 경기 단건/인증/세트 조회와 함께 시작한다.
- 기본 데이터 탭에서 세트가 없어 프리뷰로 전환되는 경로는 기존 조건을 유지한다.
- 공개 선수 비교 지표는 경기/세트 목록과 동일한 30초 주기로 서버 캐시를 재사용한다. 기존 100세트 조회 단위와 동시 요청 수 4를 유지한다.
- 선수 지표 캐시는 100세트씩 나눠 저장한다. 실제 측정한 항목 크기는 약 0.50~0.74MB로 Next.js의 2MB 제한보다 작다.
- 브리핑 원본 병합 시 동일한 팀명과 선수명의 ID 검색 결과를 해당 병합 호출 안에서 재사용한다. 별칭, 미등록 이름의 fallback, 경기 시작 전 기록 제한은 유지한다.
- API 응답 필드, 차트 표본/모집단, AI 생성 정책, 인증과 개인별 캐시 분리, 화면은 변경하지 않는다.

## 검증

- 서버와 앱 TypeScript 검사 통과.
- 변경 파일 ESLint 통과. 앱 lint 오류 없음, 기존 경고 2건 유지.
- 브리핑 복원, 선수 지표, 차트, 프리뷰 정책 및 승리 조건 관련 기존 테스트 38개 통과.
- 실제 Supabase 읽기를 사용한 로컬 API에서 기존 응답의 `data` 전체와 동일함을 확인했다. 응답마다 달라지는 `meta.requestId`, `meta.generatedAt`은 비교에서 제외했다.
- 비교 경기: `dfaeafc1-ba74-48b9-b46d-7af14cf19e5d`, `tab=preview`, 비로그인.
- 팀과 선수 이름 검색 최적화 전후 모두 실제 경기 응답이 동일했다.

## 시간 측정의 범위

개발 서버의 컴파일 및 다른 요청 영향을 분리하기 위해 별도 Node 프로세스에서 변경 전/후 API 처리 함수를 같은 실제 Supabase 데이터로 실행했다. 이 비교에서는 Next.js 데이터 캐시 저장소만 프로세스 내 Map으로 대체했다. 변경 전에는 새 선수 지표 캐시를 우회하고 원본 브리핑 병합 코드를 사용했다. 응답 본문 전체가 동일함을 검사했다.

| 조건 | 측정 시간 |
| --- | --- |
| 이번 추가 개선 전, 공유 데이터 캐시 비움 | 1,529ms |
| 추가 개선 후, 공유 데이터 캐시 비움 | 729ms |
| 추가 개선 후, 공유 데이터 캐시 준비됨 | 353ms |

단일 경기의 참고 측정이다. 네트워크 연결 재사용과 측정 순서의 영향이 있으며 앱 실행, 인증 초기화, 라우팅, 렌더링 시간은 포함하지 않는다. 실제 로컬 Next.js HTTP 측정은 서버 작업 중 0.97~7.56초로 변동해 개선 비율의 근거로 사용하지 않는다.

배포 후 iPhone/Android 실기기 진입 시간과 화면 캡처 비교는 미실행이다. Android 빌드는 실행하지 않았다.
