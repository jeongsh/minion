# MINION 모바일 앱 작업 안내

이 디렉터리가 모바일 앱 개발의 **현재 기준**이다. 과거 `native-mobile-phase-*` 문서는 짧은 이력만 남기며 실행 지시로 사용하지 않는다.

전체 0~6단계 로드맵과 인증·푸시·배포 순서는 [`native-mobile-app-strategy.md`](../native-mobile-app-strategy.md#단계별-실행-계획)에 있다.

## 필수 진입 규칙

웹 화면이나 기능을 모바일 앱으로 복제하는 모든 작업은 **구현 전에 반드시 이 문서를 처음부터 끝까지 확인하고, 아래 규칙을 작업 전 과정에 적용해야 한다.** 작업자, 에이전트와 변경 크기에 관계없이 예외는 없다.

- 이 문서를 읽지 않은 상태에서는 웹 복제 구현을 시작하지 않는다.
- 작업을 나누거나 다른 작업자·에이전트에게 넘길 때도 이 문서를 먼저 읽고 준수하도록 명시한다.
- 디자인 캡처만 보고 구현하지 않는다. 웹 원본 코드와 실제 실행 결과를 모두 확인한 뒤 구현한다.
- 이 문서의 복제 기준과 충돌하는 임의 단순화, 재설계, 구조 변경은 완료로 인정하지 않는다.

## 절대 규칙: 웹 모바일 복제

앱은 새 디자인이나 유사 구현이 아니다. **현재 웹 모바일의 화면·동작·코드 구조·데이터 흐름을 가능한 한 원본 그대로 정확하게 복제**하는 것이 목표다. React Native와 서버 런타임 차이 때문에 문법이나 플랫폼 API를 바꿔야 하는 경우에만 그 차이를 허용하며, 결과와 책임 분리는 원본과 같아야 한다.

- 웹의 실제 JSX, CSS/Tailwind, computed style, 사용 자산과 조건 분기를 먼저 확인한다.
- 렌더링된 HTML/DOM의 요소 계층, 시맨틱 구조, 컴포넌트 경계, 속성, 이벤트 연결을 확인하고 앱의 뷰 계층과 컴포넌트 구조에 동일하게 반영한다.
- 프런트엔드의 상태 모델, 훅, 데이터 가공, 검증, 로딩·오류 처리, 캐시, 요청 순서와 화면 전환 로직을 원본 코드 기준으로 추적해 복제한다.
- 연결된 API route, 서버 액션, 서비스 계층, 데이터베이스 쿼리, 인증·권한 검사, 응답 변환과 오류 계약까지 확인한다. 앱 전용 API가 필요하면 이름만 비슷한 새 구현을 만들지 말고 웹 백엔드의 책임 분리와 동작을 정확히 옮긴다.
- 상수, 계산식, 정렬·필터 조건, 기본값, 요청·응답 필드와 예외 처리도 추측하거나 축약하지 않는다. 원본 코드와 동일한 근거를 사용한다.
- 콘텐츠 순서, 표시 조건, 문구, 스크롤·스와이프, 모달, 이동 결과를 동일하게 만든다.
- 폰트 파일·weight·size·line-height, 색상·투명도, 좌표·크기·간격·border·radius를 추측하지 않는다.
- 웹이 SVG/실제 로고를 쓰면 같은 자산을 쓴다. 웹과 다른 아이콘으로 대체하지 않는다.
- 390×844 라이트·다크에서 같은 데이터·상태로 나란히 캡처해 비교한다.
- 레이아웃 좌표와 크기의 차이는 반올림을 포함해 최대 1px이다. 누적 오차나 눈에 보이는 차이는 실패다.
- 플랫폼 글꼴 래스터링 차이는 허용하되 동일한 폰트 파일, weight, size, line-height를 사용해야 한다.
- 디자인만 비슷한 화면, mock 데이터에만 맞춘 구현, 백엔드 동작을 생략한 UI, 임의 개선, 임시 카드, 데이터만 먼저 연결한 UI는 완료로 보지 않는다.

## 현재 상태와 잠금 영역

완료되어 잠긴 영역:

- `mobile/app/(tabs)/index.tsx`: 홈 전체와 Footer
- `mobile/components/minion-screen.tsx`: 헤더·로컬 내비게이션·스크롤 시 헤더 동작
- `mobile/components/minion-dock.tsx`: 독바와 팬 탭 동작
- `mobile/components/home/home-calendar-dialog.tsx`: 홈 캘린더
- 폰트·로고·팀 자산, 테마 provider, 팀 선택 sheet

### 승인된 통합 변경 기록

- 2026-08-22: 홈 최초 로딩을 공통 스피너형 placeholder에서 실제 홈 구조를 따르는 전용 skeleton으로 교체했다. 데이터가 준비된 뒤의 홈 레이아웃과 동작은 변경하지 않았으며, `mobile/app/(tabs)/index.tsx` 변경은 이 로딩 상태 연결 한 줄로 제한했다.
- 2026-08-29: 웹 전역·팀 로컬 내비게이션의 `/community` 표시명을 `팬톡`으로 변경한 것에 맞춰 앱 헤더의 허브·팀 로컬 내비게이션 라벨도 `팬톡`으로 통합했다. 허브 순서는 웹과 앱 모두 `메인 → 팬톡 → 승부예측 → 대회 → 선수 → 챔피언`으로 맞췄으며 경로, 레이아웃, 헤더 동작은 변경하지 않았다.

위 파일은 일반 화면 작업에서 임의 수정하지 않는다. 변경이 꼭 필요하면 작업을 멈추고 변경 이유와 웹 근거를 기록한 뒤 별도 통합 작업으로 처리한다.

나머지 라우트 UI는 `RouteCanvas`만 표시하는 제로베이스 상태다. API 계약·클라이언트·캐시는 유지돼 있다.

## 공통 기술 경계

- Expo SDK 54 + React Native + Expo Router를 유지한다.
- 앱은 공개 조회를 `/api/mobile/v1/*`로 호출한다. Supabase 테이블을 화면에서 직접 조립하지 않는다.
- 서버 비밀키는 앱에 넣지 않는다.
- 웹 컴포넌트를 그대로 import하지 않는다. 구조·수치·상태 규칙을 React Native로 정확히 번역한다.
- 공용 컴포넌트가 필요하면 해당 기능 영역 내부에 먼저 두고, 여러 기능이 실제로 함께 사용할 때만 공용 경계로 분리한다.

## 키보드와 하단 입력 UI

- 키보드가 필요한 화면은 `mobile/components/keyboard-aware-view.tsx`의 `KeyboardAwareView`와 `mobile/hooks/use-keyboard-layout.ts`의 `useKeyboardLayout`만 사용한다.
- 공용 파일 밖에서 `KeyboardAvoidingView`, `Keyboard.addListener` 또는 키보드 높이 보정 로직을 직접 추가하지 않는다.
- 하단 입력창과 툴바의 safe area는 `useKeyboardLayout`이 반환하는 `bottomInset`을 사용한다. 키보드가 열리면 시스템 bottom inset을 다시 더하지 않는다.
- 키보드가 닫히면 회피 레이아웃을 비활성화해 최초 화면 높이로 복원한다. 키보드 열기·닫기를 3회 반복한 뒤 최초 위치와 같은지 Android와 iPhone에서 확인한다.
- 변경 후 `node --test tests/mobile/keyboard-layout-contract.test.mjs`를 실행해 공용 계약 우회를 검사한다.

## 변경 범위와 충돌 방지

1. 요청 범위 밖의 파일은 수정하지 않는다.
2. 공용 API/타입 변경이 필요하면 영향 범위와 변경 계약을 먼저 기록한다.
3. 한 커밋에는 한 화면 또는 한 묶음만 담는다.
4. 완료 화면의 웹/앱 라이트·다크 캡처와 차이 점검표를 함께 남긴다.
5. 병합 전 `npm.cmd --prefix mobile run typecheck`와 `npm.cmd --prefix mobile run lint`를 모두 통과한다.

## 완료 판정

기능 연결이나 번들 성공만으로 완료가 아니다. 다음을 모두 만족해야 한다.

- 웹과 정보·상태·상호작용이 동일함
- 웹 원본의 DOM/컴포넌트 계층, 상태·데이터 가공 로직, API 요청·응답 계약과 백엔드 동작이 앱 환경에 빠짐없이 대응됨
- 390×844 라이트·다크 비교에서 1px 기준 통과
- iPhone과 Android Expo Go에서 스크롤, safe area, 키보드, 뒤로가기 확인
- 로딩·빈 상태·오류 상태도 웹과 동일
- 잠금 파일 변경 없음

## 로딩 UX 기준

- 최초 데이터가 없을 때는 화면 전체를 빈 상태로 막지 않고 실제 콘텐츠의 크기와 순서를 따르는 skeleton을 표시한다.
- 캐시 데이터가 있으면 기존 콘텐츠를 즉시 유지하고 새 데이터는 백그라운드에서 갱신한다.
- 이미지와 영상은 데이터 화면을 막지 않으며, 정해진 크기의 placeholder 안에서 개별적으로 로드한다.
- skeleton은 실제 레이아웃과 같은 폭·높이를 사용해 콘텐츠 표시 시 레이아웃 점프가 발생하지 않아야 한다.
- 오류 상태와 재시도 동작은 skeleton과 분리한다.
