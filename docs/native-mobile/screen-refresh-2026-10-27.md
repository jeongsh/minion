# 조회 화면 새로고침

2026-10-27 사용자 요청: 자동 갱신이 빠진 화면에 재진입과 앱 복귀 갱신을 추가하고, 아래로 당겨 새로고침을 제공한다.

## 통합 변경 근거

- 잠금 영역 `mobile/components/minion-screen.tsx`의 ScrollView와 FlatList에 선택적인 RefreshControl을 연결한다. 기존 헤더, 메뉴, 레이아웃과 글꼴은 유지한다.
- 잠금 영역 `mobile/app/(tabs)/index.tsx`에는 조회 훅과 새로고침 연결만 추가한다.
- 웹의 `app/schedule/page.tsx`와 모바일 schedule API는 같은 `getMatchesByMonth` 서비스를 사용한다. 기존 모바일 API, 응답 계약, 필터와 캐시 범위를 유지한다. 당겨서 새로고침은 사용자가 요청한 네이티브 동작이다.
- 글쓰기, 편집과 설정 폼은 자동 갱신 적용 대상에서 제외한다. 게시글 상세의 댓글 입력 상태는 유지한다.

## 동작

- `useScreenQuery`는 기존 `useCachedQuery`를 사용하며 포커스 복귀와 앱 활성화 때 새 요청을 보낸다. 숨겨진 화면은 갱신하지 않는다.
- 홈, 뉴스, 팬페이지와 일정은 기존 갱신 루틴을 유지한다. 대회와 고객지원의 중복 포커스 루틴은 공용 훅으로 대체한다.
- 당겨서 새로고침은 기존 HTTP 캐시 우회 경로를 사용한다. 필터, 선택 탭과 기존 데이터는 유지하며 수동 갱신 실패는 토스트로 알린다.
- 일반 스크롤, 선수와 챔피언 가상 목록, 별도 스크롤을 사용하는 게시글 상세에 연결한다. 스크롤 높이가 짧은 iOS 화면에서도 당기기를 허용한다.
- 사용자 후속 요청에 따라 수동 갱신 중에는 헤더 아래에 ActivityIndicator만 표시한다. 문구는 추가하지 않으며 네이티브 RefreshControl의 중복 스피너는 투명하게 처리한다.
- iOS 실기기 캡처 피드백 반영: 고정 배경 원을 제거하고 큰 스피너를 당겨진 빈 공간 중앙에 배치한다. 음수 스크롤 오프셋으로 높이를 추적하며 당기는 중에도 나타난다. 일반 스크롤과 가상 목록, 게시글 상세에 같은 계산을 적용하고 Android는 기존 표시를 유지한다.

## 검증

- Android 후속 요청: 기본 RefreshControl의 LARGE 스피너를 활성화하고 별도 고정 스피너는 제거했다. 공용 화면에서는 헤더와 표시 중인 고정 영역 아래에 배치한다. 게시글 상세는 이미 헤더 아래에서 시작하는 스크롤의 기본 위치를 사용한다. Android 실기기 확인과 빌드는 사용자 요청대로 보류한다.

- 모바일 타입 검사 통과. 모바일 린트 오류 없음, 기존 경고 2건.
- 기존 캐시와 키보드 계약 검사 26건 및 화면 갱신 회귀 검사 3건 통과.
- 회귀 검사는 최초 요청, 재진입, 앱 복귀, 중복 active 이벤트, 숨긴 화면, 비활성 쿼리, 수동 갱신 실패 시 데이터 유지 및 오류 알림을 확인했다.
- Expo Web 팬톡 화면에서 홈으로 이동 후 재진입 시 API 요청 1건을 확인했다. 런타임 오류 없음.
- Expo Web 팬톡을 390px, 768px, 1440px 라이트와 다크로 캡처하고 문서 가로 넘침 없음 확인. 390px 라이트와 다크 및 1440px 라이트 캡처를 시각 점검했다.
- iPhone 및 Android Expo Go의 실제 당기기 제스처와 네이티브 표시 위치는 미검증이다. Android 빌드는 실행하지 않았다.
