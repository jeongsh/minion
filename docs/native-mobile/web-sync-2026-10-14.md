# 웹과 앱 동기화 검증

2026-10-14 사용자 요청에 따른 홈과 이적시장 통합 변경이다. 모바일 작업 기준은 `README.md`, 디자인 기준은 `../DESIGN.md`다. 홈과 헤더 잠금 파일의 변경 근거는 README의 같은 날짜 기록에 있다.

## 대응 관계

| 웹 원본 | 앱 구현과 데이터 |
| --- | --- |
| `app/transfers/page.tsx`, `components/transfers/transfer-market.tsx` | `/transfers`, `mobile/components/transfers/transfer-market.tsx`, `/api/mobile/v1/transfers` |
| `lib/transfers/types.ts`, `lib/transfers/view.ts` | contracts의 순수 함수와 타입을 웹과 앱이 공유한다. 웹의 기존 import 경로는 re-export로 유지한다. |
| `components/domain/home-dashboard.tsx` | 매치와 캘린더, 스토브리그, 기념일, 광고, 커뮤니티, POM, 팀 채널, 대회 현황, 메타, 선수 빌드 순서로 앱 홈을 연결한다. 뉴스와 영상은 웹처럼 표시하지 않는다. Android 광고는 기존 AdMob 통합을 유지한다. |
| `buildHomeTournamentOverview`, `summarizeHomeBracket`, `getHomeInsights` | 모바일 홈 API에서 같은 서비스를 호출한다. 순위 그룹과 대진표 요약도 웹의 선정 규칙을 사용한다. |
| `getPredictionMarketData`, `predictionMarketForMatch` | 홈 매치의 승부예측 비율을 API로 전달한다. 고정 50% 표시를 대체한다. |
| `components/ui/section-heading.tsx` | 홈 영역의 `HomeSectionHeading`으로 제목과 전체보기 위계를 맞춘다. |
| `components/layout/app-shell.tsx`, `components/fan/fan-channel-navigation.tsx` | 헤더 항목은 글자 폭에 좌우 16px 패딩을 더한다. 기존 글꼴을 유지하라는 후속 요청에 따라 헤더 글꼴 변경은 복원했다. |

이적시장 공개 API는 기존 `getTransferMarket`, `getAllTeams`, `getPlayers`를 사용한다. 좋아하는 팀 순서는 기존 모바일 팀 디렉터리 API의 `followedTeamIds`를 사용하며 계정별 메모리 캐시를 적용한다. 스키마와 인증 권한은 변경하지 않는다. 홈 v1의 `news`, `videos` 필드는 구버전 호환을 위해 빈 배열로 유지하고 새 홈 필드는 optional로 추가했다.

## 화면과 동작 확인

- 웹의 실제 DOM, 링크 목적지, 계산된 스타일과 앱의 Expo Web DOM을 확인했다. 같은 실제 데이터에서 홈 매치 3개, POM, 기념일, 대회 현황, 메타 6개와 빌드 6개가 연결됐다.
- 모바일 스토브리그와 생일 배너는 높이 60px, 이미지 영역 36px, 세로 패딩 12px, 가로 패딩 16px, CTA 34×30px이다. 스토브리그 본문은 요청대로 14px이다.
- PC 웹에서 두 배너는 모두 폭 1200px, 높이 72px, 이미지 영역 40px이었다. 두 줄의 높이는 44px로 같다.
- 웹 모바일 메뉴의 실제 폭은 메인 약 56px, 이적시장 약 80px이었다. 앱도 글자 너비에 따른 항목 폭을 확인했다. 글꼴은 기존 헤더 설정을 유지한다.
- 홈의 라이트와 다크 화면을 확인했다. 웹과 Expo Web에서 스토브리그 배너의 콘텐츠 좌표는 x=16, y=328, 폭 358px, 높이 60px로 같았다. 웹 데스크톱 브라우저는 15px 스크롤바를 포함하므로 이 좌표 비교에서는 405px 뷰포트의 실제 콘텐츠 폭 390px을 사용했다. 앱 뷰포트는 390×844였다.
- 이적시장 로스터, 선수 이동, FA, 선수 검색과 검색 결과 없음 상태를 확인했다. 신규 제목은 모바일에서 20px이며 PC 웹은 기존 28px을 유지한다. 웹 최근 변동의 화살표 버튼은 0개이고 실제 마우스 드래그로 첫 슬라이드 좌표가 16px에서 -350px로 이동했다. 앱은 수평 ScrollView를 유지한다.
- 빌드 링크는 같은 매치와 세트로 이동하고 `player` 파라미터로 해당 선수를 선택한다. 네이티브의 HTML hash 자동 스크롤은 아직 별도 검증하지 않았다.

## 실행 검사

- 웹과 앱 TypeScript 검사 통과.
- 웹 `lint:typography`와 변경 웹 파일 ESLint 통과.
- 앱 lint 오류 없음. 기존 경고 2건은 `community-directory-nav.tsx`, `schedule-match-list.tsx`에 남아 있다.
- 키보드 계약 검사 4건 통과.
- 실제 이적시장 API에서 로스터 10개와 이벤트 6개를 확인했다. 공유 계산의 입력 불변성, 팀 이동 후 기존/신규 로스터, 이동 이후 FA 제외, 시즌 초 장기 재계약, 공개 API 등록과 이적시장 딥링크를 검사했다.
- 기존 모바일 계약 테스트는 5건 중 4건 통과했다. 매치 API를 public으로 기대하는 테스트가 현재 HEAD의 optional 계약과 충돌하는 기존 실패 1건은 이번 작업에서 변경하지 않았다.
- Android Hermes 번들 생성은 확인했다. 산출물은 `.tmp/mobile-web-sync-android`의 검증용 파일이며 앱 스토어 배포 파일이 아니다.
- `git diff --check` 통과.

## 남은 검증과 배포

iPhone과 Android 실기기의 스크롤, safe area, 키보드 반복, 뒤로가기 및 전체 화면 1px 비교는 실행하지 않았다. Expo Web 확인과 Android 번들 성공을 네이티브 실기기 검증 완료로 간주하지 않는다. iOS 배포 빌드와 스토어 업로드는 수행하지 않았다.

## 2026-10-14 배포 진행

- 공용 계약, 이적시장, 헤더, 홈, 이적관리, 앱 버전을 기능별 한글 커밋 6개로 분리했다. `codex/mobile-web-sync-20261014`를 원격에 푸시하고 `10723dd5`로 `dev`에 병합 및 푸시했다.
- Vercel 운영 배포가 READY가 됐다. `minion.fan`의 모바일 이적시장 API에서 시즌 2026과 로스터 10개, 홈 API에서 챔피언 메타 6개, 선수 빌드 6개와 대회 현황을 확인했다.
- Android 1.0.2, versionCode 28을 로컬 Gradle `:app:bundleRelease`로 빌드했다. 기존 업로드 키 서명과 JAR 검증을 확인했다. minSdk 24, targetSdk 36이며 운영 API 주소가 Hermes 번들에 포함되고 개발 LAN 주소는 포함되지 않는다.
- 배포 파일은 Git에서 제외된 `mobile/store-assets/minion-1.0.2-28.aab`다. 크기는 88,765,110바이트이며 SHA-256은 `CD2ADCB2CDFCA2C6959D445C8AA6D85ADFD51B6FFBCE28451AF17F12D9BE2261`이다.
- EAS 원격 Android versionCode도 28로 동기화했다. 다음 자동 증가 빌드에서 이미 업로드한 28을 재사용하지 않도록 했다.
- Google Play 프로덕션에 AAB 28과 한국어 출시 노트를 업로드하고 출시 변경사항을 저장했다. 새 빌드의 merged manifest에는 `com.google.android.gms.permission.AD_ID`가 포함된다. 활성 아티팩트 중 권한이 없는 버전에 대한 검증 오류는 이번 출시에서만 무시하는 Play 옵션으로 저장했다. 광고 ID 사용 선언은 유지했다.
- 대한민국 개발자 계정 추가정보 문제로 심사 제출 버튼이 비활성화되어 있다. 계정 정보 처리가 필요하며 아직 심사 제출 및 사용자 대상 공개가 완료된 상태는 아니다.
