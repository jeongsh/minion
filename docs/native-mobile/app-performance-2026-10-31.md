# 앱 성능 점검과 광고 지연 로딩

2026-10-31 사용자 요청으로 광고를 유지하면서 화면 밖 지면의 로드를 미루고, 앱의 요청 중복과 DB 조회 경로를 점검한다.

## 변경 계약

- 웹 `components/ui/ad-slot.tsx`와 기존 앱의 광고 지면 위치, 표시 조건과 문구를 유지한다. 이번 성능 변경은 가까운 지면만 처음 로드하고, 같은 화면의 스크롤에서는 이미 로드한 네이티브 뷰를 유지한다. 병행 작업의 anchored adaptive 크기 변경도 보존했으며, 크기 통제 여부는 측정 조건에 별도로 기록한다.
- 화면 포커스를 잃거나 앱이 배경으로 이동하면 네이티브 광고 뷰를 해제한다. 다시 진입할 때 현재 위치를 재확인한다. 키보드와 모달은 기존 재시도 중지 조건을 유지한다.
- 잠금 파일 `mobile/components/minion-screen.tsx`에는 광고 위치 재확인을 위한 기존 스크롤 이벤트와 콘텐츠 크기 변경 알림만 연결하는 통합 변경을 적용한다. 헤더, 독바, 스크롤 방식, clipping, 레이아웃과 홈 지면은 바꾸지 않는다.
- 게시글의 독립 ScrollView에도 같은 이벤트 알림을 연결한다. 타이머 좌표 폴링이나 모든 배너의 프레임별 React 상태 갱신을 추가하지 않는다.
- API 응답 계약과 사용자별 캐시 분리는 보존한다. 명시적 새로고침과 저장 후 무효화는 최신 요청을 유지한다. 기존에 지정된 공개 데이터의 캐시 유효시간은 자동 화면 재진입에서도 적용한다.
- 실제 계정의 저장, 게시, 예측 참여와 설정 변경은 실기기 성능 검증에서 실행하지 않는다. DB 및 운영 서비스는 읽기 전용으로 점검한다.

## 검증 기록

별도 패키지 `com.minion.app.perf`와 테스트 광고를 사용했다. 운영 앱은 덮어쓰지 않았다. Samsung SM-S906N, Android 16에서 시작, 스크롤, 재방문과 앱 복귀를 확인했다.

### 구현

- 화면 아래 지면은 창 하단 160dp 이내로 접근했을 때 로드를 시작한다. 스크롤 및 콘텐츠 크기 이벤트를 100ms 단위로 모아 아직 로드하지 않은 지면만 측정한다. 주기적 좌표 폴링은 없다.
- 같은 화면에서 스크롤로 멀어진 광고는 유지한다. 화면 이탈과 앱 배경 전환에서는 네이티브 뷰를 해제하고 마지막 유효 높이의 placeholder를 유지한다.
- 공용 조회 훅의 자동 진입과 복귀가 명시된 공개 캐시 유효시간을 존중하도록 했다. 수동 새로고침과 저장 후 무효화는 항상 최신 요청을 유지한다.
- 동일 조회 효과가 바로 교체되면 취소를 마이크로태스크까지 미뤄 다음 소비자가 진행 중 요청에 붙도록 했다. 다른 검색어로 바뀌거나 마지막 소비자가 떠난 요청은 계속 취소한다.
- 일정 최초 진입은 자동 재검증을 사용한다. 날짜 변경과 기존 1분 타이머는 강제 갱신을 유지한다. 자동 재검증이 수동 새로고침 의도를 덮어쓰지 않도록 했다.
- 팬 페이지와 뉴스의 별도 포커스 처리를 공용 훅으로 합쳤다. 홈과 뉴스 목록의 기사 정보는 공용 요청 및 60초 메모리 캐시를 사용한다.
- 로그인 복원과 앱 복귀의 계정 정보 조회는 동일 사용자 및 동일 요청 세대끼리만 공유한다. 저장 후 명시적 갱신은 새 요청으로 분리한다. 계정 정보에도 공용 20초 요청 제한을 적용했다.
- 알림과 경기 활동의 겹치는 진행 중 요청을 공유하고, 계정별 키와 응답 적용 시점의 사용자 검사를 유지한다.

### 실기기 전체 조회 순회

홈, 일정, 이적시장, 대회, 예측, 선수 목록 및 상세, 챔피언 목록 및 상세, 경기 상세, 팀, 팬 홈 및 일정/선수/소셜/영상, 팬톡, 뉴스, 검색, 미니콘, 내 정보, 설정, 문의, 로그인, 가입과 홈 복귀를 26단계로 순회했다. 계정 화면은 비로그인 진입만 검증했다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 관측한 앱 API 요청 | 63 | 54 |
| WebView 최대 수 | 21 | 5 |
| 마지막 홈의 WebView | 21 | 4 |
| 최대 앱 PSS | 1229MiB | 1198MiB |
| 관측한 HTTP 4xx/5xx 및 JS 오류 | 0 | 0 |
| 취소된 요청 | 1 | 0 |

한 기기에서 한 번씩 연속 순회한 값이며 통계적 지연 개선율로 해석하지 않는다. 변경 전은 작업 시작 시점의 로컬 소스를 진단 빌드한 것으로 스토어 설치본과 동일하다고 보장하지 않는다. 외부 딥링크 진입은 AppState 복귀를 만들기 때문에 알림 요청도 포함된다. 기사별 보충 요청은 서로 다른 기사이며 중복으로 세지 않는다.

변경 전 챔피언 목록에서는 시작 약 32ms 뒤 AbortError로 취소된 요청도 한 건 있었다. 서버 오류와 구분해 집계했다. 같은 키의 효과 교체 때 요청을 공유하는 변경 후에는 이번 순회에서 취소가 관측되지 않았다. 다른 검색어로 전환하거나 소비자가 떠난 조회의 취소 기능은 회귀 검사로 유지했다.

최종 순회에는 다른 작업에서 동시에 적용한 anchored adaptive 크기 변경을 보존했다. 같은 LARGE 크기로 통제한 중간 비교도 보관했으며, 그 비교에서는 요청 63→56, 마지막 WebView 21→4, 최대 PSS 1229→1192MiB였다. 최종 APK에서 일정 화면을 66초 유지한 별도 검사에서는 최초 및 약 60초 시점에 정확히 두 번 요청했고, 4초 배경 전환 후 복귀에서는 추가 일정 요청이 없었다. 초기 중복 제거와 기존 1분 갱신 보존을 함께 확인했다. 원시 데이터는 `artifacts/app-performance-2026-10-31/`에 보관한다.

### 렌더링과 상호작용

- 화면 진입 구간의 Android gfxinfo에서 지연 프레임은 변경 전 306/2518, 변경 후 187/1987이었다. 캡처 시점은 각 화면 진입 후이며 자동 스크롤 전이다. 라이브 데이터, 화면별 프레임 수와 SDK 작업이 달라 스크롤 FPS나 일정한 개선율로 해석하지 않는다.
- 변경 후에도 이적시장 진입의 프레임 시간 p95는 77ms, 일정은 46ms였다. 모든 화면이 부드러워졌다고 판정하지 않는다. 앱의 네트워크 응답과 JSON 처리, 상태 반영, 다음 프레임, JS 지연은 원시 로그에서 분리해 기록했다.
- 최종 APK에서 라이트와 다크, 홈 위아래 스크롤을 확인했고 홈의 세 광고 지면이 모두 로드됐다. 약 411dp 너비의 실제 기기에서 확인했으며 웹과의 1px 대조 검사는 아니다.
- 검색 입력에서 키보드를 세 번 다시 열고 닫아 화면 유지와 닫힘을 확인했다. 커서 핸들이 표시된 상태에서는 첫 뒤로가기 후 키보드가 남아 두 번째 뒤로가기가 필요한 경우를 관측했다. 최초 고정 시간 검사와 후속 상태 확인을 모두 보관하며 검색 코드는 변경하지 않았다.

### API와 DB 조사

- 앱 및 모바일 API 코드 246개 파일과 앱 경로 파일 45개를 목록화했다. 정적 검색의 조회 훅 32곳, 직접 요청 19곳, 폴링 5곳, DB 접근 69곳과 RPC 1곳은 실행 횟수가 아니다. 주요 API 21종을 PC에서 각각 두 번 순차 조회했다. 정상 조회는 200, 비로그인 `/me`는 의도한 401이었다. 잘못된 형식의 진단 ID로 보낸 최초 커뮤니티 요청은 실제 앱과 같은 UUID로 교정해 재확인했다.
- 홈의 응답 집계, 일정 및 달력 분리, 팀의 개인화 조회, 팬 섹션 분리, 선수 공유 데이터, 챔피언 페이지 조회 및 프리뷰 탭 분리를 확인했다. 앱 요청 시간을 SQL 실행 시간으로 간주하지 않는다.
- DB 스냅샷에서는 잠금 대기 0개였다. 누적 통계의 큰 타임라인 조회는 평균 약 278ms, 최대 약 2.94초였고 `set_id, player_id, event_type` 복합 인덱스와 상세 데이터 서버 캐시가 이미 있었다. 누적 통계만으로 최근 광고 변경의 영향으로 판단하지 않는다.
- 성능 advisor에는 외래키 보조 인덱스 10건, 사용 이력 없는 인덱스 44건과 Auth 연결 할당 방식 1건의 정보 항목이 있었다. 현재 지연 원인으로 확인되지 않아 인덱스, 정책과 스키마는 변경하지 않았다.
- 이미 도입된 개인화로 경기 상세 API는 optional 인증이다. DB 평점은 10점 저장, 기존 모바일 응답은 5점 값이라는 변환을 확인하고, 오래된 계약 테스트를 그 규칙에 맞췄다. 제품의 인증 및 점수 계산은 변경하지 않았다.
- 최근 이력의 `ae645027`은 계정과 비회원의 팔로우 소유권 필터를 분리했고, `dc08ea3b`는 DB 10점 저장과 모바일 5점 응답 변환을 변경했다. `abe177bd`는 프리뷰의 조회 병렬화와 캐시를 도입했다. 광고 SDK의 조회와 별개인 실제 데이터 경로 변경이며, 이를 성능 이유로 되돌리지 않았다. 현재 탭별 회귀 검사로 응답 일치와 관련 없는 무거운 조회의 미실행을 확인했다.

### 회귀 검사와 제한

- 일반 단위 테스트 182/182, 모바일 전체 회귀 테스트 93/93, 모바일 API 계약 5/5가 통과했다. 모바일 전체에는 새 성능 검사 11개와 에디터 검사 8개가 포함된다. 앱과 웹 타입 검사, 타이포그래피 검사도 통과했다. 앱 린트는 오류 0개이며 기존 경고 2개가 남았다.
- 에디터와 아바타, 프로필 좌표 및 이동, 경기 탭의 테스트를 현재 의존성과 이미 확정된 화면 구조에 맞췄다. 탭별 응답 일치와 불필요한 쿼리 미실행 검사는 유지했다.
- 전체 순회 후 네이티브 힙과 보관된 화면/이미지의 메모리는 여전히 크다. 광고 해제만으로 모두 회수됐거나 메모리 누수가 해결됐다고 판정하지 않는다. 추가 메모리 분석 대상이다.
- 운영 광고 소재와 느린 네트워크, 여러 기기에서 같은 지연 개선율을 보장하지 않는다. iPhone 실기기, 실제 회원의 저장/게시/예측 참여, 웹과 네이티브의 1px 캡처 대조는 실행하지 않았다. 배포와 운영 DB 쓰기는 실행하지 않았다.
- 검증 후 별도 진단 앱을 제거하고 USB 화면 유지 설정을 원래 값 0으로 복원했다. 운영 앱 `1.0.2 (33)`을 그대로 다시 열었다. 성능 변경은 소스에 반영되어 있으며 기존 설치본을 업데이트한 것은 아니다.
- 후속 운영 광고 검증은 별도다. 사용자가 34에서 광고 한 곳만 표시된다고 보고해, 같은 Play 서명의 미출시 검증용 35를 데이터 보존 업데이트로 검사했다. 실제 운영 단위에서는 팀 채널 뒤만 로드 및 노출됐고 나머지는 SDK no-fill이었다. **세 지면 실제 노출 검사는 미통과이며 배포 보류**다. 승인 범위와 현재 기기 및 스토어 상태는 `admob-production-34-2026-10-31.md`의 후속 실기기 검증 35를 따른다.
- 36번 후속 수정에서는 SDK 자동 갱신과 겹치는 앱 재시도를 제거하고 홈 광고단위를 분리했다. 첫 실행에서는 세 지면의 실제 광고 및 노출을 모두 확인했으나 새 실행에서는 상단 no-fill이 반복돼 **공급 안정성 검증은 미통과, 배포 보류**를 유지한다. 현재 폰은 진단 36, 스토어는 34이며 다음 정식 빌드 번호는 최소 37이다. 최신 근거는 `admob-placement-fix-2026-10-31.md`와 `artifacts/ads-placement-fix-2026-10-31/`에 있다.
