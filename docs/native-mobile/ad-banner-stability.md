# Android 광고 배치와 안정성 수정

## 2026-10-31 배포 재개

사용자가 No fill은 광고 공급 상황에 따라 발생할 수 있음을 확인하고 현재 코드의 Android와 iOS TestFlight 배포를 요청했다. 이전 진단의 최초 충전율 100% 조건을 배포 차단 기준으로 적용하지 않는다. 광고가 공급됐을 때의 표시, 중복 요청 방지, 동의 준수와 첫 로드 실패 시 빈 지면 제거를 검증 기준으로 삼는다. 현재 코드는 첫 로드 실패 지면을 제거하고 이미 로드된 소재는 갱신 실패에도 유지하며 공개 콘텐츠 URL을 전달한다. Android 정식 빌드는 39, iOS 빌드는 19다. 요청에 따라 USB 화면 유지 설정은 원래 값 0으로 복원했다. 아래는 당시 진단과 정리 이력이며 문의는 발송하지 않았다.

## 2026-10-31 광고 미표시 지면 제거와 콘텐츠 URL 전달

- 사용자 요청으로 광고를 불러오지 못한 지면은 영역 자체를 제거한다. 웹 `components/ui/ad-slot.tsx`가 AdSense `unfilled` 지면을 `display: none`으로 숨기는 동작과 같다. 로딩 중에는 기존 예약 높이와 `광고영역` 안내를 유지하고, 첫 로드가 실패하면 공용 상하 여백과 호출 화면이 준 여백까지 렌더링하지 않는다.
- 실패한 지면은 네이티브 배너를 해제해 SDK가 보이지 않는 지면을 계속 재요청하지 않게 한다. 같은 방문에서는 다시 표시하지 않고, 지면별 요청 간격 60초가 지난 뒤의 다음 화면 방문이나 앱 복귀에서만 다시 요청한다. 이미 표시한 광고는 SDK 갱신 실패에도 기존 소재를 유지한다.
- 요청 시작 기준을 화면 아래 160dp에서 한 화면 높이로 넓혔다. 대부분의 로드와 제거가 화면 밖에서 끝나 보이는 레이아웃 이동을 줄인다.
- 비개인화 요청에 AdMob 콘텐츠 매핑 `contentUrl`을 추가했다. 같은 콘텐츠의 공개 웹 페이지가 있는 광고 화면만 `https://minion.fan` 경로를 보내며, 팀 일정 탭은 웹 팀 경기 캘린더 `/fan/{team}/matches`로 대응한다. 대응 페이지가 없는 화면은 URL을 보내지 않는다. 요청 옵션 변경은 네이티브 재요청을 일으키므로 배너 세션 시작 시 URL을 고정한다.
- 화면 밖으로 스크롤된 로드 완료 배너는 해제하지 않는다. 재요청이 실패하면 스크롤 중 콘텐츠가 이동하기 때문이며, 이 배너의 SDK 자동 갱신은 유지된다. 화면 재진입 후 60초 요청 간격을 기다리는 지면은 기존처럼 `광고영역`을 보인다.
- 잠금 파일 `mobile/app/(tabs)/index.tsx`와 `mobile/components/minion-screen.tsx`는 변경하지 않았다. 개인정보처리방침에는 현재 화면의 공개 URL 전달 문구가 없으므로 문구 보강 여부는 별도 검토 대상이다.
- 검증: 광고·성능 계약 테스트 26개 통과. 신규 3개는 첫 로드 실패 시 지면 제거와 JS 재시도 없음, 쿨다운 뒤 재방문 복귀, 콘텐츠 URL 대응표를 검사한다. 앱 typecheck 통과, lint 오류 0 및 기존 경고 2건.
- 미검증: Android 빌드 보류 지침에 따라 빌드와 실기기 확인을 하지 않았다. 실제 광고 공급 변화, 네이티브 레이아웃 이동과 라이트/다크 캡처는 미확인이다. 테스트 광고는 항상 채워지므로 제거 동작은 네트워크 차단 같은 실패 조건에서 확인해야 한다.

## 2026-10-31 전체 지면 첫 운영 요청과 네이티브 대조, 진단 38

진단 37에서 홈을 마지막에 방문하는 순서로 21지면의 최초 운영 요청을 검사했다. 4지면만 load와 impression을 통과했고 17지면은 최초 no-fill이었다. 진단 38의 별도 Android Activity에서 React Native 없이 동일 패키지, Play 서명, GMA 24.6.0과 비개인화 옵션으로 대조해도 운영 단위 4개 중 3개가 no-fill, 1개가 실제 노출이었다. Google 데모 단위는 성공했다. 따라서 모든 화면의 최초 운영 노출은 미통과이며, 현재 증거로 서버 내부 원인을 특정하거나 코드 수정만으로 해결됐다고 판정하지 않는다.

현재 폰은 미출시 진단 38, Play 운영 버전은 34다. 35~38은 공개/테스트 배포 금지이며 다음 깨끗한 정식 빌드는 최소 39다. USB 화면 유지 값 2는 사용자 요청대로 유지하고 배포 요청 시 원래 값 0으로 복원한다. 상세 측정은 [후속 수정 기록](admob-placement-fix-2026-10-31.md)의 최신 항목을 따른다.

사용자가 조사 중단 후 로컬 임시 파일 삭제를 요청했다. 이 광고 진단의 `.tmp` 작업 폴더, `artifacts` 원본 로그와 캡처, 로컬 검증 APK/AAB 및 Android 빌드 출력을 정리하며 이 문서의 측정 요약은 보존한다. 과거 문서에 적힌 원본 산출물 경로는 삭제 후 사용할 수 없다. 설치된 앱과 앱 데이터, Play 미출시 파일, 출시 트랙은 이번 로컬 파일 정리 대상이 아니다. USB 설정 복원 기준은 위의 현재 2, 원래 0을 따른다.

## 2026-10-31 요청과 동의 복구 검증, 진단 37

UMP 오류 후 영구 대기, 동시 초기화와 개인정보 옵션 호출을 수정하고 동일 지면의 빠른 재진입 요청을 제한했다. 릴리스 UMP 보존 규칙도 추가했다. 행동 검사 24개, 타입 검사와 lint 오류 0을 확인했다. 실기기 테스트 광고 21지면 모두 load와 impression을 통과했고 운영 광고도 홈, 팬톡과 선수 상세 7지면에서 표시됐다. 재실행 하단은 최초 no-fill 후 약 61초 만에 표시되어 즉시 공급 안정성은 여전히 미통과다. 상세 결과는 [후속 수정 기록](admob-placement-fix-2026-10-31.md)을 따른다.

## 2026-10-31 운영 광고 후속 수정

실기기 35의 단일 지면 노출을 확인한 뒤, AdMob 자동 새로고침과 겹치는 앱 실패 재시도 타이머를 제거했다. 홈은 세 지면에 별도 광고단위를 연결한다. 아래 과거의 수동 재시도 정책보다 이 변경이 우선한다. 근거, 광고단위와 수정본 검증은 [후속 수정 기록](admob-placement-fix-2026-10-31.md)을 따른다. 실제 운영 광고 노출 검증이 끝나기 전에는 해결 완료나 배포 가능으로 판정하지 않는다.

## 2026-10-31 콘텐츠 너비에 맞춘 적응형 배너

- 사용자 요청으로 공용 `ContentBanner`의 고정 `LARGE_BANNER`를 `ANCHORED_ADAPTIVE_BANNER`로 변경했다. `onLayout`으로 측정하고 내림한 콘텐츠 너비를 SDK의 `width`에 전달한다. 기존 지면 위치와 상하 여백은 유지하며 높이는 SDK가 보고한 실제 값을 따른다.
- 이전 inline 방식으로 되돌리지 않는다. 설치된 SDK 15.8.3의 Android `setSizeConfig`는 광고 요청 전에 `onSizeChange`를 전달한다. Anchored 방식은 이때 양수 크기를 계산하므로 `BaseAd`의 초기 0x0을 해제할 수 있다. 부모에는 측정 너비와 예약 높이를 계속 제공하며, 시작 대기 상태도 같은 예약 높이를 유지한다. 성공한 로드와 유효한 크기를 모두 확인하기 전에는 안내를 숨기지 않는다.
- 검증: 앱 typecheck 통과, 앱 lint 오류 0 및 기존 경고 2건, diff 공백 검사 통과. `.tmp/verify-adaptive-banner.cjs`에서 실제 컴포넌트와 설치된 SDK `BaseAd`를 transpile해 320/358/380/736dp 요청 너비, 0x0에서 양수 크기로의 SDK 이벤트 연결, 로드 전 공간 유지, 정상 로드 후 안내 해제를 검증했다. 두 이벤트 순서, 잘못된 크기 무시, 로딩 및 실패 안내, SDK 미준비 및 미지원 상태, 세션 키 유지, 재시도 간격과 횟수 제한 및 성공 후 초기화, 타이머 정리도 모의 실행으로 확인했다.
- ADB를 샌드박스 밖에서 실행하자 Samsung SM-S906N과 에뮬레이터 연결을 확인했다. 설치된 앱은 각각 버전 33과 34의 배포용 앱으로 개발 클라이언트가 아니며 Metro 서버도 없다. 새 Android 빌드 요청이 없어 빌드와 배포는 실행하지 않았다. 따라서 이번 코드의 실제 광고 로드, impression, 스크롤 유지 및 네이티브 라이트/다크 화면은 미검증이다. 모의 실행은 실제 네이티브 렌더링 검증을 대신하지 않는다.

## 2026-10-31 광고 미표시와 팀 채널 수정

- 추가 사용자 요청으로 로드 후 지면 높이는 SDK의 `onAdLoaded`와 `onSizeChange`가 보고한 실제 높이를 따른다. 바깥 고정 높이를 제거하고 공용 상하 여백은 각 24dp에서 12dp로 줄였다. 표준 배너 요청 방식, 지면 위치와 화면별 독바 회피 여백은 유지한다. 광고 이미지 내부의 여백은 앱에서 자르거나 변형하지 않는다.
- 로딩과 초기 실패에는 100dp `광고영역`을 유지한다. 크기 이벤트만으로 광고가 로드됐다고 판단하지 않으며, 로드와 유효한 크기 양쪽을 확인한 뒤 안내를 숨긴다. 0, 음수와 비정상 크기는 무시한다. 초기화 전 placeholder도 일반 레이아웃으로 높이를 확보한다.
- 성공한 광고는 포커스 변경이나 후속 갱신 실패로 제거하지 않는다. 성공 시 재시도 횟수를 초기화해 이후의 별도 실패에도 정상 backoff를 적용한다. 타입 검사 통과, 앱 lint 오류 0 및 기존 경고 2건. 실제 컴포넌트와 재시도 정책을 실행하는 임시 hook 하네스로 SDK 이벤트 순서 두 경우, 50/91/100dp 높이 전환, 잘못된 크기, 로딩과 실패, 동의 철회, 비활성 지면, 세션 키 유지, 재시도 간격과 횟수 제한 및 성공 후 초기화, 타이머 정리를 검증했다. 실제 Android 광고와 네이티브 화면 검증은 여전히 미실행이다.
- 후속 사용자 요청으로 광고가 없는 지면에는 `광고영역`을 표시한다. 기존 표면 토큰과 13px Pretendard를 사용하며, SDK가 양수 크기의 광고 로드를 보고하면 문구를 숨긴다. 로딩, 초기 실패와 재시도 중에도 배너 자체는 유지한다. 타입 검사와 변경 파일 ESLint, 모의 실행의 로딩/실패/0 크기/정상 로드 전환을 통과했다. 실제 기기 화면은 미검증이다.
- 사용자 요청은 빈 지면 제거가 아니라 실제 광고 표시 복구다. 기존 지면 높이, 동의 조건과 재시도 정책은 유지한다.
- 설치된 `react-native-google-mobile-ads` 15.8.3의 `BaseAd`는 0x0에서 시작한다. Android inline 배너의 초기 `AdSize` 높이도 0이며, 기존 creative 부모에는 너비가 없었다. 따라서 표준 `LARGE_BANNER`(320x100)와 측정된 부모 너비를 사용해 초기 표시 크기를 확보한다. 의존성이나 네이티브 코드를 수정하지 않는다.
- 로드 완료에는 SDK가 보고한 크기, 노출에는 별도 impression 로그를 남긴다. 로드 성공만으로 실제 노출 성공을 판정하지 않는다. 기기 로그가 없어 사용자 화면의 미표시 원인을 확정한 상태는 아니다.
- 잠금 홈 파일의 팀 채널만 이번 요청의 통합 변경으로 처리한다. 웹 `components/domain/home-dashboard.tsx`의 `grid-cols-5 gap-2`, 44px 로고와 기존 링크를 근거로 5개씩 두 행에 배치한다. 화면 너비 대신 실제 행의 flex 분배로 폭을 결정한다. 다른 홈 섹션은 변경하지 않는다.
- `mobile/AGENTS.md`가 참조하는 OWNER-A.md와 OWNER-B.md는 현재 저장소에 없다. 현재 단일 실행 기준인 README와 기존 웹 원본을 적용했다.
- 실제 Android 광고 로드와 impression, 네이티브 라이트/다크 캡처는 미검증이다. ADB 서버가 시작되지 않아 기기 연결을 확인할 수 없었으며 Android 빌드와 배포는 실행하지 않는다.
- 검증: 앱 typecheck 통과, lint 오류 0 및 기존 경고 2건, diff 공백 검사 통과. 실제 컴포넌트를 transpile한 모의 실행에서 두 행의 5개 셀, 44px 로고, 10개 링크, 팀 누락 시 열 유지와 배너 부모 너비 320/358/380/736px, 운영 광고 ID, 로드 및 impression 콜백을 확인했다. 모의 실행은 네이티브 광고 공급이나 렌더링 검증을 대신하지 않는다.

지면 수는 광고 공급 성공 횟수가 아니다. 콘텐츠가 없는 상태, 블라인드 게시글과 검색 조건 등 기존 노출 조건을 적용한다. 승부예측은 웹에서 별도 환경 설정으로 opt-in하는 지면으로, 앱의 기존 비활성 설정을 유지한다. iOS용 AdMob 앱/광고단위가 등록되지 않은 기존 구성도 유지한다.

## 공용 동작

- 화면 좌표 폴링, 스크롤 위치에 따른 opacity 전환과 별도 한국어 광고 라벨을 제거했다. SDK가 표시하는 광고 식별 표시는 변경하지 않는다.
- inline adaptive 배너는 측정한 콘텐츠 너비와 최대 100px 높이를 전달한다. 바깥 100px 지면을 로딩 전부터 유지한다. 광고 미제공 시에도 빈 지면은 남아 콘텐츠가 갑자기 위로 이동하지 않는다.
- 새 요청과 수동 재시도는 포커스된 전경 화면에서 키보드/모달이 닫혔을 때만 한다. 이미 시작한 배너는 스크롤, 모달, 포커스 변경으로 재생성하지 않는다. 동의 철회는 네이티브 배너를 제거한다.
- 성공한 광고 갱신은 SDK에 맡긴다. 실패 시 network/internal은 30초와 60초, no-fill/mediation-no-fill은 60초와 120초 간격으로 최대 두 번 재시도한다. 설정 오류와 알 수 없는 오류는 자동 재시도하지 않는다. 성공, 화면 비활성, 언마운트는 대기 중인 타이머를 취소한다.
- 지면 이름, 오류 코드, 재시도 횟수와 시각을 콘솔 및 최대 50개 메모리 기록으로 남긴다. `getRecentBannerFailures()`로 확인한다. 사용자 정보와 SDK 원문 오류는 저장하지 않는다.
- 홈 잠금 영역에는 누락 광고 2곳만 추가한다. 공용 ScrollView와 게시글 ScrollView는 네이티브 광고 뷰가 화면 밖에서 분리되지 않도록 clipping을 끈다.
