# MINION 네이티브 모바일 앱 전략 — 요약

현재 실행 문서는 [`docs/native-mobile/README.md`](./native-mobile/README.md)다.

## 목표

Expo + React Native 앱에서 기존 웹 모바일의 디자인·정보·동작을 **1px 단위로 동일하게 재현**한다. 앱용 재해석이나 리디자인은 하지 않는다.

## 구조

- 웹/API: 기존 Next.js 유지
- 앱: `mobile/`의 Expo SDK 54 + Expo Router
- DB/Auth/Storage: 기존 Supabase 유지
- 공개 화면 데이터: `/api/mobile/v1/*` 집계 API
- 공용화: DTO, 검증, 포맷, 도메인 로직
- 비공용: 웹 React 컴포넌트와 CSS. 앱에서는 수치와 동작을 React Native로 정확히 번역한다.

## 제품 범위

포함: 홈, 일정, 대회, 승부예측, 경기 상세·라이브·평점, 팀·선수, 팬페이지, 뉴스·소셜·영상, 커뮤니티, 인증·프로필·알림·딥링크.

제외: 관리자 화면, 운영/동기화 도구, 주간 리포트 전체.

## 보안 경계

- 앱에는 publishable key만 포함하며 서버 비밀키를 넣지 않는다.
- 커뮤니티 쓰기, 신고, LP, 업로드 검수, 비회원 처리 등 권한 작업은 Next API를 통과한다.
- Supabase 직접 접근은 인증과 RLS로 제한된 사용자 데이터에만 허용한다.

### 0단계 — 기준선·계약

- 웹 경로와 앱 경로, 독바 활성 범위, 집중 화면 정책을 확정한다.
- 390×844 라이트·다크 웹 캡처와 성능 기준을 저장한다.
- 모바일 API DTO, endpoint allow-list와 보안 경계를 정의한다.
- Android·iPhone 실제 기기에서 safe area, 폰트, 네트워크 조건을 기록한다.

완료 조건: 반복 가능한 웹 기준선과 실제 기기 비교 환경이 있고, 화면·API 계약의 담당자가 정해져 있어야 한다.

### 1단계 — 앱 셸

- Expo SDK 54, Expo Router, 폰트, 라이트·다크 테마를 구성한다.
- 헤더, 스크롤 시 헤더 노출·숨김, 허브·팬 로컬 내비게이션과 독바를 웹과 동일하게 구현한다.
- 최애팀 없음 → 팀 선택 모달, 팀 선택 → 이동만 수행, 팬페이지 별 버튼 → 최애팀 설정 규칙을 보존한다.
- 로딩·빈 상태·오류·토스트·바텀시트의 공통 기반을 만든다.

완료 조건: iOS·Android Expo Go에서 공통 셸의 시각·동작·safe area가 웹과 일치해야 한다. 현재 완료된 셸은 잠금 영역이다.

### 2단계 — 공개 읽기 화면

- 홈, 일정, 대회, 승부예측, 경기 상세·라이브, 팀, 선수, 팬 채널, 뉴스, 검색과 커뮤니티 읽기 화면을 구현한다.
- 앱은 `/api/mobile/v1/*` 집계 API를 사용하고 캐시 데이터를 먼저 표시한 뒤 백그라운드에서 재검증한다.
- 각 화면은 웹 JSX·CSS·computed style과 동일한 콘텐츠 순서, 조건 분기, 스와이프, 모달과 이동 결과를 가진다.
- A는 매치·탐색, B는 팀·선수·팬을 담당하며 잠금 파일은 공동 합의 없이 수정하지 않는다.

완료 조건: 화면마다 390×844 라이트·다크 overlay 비교에서 레이아웃 차이가 최대 1px이고, 로딩·빈 상태·오류와 실제 기기 동작까지 일치해야 한다.

### 3단계 — 커뮤니티 참여

- 허브·팀 커뮤니티의 목록, 상세, 검색, 댓글·답글, 반응, 신고와 차단 상태를 구현한다.
- 글 작성·수정·삭제, 이미지 업로드와 투표를 웹 정책과 동일하게 제공한다.
- 저장된 Tiptap JSON은 네이티브로 렌더링하고, 호환성이 필요한 작성 본문에만 제한적으로 WebView를 사용한다.
- 길이·금칙어·제재·업로드 검수·LP·AI 검수 같은 권한 로직은 Next 모바일 API에서 처리한다.

완료 조건: 웹과 동일한 권한·문구·낙관적 업데이트·실패 복구를 가지며 비로그인 사용자의 허용 범위도 일치해야 한다.

### 4단계 — 인증·사용자 동기화

- Supabase Auth 세션과 설치 식별자를 SecureStore에 저장하고 자동 갱신·로그아웃을 구현한다.
- 이메일, Google, Kakao, Apple, Naver 로그인을 시스템 브라우저와 앱 딥링크로 연결한다.
- OAuth 완료 후 로그인 전 화면으로 복귀하며, 토큰을 딥링크 query에 직접 넣지 않는다.
- Naver처럼 서버 중계가 필요한 로그인은 Next callback이 짧게 만료되는 일회용 코드를 발급하고 앱이 세션으로 교환한다.
- 프로필, LP, 알림 설정, 최애팀·팔로우 팀, 내 글·댓글과 차단 목록을 사용자 계정과 동기화한다.
- 비로그인 상태, 세션 만료, 계정 연결 충돌과 탈퇴 상태를 웹과 같은 흐름으로 처리한다.

완료 조건: iOS·Android에서 모든 로그인·로그아웃·세션 복원·원래 화면 복귀가 성공하고, RLS와 서버 권한 경계를 통과해야 한다. iOS에서 제3자 로그인을 제공할 때 Apple 로그인도 함께 제공한다.

### 5단계 — 푸시·딥링크

- 기기별 Expo push token을 사용자 계정과 연결하고 알림 설정 변경·로그아웃·토큰 갱신에 맞춰 등록을 관리한다.
- 팔로우 팀 경기 시작, 주요 경기 이벤트, 평점 오픈, 내 글 댓글·답글과 커뮤니티 반응 알림을 지원한다.
- 알림을 누르면 실행 중·백그라운드·종료 상태 모두 정확한 앱 화면으로 이동한다.
- 기존 웹 URL과 앱 라우트를 같은 규칙으로 매핑하고 알 수 없는 링크에는 안전한 폴백을 둔다.

완료 조건: 실제 iOS·Android 기기에서 알림 수신, 설정 반영, 중복 방지와 모든 앱 상태의 딥링크 이동을 검증해야 한다.

### 6단계 — 안정화·배포

- 실제 기기에서 성능, 접근성, 키보드, 뒤로가기, 네트워크 단절·재접속과 캐시 복구를 점검한다.
- 오류 수집, 개인정보 처리, 권한 문구, 앱 아이콘·스플래시와 스토어 메타데이터를 확정한다.
- iOS·Android 빌드, 내부 테스트, 스토어 심사와 단계적 배포를 진행한다.
- 웹과 앱의 기능·디자인 회귀 체크리스트를 릴리스마다 실행한다.

완료 조건: 타입·린트·계약 테스트와 실제 기기 QA가 통과하고 치명적 오류 없이 스토어 배포 및 롤백 절차가 준비돼 있어야 한다.

- 제로베이스: 그 밖의 모바일 라우트 UI.
