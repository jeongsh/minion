# MINION 디자인 기준

이 문서는 바이브 코딩과 UI 수정 시 반드시 지켜야 할 공용 디자인 기준이다. 새 컴포넌트는 기존 화면의 임의 크기를 복사하지 말고 이 문서의 역할과 위계를 먼저 따른다.

## 우선 원칙

- 사용자가 지금 판단하고 행동하는 데 필요한 핵심만 남긴다. 설명량보다 핵심을 빠르게 찾을 수 있는지를 기준으로 삼는다.
- 설명을 빼도 이해하고 사용할 수 있으면 생략한다. 제목과 조작의 의미를 반복하거나 빈 공간을 채우는 문구는 넣지 않는다.
- 중복 정보, 불필요한 컨테이너, 과도한 여백을 줄여 컴팩트하게 만든다. 기존 타이포그래피, 가독성, 터치 영역은 유지한다.

## 화면 구성과 문구

- 구현 전에 홈과 관련 서브페이지의 실제 화면 및 공용 컴포넌트를 확인한다. `minion-design` 스킬에도 실행 기준을 정리한다.
- 홈 섹션 제목과 전체보기는 `components/ui/section-heading.tsx`의 `SectionHeading`을 사용한다. 전체보기 아이콘은 공용 ChevronRight를 따른다.
- 화면 문구에 가운데점(U+00B7)을 쓰지 않는다. 메타 정보는 별도 요소와 gap으로 나눈다. 유사한 점 기호로 우회하지 않는다.
- 제목은 필요한 이름 하나로 표현한다. 영문 장식 제목, 중복 부제, 내비게이션과 중복되는 페이지 소개를 추가하지 않는다.
- 자명한 조작 설명과 통계 해설을 기본 노출하지 않는다. 데이터 범위와 단위, 표본, 위험한 작업의 필수 안내는 간결하게 유지한다.
- 테두리는 꼭 필요한 곳에만 사용한다. 기존 표면 색상과 간격으로 구분하고 큰 외곽 테두리, 카드 중첩, 과도한 패딩을 피한다.
- 홈 목록은 `home-board-carousel.tsx`의 표면과 반응형 밀도를 기준으로 한다. 모바일에서 불필요한 카드 외곽과 여백을 줄인다.
- 홈 메타와 선수 빌드는 카드형을 유지한다. Probuild의 사진, 이름, 챔피언, 아이템 배치를 참고하되 색상은 MINION 토큰을 그대로 사용한다. 모바일도 카드형 캐러셀로 표현한다.
- Probuild 참고 범위는 기존 카드 내부의 정보 순서와 표현이다. 별도 요청 없이 섹션을 추가하거나 홈 배치, 카드 수, 데이터 선정 방식을 바꾸지 않는다.
- `--ui-card-bg`, `--ui-surface`, `--ui-card-hover` 등 기존 토큰을 사용한다. 라이트 모드를 위해 테두리를 덧붙이지 않는다.
- 오래된 구현에 남은 금지 표현이나 작은 글씨를 복사하지 않는다. 최신 사용자 지침이 우선한다.

## 타이포그래피 원칙

- 기본 글꼴은 `Pretendard`다.
- `Paperozi`는 페이지 제목과 주요 섹션 제목에만 사용한다.
- 탭, 버튼, 필터, 표, 메타 정보, 배지에는 `Paperozi`를 사용하지 않는다.
- 예외: 웹 모바일 헤더의 허브 로컬 메뉴는 기존 브랜드 표현인 `Paperozi`를 유지한다.
- 크기는 요소의 태그가 아니라 역할로 결정한다. `h2`라는 이유만으로 크게 만들거나 카드 제목을 메타 크기로 줄이지 않는다.
- 같은 페이지의 동일한 역할은 크기와 굵기가 같아야 한다.
- 한글 문장형 본문은 기본 16px이다. 공간이 좁다는 이유로 14px까지 줄이지 않는다.
- 14px은 버튼, 보조 컨트롤, 표 데이터, 짧은 메타처럼 압축이 필요한 UI에만 사용한다.

## 폰트 위계

| 역할 | 크기 | 권장 굵기 | 글꼴 | 예시 |
| --- | ---: | ---: | --- | --- |
| 페이지 제목 | 28px | 400 | Paperozi | 경기 상세, 선수, 기록실 |
| 주요 섹션 제목 | 20px | 400 | Paperozi | 세트 요약, 영상, 승부예측 |
| 하위 섹션 제목 | 18px | 700~900 | Pretendard | 맞대결, 한줄평, 날짜 그룹 |
| 핵심 수치 | 24~56px | 700~900 | Pretendard | 스코어, 평점, 퍼센트 |
| 카드 제목 | 15~16px | 700~900 | Pretendard | 선수명, 경기명, 게시글 제목 |
| 한글 본문 | 16px | 400~500 | Pretendard | 설명, 리뷰, 댓글, 빈 상태 안내 |
| 일반 UI | 14px | 400~500 | Pretendard | 버튼, 탭, 필터, 표 데이터 |
| 메타 정보 | 13px | 400~500 | Pretendard | 날짜, 리그, 포지션, 보조 수치 |
| 영문·숫자 배지 | 12px | 400~500 | Pretendard | LIVE, BO5, W/L, 영상 시간 |

## 한글 최소 크기와 12px 강제 규칙

- 한글이 포함된 텍스트는 최소 13px이다. 이름, 상태, 조사 한 글자라도 포함되면 12px을 사용하지 않는다.
- 11px 이하의 가시 텍스트는 언어와 관계없이 사용하지 않는다.
- 12px은 `LIVE`, `BO5`, `W/L`, 영상 시간처럼 매우 짧은 영문·숫자 표기에만 허용한다.
- 14px 이하 텍스트는 `font-medium`(500)을 넘지 않는다.
- `font-semibold`, `font-bold`, `font-extrabold`, `font-black`을 사용하지 않는다.
- 한글 상태 배지와 한글 메타 정보는 13px 이상을 사용한다.
- 이름, 제목, 버튼 문구, 문장, 표의 핵심 값은 12px로 만들지 않는다.
- 강조가 필요하면 굵기를 올리지 말고 배경색, 테두리, 색상 대비를 사용한다.

```tsx
// Good
<span className="text-xs font-medium">BO5</span>
<span className="text-[13px] font-medium">진행중</span>
<span className="text-[13px] font-medium">2026 LCK</span>
<h2 className="home-section-title text-xl">세트 요약</h2>

// Bad
<span className="text-xs font-medium">진행중</span>
<h3 className="text-[13px] font-black">맞대결</h3>
<button className="font-paperozi text-sm">필터</button>
```

## 매치 상세 기준

- 페이지 제목은 공용 `PageHeader`의 28px Paperozi를 사용한다.
- 경기 스코어는 페이지에서 가장 큰 데이터로 유지하되, 그 외 평점과 통계가 경쟁하지 않게 한다.
- `세트 요약`, `승부예측`, `영상` 같은 1차 구역은 20px Paperozi다.
- `맞대결`, `한줄평`, 선수 평점 그룹 같은 2차 구역은 18px Pretendard 굵은 글씨다.
- 주요 탭은 16px, 선수명과 경기명은 15~16px, 한글 본문은 16px, 매치 데이터 표는 15px, 짧은 메타는 14px을 사용한다.
- `SET POG`, `BO3`처럼 영문·숫자로만 된 배지는 12px·최대 500을 허용한다. 경기 상태처럼 한글이 포함되면 최소 13px을 사용한다.
- 동일한 의미의 상태를 데스크톱과 모바일에서 서로 다른 크기·굵기로 만들지 않는다.

## 로딩과 스켈레톤 기준

- 스켈레톤은 공통 장식이 아니라 해당 페이지의 실제 정보 구조를 미리 보여주는 상태다.
- 홈, 일정, 대회, 승부예측, 선수, 팀, 뉴스, 커뮤니티, 매치 상세은 서로 다른 전용 스켈레톤을 사용한다.
- 다른 페이지의 카드·표·미디어 구성을 임의로 재사용하지 않는다. 전용 상태가 없는 페이지는 중립적인 빈 fallback과 로딩 인디케이터만 사용한다.
- 헤더, 로컬 내비게이션, 이미 표시된 이전 페이지는 불투명한 배경으로 덮지 않는다.
- 페이지 전환 완료를 이미지·영상 다운로드에 묶지 않는다. 미디어는 크기가 고정된 각자의 placeholder에서 개별적으로 로드한다.
- 탭이나 세트 선택처럼 페이지 일부만 바뀌는 동작은 해당 콘텐츠 영역에만 스켈레톤을 표시한다.
- 실제 콘텐츠와 같은 breakpoint, 열 수, 폭, 높이를 사용해 로딩 완료 시 레이아웃 점프를 최소화한다.

## 공용 UI 사용

- shadcn을 사용하지 않는다. 기존 MINION 토큰과 공용 컴포넌트를 재사용한다.
- 모든 표의 기반은 `components/ui/table.tsx` 하나다. 데이터 목록은 `DataTable`, 복잡한 셀과 펼침 행은 같은 Table 구성 요소와 `ExpandableTableRow`로 조합한다.
- 공용 표의 시각 기준은 세트상세와 선수상세다. `Table`이 8px 모서리, `--ui-border` 외곽선, `--ui-card-bg` 헤더, `--ui-surface` 데이터 영역과 행 구분선을 담당한다. POM을 포함한 `DataTable`도 같은 외형을 사용하며 별도 카드 표면이나 모바일 프레임을 만들지 않는다.
- `Table`의 `className`은 표의 열 폭 등에, `containerClassName`은 바깥 여백 등에 사용한다. 이미 외곽선이 있는 상세 콘텐츠 안에서만 `framed={false}`로 중복 프레임을 생략한다. 호출부에 외곽선과 모서리 래퍼를 다시 만들지 않는다.
- 열 정렬은 DataTable의 `align`으로 한 번만 지정해 헤더와 셀에 함께 적용한다. 두 줄 수치는 `TableValue`로 줄 간격을 공유한다. 공용 헤더에 정렬을 강제로 덮어쓰는 클래스를 추가하지 않는다.
- 순위표의 순위는 `rankColumn()`으로 별도 열에 표시한다. 선수명이나 팀명 안에 숫자를 섞지 않는다. 순위와 일반 수치는 공용 표의 14px 기본 글꼴과 고정폭 숫자를 따르며 기울임, 별도 크기와 굵기로 장식하지 않는다.
- 팀 경기기록, 관리자 목록과 정책 표에서도 공용 셀 크기, 줄 높이와 구분선을 사용한다. 부모의 CSS 선택자로 `th`/`td`의 패딩, 배경이나 테두리를 덮어쓰지 않는다. 일반 표의 두 줄 수치는 `TableValue`, 로딩 표는 `TableSkeleton`을 재사용한다.
- 헤더 40px, 데이터 행 최소 48px, 셀 패딩 8px 12px, 기본 14px Pretendard를 공유한다. 열 정렬/폭과 데이터의 팀/진영 색만 호출부에서 정한다.
- 선수상세와 챔피언 상세의 기존 큰 글씨와 상세 표 구성은 의도한 예외다. 선수 시즌 요약의 16px/18px 주요 수치, 챔피언 상세의 16px 이름과 15px KDA 및 기존 보조 수치 배치를 유지한다. 공용화 때문에 이를 일반 목록의 14px 크기와 동일한 줄 구성으로 축소하지 않는다.
- 모바일에서도 같은 표를 사용한다. 여러 열을 작은 글씨로 압축하거나 별도 div 표를 만들지 않고 표 내부에서 가로 스크롤한다. 도메인별 기본/통계 열 전환은 유지한다.
- 공용 표 적용: 대회/팀 순위, 선수 기록/시즌 요약/챔피언 사용, 챔피언 상대/선수/경기/조합, 관리자 목록, 정책/광고 표. 차트, 대진표 연결선과 스킬 빌드 시간축은 표가 아닌 도메인 시각화로 유지한다.
- 검색 입력은 `SearchInput`, 일반 입력은 `Input`, 셀렉트는 `FilterDropdown`, 탭은 `UnderlineNav`/`SegmentedControl`/`SegmentedToggle`, 페이지 이동은 `Pagination`, 일반 액션은 `Button`을 사용한다.
- 콘텐츠 탭과 셀렉트의 전체 높이는 화면 폭에 관계없이 40px이다. 세그먼트 탭은 트랙 패딩을 포함해 40px로 맞추고 내부 항목은 남은 높이를 채운다. 셀렉트 호출부에서 높이나 최소 높이를 덮어쓰지 않는다. 앱은 `minionSize.control`을 사용하며 로딩 화면에도 같은 높이를 적용한다.
- 기존 관리자 폼에 남아 있는 네이티브 셀렉트는 `minion-native-select`로 같은 40px 높이를 공유한다. 새 웹 셀렉트는 계속 `FilterDropdown`을 사용한다.
- 일정과 대회의 데스크톱 2단 헤더는 `EventFilterHeader`를 공유한다. 필터와 보조 버튼은 모두 40px이며, 한 줄일 때 상하 패딩 각 10px과 하단 테두리 1px을 포함해 총 61px이다. 별도 최소 높이로 헤더를 늘리지 않는다. 로딩 화면도 같은 헤더를 사용한다.
- 기본 웹 입력과 셀렉트는 `formControlClassName`으로 40px 높이, `--ui-border` 테두리, 8px 모서리와 포커스 표시를 공유한다. 호출부에서 일반 컨트롤의 테두리 색과 모서리를 임의로 덮어쓰지 않는다. 테두리 없는 `plain` 필터는 해당 용도를 유지한다.
- 모달의 포털, 배경, 스크롤 잠금, Escape, 포커스 가두기와 복원은 `ControlledDialog`가 담당한다. 트리거가 함께 필요한 화면은 `AdaptiveDialog`를 사용한다. 콘텐츠와 제출 로직은 호출부에 둔다.
- 페이지 안에서 같은 역할의 검색/필터/탭/표/모달을 다시 구현하지 않는다. 새로운 요구는 공용 컴포넌트에 추가한다.
- ESLint는 공용 Table 밖의 HTML 표 태그와 공개 화면의 네이티브 select 사용을 금지한다. 기존 관리자 폼의 select는 이 검사 범위에서 제외하며 이번 작업에서 동작을 변경하지 않았다.
