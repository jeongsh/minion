# MINION 모바일·태블릿 전용 반응형 재설계 명세

> 작성일: 2026-07-14  
> 범위: `admin`과 `records`를 제외한 모든 공개 페이지  
> 기준 레퍼런스: CHZZK 데스크톱/모바일 홈, CHZZK 데스크톱/모바일 채널, MINION 현재 코드와 로컬 런타임  
> 목적: PC 화면을 줄이는 반응형이 아니라, 기기별로 정보 우선순위와 조작 구조가 달라지는 모바일·태블릿 전용 경험을 정의한다.

---

## 0. 이 문서에서 먼저 고정하는 결론

1. **모바일은 PC의 축소판이 아니다.** 모바일에서는 한 화면에 하나의 핵심 과업만 남기고, 보조 정보는 요약·접기·더보기·상세 화면으로 이동한다.
2. **태블릿은 큰 모바일도, 작은 PC도 아니다.** 768~1199px에서는 사이드바를 없애고 2열 콘텐츠와 태블릿 전용 상단 셸을 사용한다.
3. **전역 내비게이션과 팬 내비게이션을 겹치지 않는다.** 팬 페이지에서는 허브 하단 탭을 제거하고 팬 전용 탭만 유지한다.
4. **현재 `lg=1024`, `xl=1280`에 몰린 급격한 레이아웃 전환을 해체한다.** 콘텐츠별 전환점을 두고, 1024px에서 데스크톱 LNB가 갑자기 나타나는 현행 동작을 없앤다.
5. **데이터를 숨기는 것과 삭제하는 것을 구분한다.** 모바일 첫 화면에서는 덜어내되, `더보기`, 드로어, 상세 화면, 아코디언을 통해 전체 데이터에 접근할 수 있어야 한다.
6. **한국어 본문은 16px을 기본으로 한다.** 14px은 압축 UI와 짧은 메타 정보, 13px은 보조 메타, 12px은 `BO5`, `W/L`, 시간처럼 짧은 숫자·영문 배지에만 쓴다.
7. **모든 탭·버튼의 실제 터치 영역은 최소 44×44px이다.** 시각적으로 작은 아이콘도 hit area는 44px 이상이어야 한다.
8. **모바일 세로 길이는 기능이 아니라 비용이다.** 홈, 리포트, 선수/팀 상세, 팬 홈은 기본 노출량을 제한하고 다음 탐색 지점을 명확히 제공한다.

### 구현 우선순위

| 우선순위 | 작업 | 이유 |
|---|---|---|
| P0 | 전역 셸, 모바일 하단 탭, 태블릿 헤더, 팬 이중 내비게이션 제거 | 모든 페이지의 사용성을 동시에 결정한다. |
| P0 | 공통 터치 규격, 페이지 패딩, 제목 크기, 표 대체 패턴 | 페이지별 작업이 다시 제각각 벌어지는 것을 막는다. |
| P1 | 홈, 일정, 승부예측, 커뮤니티, 팬 홈 | 방문 빈도와 모바일 상호작용 비중이 높다. |
| P1 | 선수/팀 상세, 경기 상세, 대회 상세 | 데이터 밀도가 높아 현재 단순 적층의 피해가 크다. |
| P2 | 리포트, 영상/인스타그램, 글쓰기/수정, 마이페이지 | 길이와 편집 조작을 기기별로 재구성해야 한다. |
| P3 | 로그인/회원가입, 내부 실험 페이지 | 셸이 정리된 뒤 짧게 마감할 수 있다. |

동일 URL을 CSS만 줄여 추정하지 않고, CHZZK가 실제로 분리해 제공하는 데스크톱·모바일 셸을 각각 열어 DOM 위치와 계산 스타일을 확인했다. MINION은 실행 중인 `http://localhost:3000`에서 320, 360, 390, 500, 640, 768, 900, 1024, 1100, 1280, 1440px로 폭을 바꿔 점검했다.

### 1.2 포함·제외 범위

- 포함: 홈, 일정, 대회, 팀, 선수, 승부예측, 리포트, 경기·세트, 커뮤니티, 마이페이지, 인증, 모든 팬 페이지, 내부 CHZZK 콘셉트 실험 페이지
- 제외: `/admin/**`, `/records`
- 리다이렉트 경로도 포함: 커뮤니티 보드별 진입/새 글 경로는 최종 도착 화면과 함께 검증한다.
- 이번 문서는 **설계 명세**다. 실제 화면 변경은 후속 구현 단위로 나눈다.

## 2. CHZZK 데스크톱과 모바일의 차이

## 2.1 전역 셸 비교

| 항목 | 데스크톱 | 모바일 | MINION에 적용할 원칙 |
|---|---|---|---|
| 상단 헤더 | 60px 높이, 로고·검색 입력·다수 유틸리티 | 48px 높이, 로고·검색 아이콘·메뉴·앱 열기 | 767px 이하에서는 검색창을 검색 아이콘으로 바꾸고, 계정/테마/LP를 모두 헤더에 펼치지 않는다. |
| 좌측 내비게이션 | 240px 고정, 주요 메뉴·팔로잉·추천·일정·서비스 | 완전히 제거 | 모바일·태블릿에서는 LNB를 렌더링하지 않는다. 메뉴 드로어와 하단 탭으로 나눈다. |
| 보조 주제 탭 | 콘텐츠 영역 안에 배치 | 상단 48px 아래 42~46px 고정 탭 | 문맥 탭이 중요한 화면은 헤더 아래 44px 단일 행으로 고정한다. |
| 하단 내비게이션 | 없음 | 홈 기준 약 54px 고정 | 허브 페이지에만 56px 하단 탭을 사용하고 팬/편집/몰입형 화면에서는 숨긴다. |
| 검색 | 239×38px 입력창, 15px 텍스트 | 아이콘 하나 | 모바일에서 검색을 항상 노출하는 대신 검색 전용 오버레이로 전환한다. |
| 사이드 콘텐츠 | 한 화면에 계속 노출 | 메뉴나 상세 화면으로 이동 | 인기글·광고·추천과 같은 보조 정보는 모바일 본문 아래에 그대로 붙이지 않는다. |

CHZZK의 핵심은 `display: none` 몇 개가 아니다. **PC의 가로 폭을 사용하던 탐색·검색·보조 정보를 모바일에서는 별도의 진입점으로 재배치**한다.

## 2.4 CHZZK에서 가져와야 할 패턴과 가져오지 말아야 할 값

### 가져올 패턴

- 데스크톱과 모바일을 별도 정보 구조로 설계한다.
- 검색 입력→검색 아이콘, LNB→메뉴/하단 탭, 모자이크→단일 캐러셀처럼 **형태를 바꾼다**.
- 카드 제목 크기는 과도하게 줄이지 않고, 카드 수와 메타데이터 양을 줄인다.
- 채널에서는 프로필·주요 CTA·채널 탭을 첫 화면에 묶고 부가 행동을 더보기에 숨긴다.
- 가로 스크롤 레일에서 다음 카드 일부를 보여 탐색 가능성을 알린다.

### 그대로 복제하지 않을 값

- CHZZK 모바일의 12px 한국어 설명은 MINION의 가독성 기준에 맞지 않는다.
- 34px 높이 데스크톱 CTA는 터치 환경 기준으로 부족하다.
- 서비스 고유의 앱 설치 배너와 라이브 방송 중심 내비게이션은 MINION IA에 맞지 않는다.
- CHZZK의 시각 언어·색·브랜딩을 복제하지 않고, 구조와 밀도 변화만 참고한다.

## 3. MINION 현행 반응형 감사 결과

## 3.1 뷰포트 매트릭스

홈의 실제 문서 높이와 고정 셸을 측정한 결과다. 브라우저 세로 스크롤바 약 15px를 제외한 client 폭이 실제 레이아웃 폭이다.

| 요청 뷰포트 | 실제 client 폭 | 고정 셸 | 문서 높이 | 관찰 |
|---:|---:|---|---:|---|
| 320×568 | 305 | 56px 헤더 + 64px 하단 탭 | 4013px | 첫 화면 대비 전역 셸 점유율이 크다. |
| 360×800 | 345 | 56 + 64 | 4106px | 홈 섹션이 대부분 그대로 적층된다. |
| 390×844 | 375 | 56 + 64 | 4170px | 일반 스마트폰 기준에서도 홈이 길다. |
| 500×800 | 485 | 56 + 64 | 4459px | 중간 폭에서 오히려 더 길어진다. |
| 640×900 | 625 | 64 + 64 | 4179px | 헤더 높이만 바뀌고 정보 구조는 모바일과 같다. |
| 768×1024 | 753 | 64 + 64 | 4377px | 검색창과 계정 정보가 헤더에서 충돌하는 태블릿 과밀 상태다. |
| 900×800 | 885 | 64 + 64 | 4451px | 충분한 가로 폭을 1열 적층이 활용하지 못한다. |

| 1100×800 | 1085 | 64 + 216px LNB | 4459px | 작은 데스크톱에서 콘텐츠 폭이 과도하게 줄어든다. |
| 1280×800 | 1265 | 64 + 216px LNB | 2486px | `xl` 다열 전환으로 문서 높이가 갑자기 절반 가까이 줄어든다. |
| 1440×900 | 1425 | 64 + 216px LNB | 2478px | 데스크톱 구성은 안정적이다. |

### 가장 큰 구조 문제

- 768~1100px가 모바일과 PC 규칙 사이에서 방치되어 있다.
- 1024px에 216px LNB를 바로 노출해 실제 메인 폭을 약 793px로 만든다.
- 핵심 다열 콘텐츠는 1280px까지 기다려, 1024~1279px가 가장 비효율적인 구간이 된다.
- 하단 탭의 5개 항목이 단순히 데스크톱 nav 앞 5개를 잘라 만든 구조라 홈·커뮤니티·마이페이지가 빠지고, 제외 대상인 기록실이 들어간다.
- 팬 페이지에서는 전역 하단 탭과 팬 탭이 동시에 나타나 내비게이션이 중복된다.

## 4. 새 반응형 체계

## 4.1 기기 모드

CSS 폭만으로 레이아웃을 정하되, 세 가지 명확한 제품 모드를 둔다.

| 모드 | CSS 범위 | 기준 폭 | 셸 | 콘텐츠 원칙 |
|---|---:|---:|---|---|
| Handset | 0~767px | 320, 360, 390 | 56px 상단 + 조건부 56px 하단 | 1열, 가로 레일, 접기/요약, 모바일 전용 순서 |
| Tablet | 768~1199px | 768, 834, 1024 | 64px 상단, LNB 없음, 조건부 compact nav | 2열을 적극 사용, 터치 우선, PC 데이터 밀도 금지 |
| Desktop | 1200px 이상 | 1280, 1440 | 64px 상단 + 216px LNB | 다열, 보조 정보 상시 노출 |

### 보조 전환점

- 360px: 극소형 핸드셋 보정. 팀명·탭 라벨 길이와 2열 카드 최소 폭을 확인한다.
- 480px: 큰 핸드셋에서 카드 레일 폭과 폼 배열을 조정한다.
- 600px: 핸드셋 가로/소형 태블릿에서 일부 2열 허용. 셸은 여전히 handset이다.
- 900px: 태블릿에서 2열 비율을 넓히고 보조 패널 일부를 노출한다.
- 1200px: 데스크톱 LNB와 3~4열 전환의 시작점이다.

`sm/md/lg/xl` 유틸리티를 그대로 제품 모드로 간주하지 않는다. 컴포넌트는 `handset/tablet/desktop` 행동 표를 먼저 갖고, 그 행동에 맞는 media query를 사용한다.

## 4.2 전역 셸

### Handset

- 상단 헤더: 높이 56px, 좌우 12px, `env(safe-area-inset-top)` 반영.
- 좌측: 메뉴 44×44px 또는 현재 문맥에 따라 뒤로가기 44×44px.
- 중앙: MINION 로고 또는 짧은 페이지 제목. 둘을 동시에 크게 노출하지 않는다.
- 우측: 검색 44×44px, 사용자/더보기 44×44px. 테마·LP·등급·로그아웃을 모두 펼치지 않는다.
- 허브 하단 탭: 높이 56px + `env(safe-area-inset-bottom)`, 항목은 `홈 / 일정 / 예측 / 커뮤니티 / MY` 5개.
- `대회 / 팀 / 선수 / 리포트 / 기록실`은 전체 메뉴와 홈 진입점에서 제공한다.
- 팬 페이지, 로그인/회원가입, 글쓰기/수정, 예측 다이얼로그, 영상 상세, 양파 보드 입력 집중 상태에서는 전역 하단 탭을 숨긴다.
- 본문 bottom padding은 하단 탭이 있을 때 `calc(72px + env(safe-area-inset-bottom))`, 없을 때 24px.

### Tablet

- 상단 헤더: 64px, 좌우 20px.
- LNB와 하단 탭 모두 기본적으로 사용하지 않는다.
- 좌측 메뉴 버튼, 로고, 최대 320px 검색 트리거/입력, 우측 사용자 아이콘+더보기만 둔다.
- LP·닉네임·등급·로그아웃을 한 줄에 모두 넣지 않는다. 사용자 메뉴 popover로 이동한다.
- 주요 허브 이동은 메뉴 드로어 또는 페이지 상단의 얇은 48px nav rail에서 제공한다.
- 1024px에서도 216px LNB를 띄우지 않는다.

### Desktop

- 1200px부터 216px LNB를 사용한다.
- 1200~1279px에서는 LNB를 72px 아이콘 rail로 줄이는 선택안도 가능하지만, 같은 세션에서 216px과 72px이 자동 전환되며 콘텐츠가 흔들리지 않게 한다.
- 검색 입력, LP/계정 정보, 전체 탐색을 상시 노출한다.

## 4.3 팬 셸

- `/fan/[teamSlug]/**`에서는 전역 허브 하단 탭을 렌더링하지 않는다.
- 모바일 팬 헤더 순서: `56px 전역 상단 → 채널 프로필 104~128px → 44px 팬 탭 → 본문`.
- 팬 탭은 한 줄이어야 한다. 기본 5개는 `홈 / 일정 / 선수 / 커뮤니티 / 영상`, 나머지 `인스타그램 / 양파 / 정보`는 `더보기` bottom sheet로 이동한다.
- 현재 390px에서 2줄로 늘어나는 grid 탭을 제거하고 `overflow-x: auto` 또는 5+More 패턴을 사용한다.
- 태블릿 팬 홈은 일정과 달력을 5:7 또는 1:1 2열로 둔다.
- 팀 전환은 채널 프로필의 팀명/로고를 눌러 bottom sheet를 여는 방식으로 통합한다.

## 4.4 콘텐츠 폭과 여백

| 토큰 | Handset | Tablet | Desktop |
|---|---:|---:|---:|
| 페이지 좌우 padding | 16px | 24px | 32~40px |
| 320px 보정 | 12px | - | - |
| 페이지 상단 padding | 20px | 28px | 32~40px |
| 큰 섹션 간격 | 32px | 40px | 48px |
| 카드 grid gap | 12px | 16px | 16~20px |
| 카드 내부 padding | 16px | 18~20px | 20~24px |
| 밀집 행 좌우 padding | 14~16px | 16px | 18~20px |
| 일반·데이터·팬 화면 | 100% | 100% | 1400px |
| 리포트·게시글 읽기 화면 | 100% | 100% | 1080px |
| 계정·폼 화면 | 100% | 672px | 672px |
| 캡처 화면 | 100% | 576px | 576px |

페이지 전체에 padding을 주고 카드 안에서 다시 과도한 padding을 주는 이중 거터를 피한다. 모바일 full-bleed 미디어는 페이지 거터 밖으로 뺄 수 있지만, 텍스트 기준선은 16px에 맞춘다.

구현에서는 `layout-wide / layout-reading / layout-form / layout-capture` 네 컨테이너만 사용한다. 일반 페이지에서 임의의 `max-w-[1280px]`, `max-w-[1320px]`, `max-w-[1500px]`를 새로 만들지 않는다. 팬 헤더·팬 탭·본문·푸터는 모두 `layout-wide`와 같은 기준선을 공유한다.

금지 규칙:

- 12px 이하 한국어 문장, 메뉴, 버튼 라벨 금지.
- 모바일에서 공간이 부족하다는 이유로 폰트를 먼저 줄이지 않는다. 먼저 데이터·열·메타를 줄인다.
- 동일 위계의 제목이 페이지마다 17, 18, 20px로 흔들리지 않게 공통 토큰을 사용한다.
- 숫자와 영문 배지의 작은 크기를 한국어 라벨에 전파하지 않는다.

## 5.2 버튼·탭·입력

| Compact 버튼 | 36px | 44×44 | 12px | 8px | 데스크톱 표 도구용. 모바일에서는 wrapper로 hit area 확보 |
| 아이콘 버튼 | 아이콘 20~22px | 44×44 | 0 | 10px 또는 원형 | 메뉴, 검색, 더보기 |

| 텍스트 input/select | 48px | 48px | 14~16px | 10px | iOS 확대 방지를 위해 입력 글자 16px |

현재 `Button sm=32px`, `md=40px`을 모바일 핵심 조작에 그대로 사용하지 않는다. `sm`은 데스크톱 밀집 도구에 한정하고 모바일 action은 `touch` 44px variant를 기본으로 한다.

## 5.3 radius·border·shadow

| 대상 | radius | border/shadow |
|---|---:|---|
| 큰 표면 카드/패널 | 16px | 1px 중립 border, 기본 shadow 없음 |
| 미디어 썸네일/일반 카드 | 12px | 이미지 자체에는 border 생략 가능 |
| 입력/버튼 | 10px | focus ring 2px + 2px offset |
| 작은 상태 배지 | 6px 또는 pill | 강한 배경은 짧은 상태에만 사용 |
| 아바타/팀 로고 컨테이너 | 원형 또는 12px | 로고 원본 비율 유지 |
| bottom sheet 상단 | 20px 20px 0 0 | backdrop과 1단계 elevation |
| modal | 16px, 모바일 full-screen 시 0 | 화면을 덮으면 내부 모서리 없음 |

모든 것을 둥글게 만들지 않는다. 레이아웃 구획 자체는 여백과 divider로 나누고, 실제 독립 상호작용 단위에만 카드 radius를 쓴다.

## 5.4 이미지·미디어

- 히어로: 모바일 16:9 또는 최대 높이 220px. 텍스트가 이미지 위에 겹치면 최소 4.5:1 대비를 보장한다.
- 선수/팀 초상: 목록 3:4, 상세 상단은 모바일 최대 높이 280~320px. 4:5 원본을 화면 전체 높이로 그대로 쓰지 않는다.
- 영상: 16:9 고정, 제목 2줄, 메타 1줄. 모바일 홈에서는 72~78vw 폭 레일.
- 팀 채널/로고: 모바일 한 행 5개 고정 대신 64~72px 항목의 가로 레일. 320px에서도 로고와 라벨이 겹치지 않아야 한다.
- 로딩 중 aspect-ratio를 미리 잡아 CLS를 방지한다.

## 5.5 안전 영역·스크롤·접근성

- 상단/하단 fixed UI는 `env(safe-area-inset-top/bottom)`을 반영한다.
- 가로 레일은 페이지 전체 수평 overflow를 만들지 않고 해당 컨테이너 내부에서만 스크롤한다.
- `scrollbar-width: none`을 사용하더라도 다음 카드 일부 또는 페이지 인디케이터로 스크롤 가능성을 보여준다.
- sticky 필터와 탭의 `top`은 실제 셸 높이를 CSS 변수로 공유한다.
- 모달이 열리면 배경 스크롤을 잠그고, 닫힐 때 focus를 원래 trigger로 돌린다.
- hover에서만 드러나는 행동은 모바일에 두지 않는다.
- 200% 확대와 키보드 탐색에서도 버튼·탭·라벨이 겹치지 않아야 한다.

## 6. 공통 컴포넌트 전환 규칙

## 6.1 `AppShell`

대상: `components/layout/app-shell.tsx`, `lib/navigation.ts`

| Handset | Tablet | Desktop |
|---|---|---|
| 56px 헤더, 조건부 56px 하단 탭, LNB 없음 | 64px 헤더, LNB·하단 탭 없음, 메뉴 드로어 | 64px 헤더, 216px LNB |
| 검색 아이콘→full-screen 검색 | 최대 320px 검색 또는 아이콘 | 검색 입력 상시 노출 |
| 사용자 아이콘→bottom sheet | 사용자 popover | LP·계정 정보 직접 노출 가능 |

- pathname 기반으로 `hub`, `fan`, `focus`, `auth` shell variant를 명시한다.
- `nav.slice(0, 5)`를 제거하고 mobile nav 목록을 별도로 정의한다.
- 현재 헤더의 768px 과밀 조합을 제거한다.
- route transition overlay와 fixed nav의 stacking context를 함께 검증한다.

## 6.2 `PageHeader`와 `SectionHeading`

대상: `components/ui/page-header.tsx`, `components/ui/section-heading.tsx`

- `PageHeader` 모바일 제목은 24px, 상하 간격 20/16px.
- 긴 action은 제목 옆에 억지로 붙이지 않고 다음 행 또는 우측 44px 아이콘으로 이동한다.
- 설명은 16px 본문으로 최대 2~3줄. 반복 설명은 모바일에서 접을 수 있다.
- `SectionHeading`의 trailing link는 최소 44px hit area를 갖는다.
- 같은 섹션에서 `제목+설명+필터+더보기`가 모두 한 줄에 있지 않게 한다.

## 6.3 카드와 `SurfacePanel`

대상: `components/ui/surface-panel.tsx`, 도메인 카드 전반

- 모바일 카드 외곽 radius 16px, 내부 미디어 12px, padding 16px.
- 목록형 데이터가 많은 화면은 카드마다 border를 겹치지 말고 하나의 panel 안에 56~72px 행+divider를 사용한다.
- 카드는 전체가 클릭 가능하거나 명확한 CTA가 있어야 한다. 일부 텍스트만 작은 링크로 만들지 않는다.
- 태블릿에서 카드 최소 폭 280px, 정보 카드 최소 폭 320px를 기준으로 2열 여부를 결정한다.

## 6.4 `DataTable`

대상: `components/ui/data-table.tsx`

기본 `min-width: 42rem` 가로 스크롤을 모바일 해법으로 사용하지 않는다.

| 데이터 유형 | 모바일 표현 | 태블릿 | 데스크톱 |
|---|---|---|---|
| 2열 key/value | definition list 카드 | 2열 definition grid | table 가능 |
| 순위/통계 4~6열 | 핵심 3열+행 확장 상세 | 4~5열, 선택 열 숨김 | 전체 table |
| 비교형 선수 데이터 | 선수별 카드 또는 가로 snap | 핵심 열 고정 table | 전체 table |
| 시간 순 경기 데이터 | timeline/list | list/table | table |
| 대진표 | 라운드 selector+세로 경기 목록 | 선택 라운드 2열 | 전체 bracket |

- 정말 가로 비교가 본질인 경우에만 local horizontal scroll을 허용한다.
- 허용할 때 첫 열 sticky, scroll shadow, “옆으로 밀어 전체 보기” 안내를 첫 방문 1회 제공한다.

## 6.5 필터·탭

- 모바일 필터는 한 줄 핵심 필터+`필터` 버튼으로 구성한다.
- 3개를 넘는 select를 sticky 박스에 전부 펼치지 않는다. bottom sheet에서 전체 조건을 편집하고 상단에는 적용된 chip만 남긴다.
- sticky 높이는 44~56px 한 행을 기본으로 하고 최대 88px을 넘지 않는다.
- 탭이 5개를 넘으면 `가로 스크롤` 또는 `4~5개+더보기`를 선택한다. 2줄 wrap은 금지한다.

## 6.6 캐러셀·가로 레일

- 모바일 카드 폭은 `calc(100vw - 64px)` 또는 72~78vw로 다음 카드 12~24px가 보이게 한다.
- 태블릿은 2.2~2.5개, 데스크톱은 grid로 전환한다.
- pagination dot은 5개 이상일 때 축약하고, 화살표는 모바일에서 기본 숨김이다.
- 마우스만 고려한 drag가 아니라 touch pan과 키보드 이동을 지원한다.

## 6.7 다이얼로그·bottom sheet

- Handset: 선택/필터/간단한 행동은 bottom sheet, 복잡한 폼/상세는 full-screen dialog.
- Tablet: 폭 560~720px 중앙 modal 또는 우측 drawer.
- Desktop: 기존 modal.
- 예측 베팅, 팀 선택, 팬 더보기, 필터 편집은 같은 sheet 기본 구조를 공유한다.

## 6.8 푸터·광고·보조 aside

- 모바일의 핵심 피드 끝에 데스크톱 푸터 전체를 반복하지 않는다. 법적/정책 링크 중심의 compact footer를 사용한다.
- 커뮤니티 인기글, 데스크톱 광고 aside를 모바일 본문 끝에 자동 적층하지 않는다.
- 광고는 섹션 사이 명확한 슬롯에만 배치하고, 첫 핵심 행동 이전에는 최대 1개만 둔다.
- 팬/양파/영상 상세처럼 몰입형 화면에서는 compact footer도 생략할 수 있다.

## 7.1 홈 `/`

대상: `app/page.tsx`, `components/domain/home-dashboard.tsx`와 하위 home 컴포넌트

### 핵심 과업

1. 오늘 볼 경기와 예측 가능 여부 확인
2. 관심 팀/리그의 주요 소식 탐색
3. 일정·예측·커뮤니티·영상으로 빠르게 이동

### Handset 구성 순서

1. **히어로 스와이퍼**
   - 16:9, 페이지 거터 기준 full width, 최대 높이 220px.
   - 한 번에 1장만 보이고 제목은 2줄, 설명은 제거한다.
   - 배지+제목+하나의 CTA만 남긴다.
   - 자동 재생은 5초 이상, `prefers-reduced-motion`에서는 중지한다.
2. **다가오는 경기/예측 카드**
   - 다음 경기 1건을 기본 노출한다.
   - 팀 로고, 팀 약칭, 시작 시간, 예측 상태, 참여 CTA만 남긴다.
   - BO, 패치, 대회 전체명, 상세 배당은 `상세` sheet로 이동한다.
   - 여러 경기는 내부 세로 스크롤이 아니라 가로 snap 레일로 전환한다.
3. **빠른 이동**
   - `일정 / 예측 / 대회 / 팀 / 선수 / 리포트` 중 4개 직접 노출+`전체`.
   - 44×44px 이상의 아이콘/라벨 조합, 3열 또는 가로 레일.
4. **오늘의 경기**
   - 최대 3경기. 시간·두 팀·상태만 보이는 64~72px 행.
   - 광고를 경기 리스트 내부 카드처럼 섞지 않는다.
5. **커뮤니티 최신/인기**
   - 탭 2개, 각 5건. 게시판·제목·댓글·시간만 노출.
   - 본문 미리보기와 작성자 부가 정보는 생략한다.
6. **팀 채널**
   - 64~72px 항목 가로 레일. 첫 행 5개 억지 고정 금지.
   - 팀 로고·약칭만 직접 노출하고 전체명은 접근성 라벨과 상세에서 제공한다.
7. **LCK 순위**
   - 상위 5팀, `순위 / 팀 / 승패` 3열만.
   - 득실·연속·세부 지표는 행 확장 또는 전체 순위 링크로 이동한다.
8. **최근 영상**
   - 72~78vw 카드 가로 레일 4개.
9. **이번 달 주요 일정**
   - 전체 월간 달력 대신 날짜가 있는 주간 strip+다음 3개 이벤트.
   - 전체 달력은 `/schedule`로 이동한다.
10. compact footer

### 모바일 첫 화면에서 제거할 것

- 데스크톱 2열 히어로/예측 병치
- 예측 카드 내부 세로 스크롤
- 전체 월간 달력
- 순위와 최근 폼을 모두 완전한 카드로 동시 노출
- 4열 영상 grid
- 반복 광고 슬롯
- 긴 섹션 설명

### Tablet 구성

- 히어로와 다음 경기/예측을 `7:5` 2열로 배치한다.
- 오늘 경기와 커뮤니티를 `1:1` 2열로 둔다.
- 순위와 최근 폼을 `1:1`, 주간 일정은 다음 행 full width로 둔다.
- 내부 스크롤 컨테이너를 금지하고 카드 높이를 콘텐츠에 맞춘다.
- 768px에서 검색/계정이 헤더를 두 줄로 만들지 않게 전역 셸 규칙을 우선 적용한다.

### Desktop 구성

- 기존 히어로+예측 2열 방향은 유지할 수 있다.
- 다만 1200px 시작 시 `1fr + 360px`, 1360px 이상에서 `1.7fr + 420px`로 점진 전환한다.

### 완료 조건

- 390×844에서 히어로와 다음 경기 CTA가 첫 화면 안에 보인다.
- 홈의 기본 문서 높이는 390px 폭에서 현행 약 4170px보다 최소 25% 줄어든다.
- 768~1100px에서 예측 카드 내부 스크롤이 없다.
- 1200px 전후에서 콘텐츠 순서가 갑자기 바뀌거나 높이가 절반으로 튀지 않는다.

- 768px에서 하루 2경기 이상이면 2열 카드가 가능하되 시간 순서를 가로로 읽게 만들지 않는다. 같은 날짜 그룹 안에서 위→아래 순서를 유지한다.

### 완료 조건

- sticky 영역이 어느 폭에서도 88px을 넘지 않는다.
- 320px에서 팀명·스코어·상태가 겹치지 않는다.
- 200% 확대에서도 필터가 페이지 전체 수평 스크롤을 만들지 않는다.
- 현재 화면의 실제 겹침·잘림 원인과 교정 계약은 **17장 일정 페이지 실측 사례**를 함께 적용한다.

### Tablet

- 경기 요약 full width.
- 선택 세트에서 통계와 타임라인을 `7:5` 2열로 둘 수 있다.

## 17. 미세 레이아웃 깨짐 실측 사례 — 일정 페이지

이 장은 2026-07-14에 전달받은 모바일 캡처와 현재 `/schedule` 코드를 같은 화면에서 재현해 분석한 결과다. 이런 문제는 “조금 못생긴 여백”이 아니라, 서로 독립적으로 만든 레이아웃 규칙이 같은 폭에서 충돌한 구조적 결함이다.

### 17.1 캡처에서 보이는 현상

1. fixed 헤더 바로 아래 8px 안팎의 틈으로 이전 경기 콘텐츠가 잘린 채 보인다.
2. 필터가 한 줄 또는 두 줄로 유동적으로 바뀌고 `필터 초기화`는 별도 행을 차지한다.
3. 오늘 날짜 제목이 sticky 필터 뒤로 들어가거나, 폭에 따라 보였다가 사라진다.
4. `Team Secret`, `Karmine Corp`, `Bilibili Gaming`, `Movistar KOI` 같은 팀명이 의미를 구분하기 어려울 정도로 잘린다.
5. 좌우 팀명, 44px 로고 두 개, 64px `VS`, gap이 한 행에서 경쟁해 팀명 가용 폭이 지나치게 작다.
6. 필터와 경기 카드가 각각은 overflow를 만들지 않지만, 전체 화면은 “무언가가 위에 끼이고 잘린” 상태가 된다.

### 17.2 코드상 직접 원인

| 현상 | 현재 구현 | 직접 원인 |
|---|---|---|
| 헤더 아래 콘텐츠 비침 | 헤더 `h-14`(56px), 필터 `sticky top-16`(64px) | 모바일에서 헤더와 sticky top 값이 8px 다르다. |
| 날짜 제목 가림 | 자동 `scrollIntoView()` + section `scroll-mt-40`(160px) | 실제 가림 높이는 헤더+가변 필터 높이인데 고정 160px만 사용한다. |
| 필터의 예상 밖 줄내림 | 바깥 wrapper와 `ScheduleFilters`가 모두 `flex-wrap` | 두 단계 wrap과 divider, reset이 서로 다른 줄을 만든다. |
| 필터 높이 변동 | 4개 dropdown+3개 divider+reset을 모두 직접 노출 | 폭이 줄 때 정보 구조를 바꾸지 않고 wrapping에 맡겼다. |
| 필터 터치 영역 부족 | dropdown trigger 계산 높이 24px | 텍스트 크기만 있고 44px hit area가 없다. |
| 팀명 과도한 잘림 | 양 팀 `flex-1 min-w-0 truncate`, 로고 44px, score `w-16` | 고정 요소를 뺀 나머지를 팀명에 균등 분배하므로 실제 텍스트 폭이 부족하다. |
| 길이가 다른 팀명의 불균형 | 공식 `team.name` 사용 | 모바일용 `shortName` 전환이나 별도 세로 조합이 없다. |

관련 코드 경계:

- `components/layout/app-shell.tsx`: 모바일 헤더 56px, tablet 이상 64px.
- `app/schedule/page.tsx`: `sticky top-16`, 두 단계 `flex-wrap`, reset 직접 노출.
- `app/schedule/schedule-filters.tsx`: dropdown 4개와 divider 3개를 한 flex row에 배치.
- `components/domain/schedule-today-scroll.tsx`: 진입 즉시 `scrollIntoView()`.
- `components/domain/schedule-list.tsx`: `scroll-mt-40`, 공식 팀명+`truncate`, 로고/score 고정 폭.

### 17.4 팀명 가용 폭 실측

첫 경기 `Gen.G vs Karmine Corp` 기준이다.

| 요청 폭 | 카드 폭 | Gen.G 가용 폭 | Karmine Corp 가용 폭 | 결과 |
|---:|---:|---:|---:|---|
| 320 | 263px | 20px / 실제 45px | 20px / 실제 100px | 양쪽 모두 식별 불가 수준 |
| 360 | 303px | 40px / 45px | 40px / 100px | 짧은 이름도 잘림 |
| 390 | 333px | 45px / 45px | 55px / 100px | 한쪽만 온전히 보임 |
| 430 | 373px | 45px / 45px | 75px / 100px | 긴 팀명 여전히 잘림 |
| 480 | 423px | 45px / 45px | 100px / 100px | 이 폭부터 둘 다 온전함 |

`truncate`는 여기서 레이아웃을 고친 것이 아니라 실패를 말줄임표로 감춘 것이다. 팀은 경기의 핵심 식별 정보이므로 다음 중 하나로 구조를 바꿔야 한다.

1. 767px 이하에서 `team.shortName`을 사용하고 전체명은 accessible name과 상세 화면에서 제공.
2. 각 팀을 `로고 위/이름 아래` 세로 묶음으로 바꿔 최소 폭 92~104px을 보장.
3. 시간·상태를 별도 상단 행, 팀 대결을 별도 중앙 행으로 분리.
4. `VS` 폭을 32~40px로 줄이되 팀명 폰트는 14px 아래로 줄이지 않음.

### 17.5 이 화면의 교정 계약

#### 셸·sticky

- 모바일 sticky top을 `top-16`처럼 고정하지 않고 `top: var(--shell-header-h)`로 통일한다.
- `--shell-header-h`는 handset 56px, tablet/desktop 64px.
- sticky 필터 실제 높이를 `ResizeObserver`로 `--schedule-filter-h`에 반영하거나, 모바일 필터를 56px 고정 단일 행으로 재구성한다.
- anchor/자동 스크롤 offset은 `calc(var(--shell-header-h) + var(--schedule-filter-h) + 12px)`를 사용한다.
- `scrollIntoView()`는 콘텐츠와 sticky가 모두 측정된 뒤 실행하고, 뒤로가기 scroll restoration을 덮어쓰지 않는다.
- auto-scroll 후 target heading의 top이 sticky bottom+12px 이상인지 브라우저에서 검증한다.

#### 필터

- handset에는 `월` 또는 현재 기간, 적용 filter chip 최대 1~2개, 44px `필터` 버튼만 직접 노출한다.
- 연도·대회·팀·초기화는 filter sheet로 이동한다.
- divider 문자는 모바일에서 제거한다. divider가 혼자 다음 줄에 남을 수 있는 구조를 금지한다.
- tablet/desktop에서만 4개 dropdown을 한 행에 펼친다.
- dropdown trigger는 시각 높이와 관계없이 최소 44×44px hit area.
- reset은 44px action이며, 적용 조건이 없을 때 숨기거나 disabled 처리한다.

#### 경기 행

- handset은 공식 팀명 대신 `shortName`을 기본으로 한다.
- `시간+상태`, `팀 대결`, `대회+라운드`를 세 행으로 명시한다.
- 팀 대결은 `minmax(0,1fr) 36px minmax(0,1fr)`를 기본으로 하고 각 팀 내부를 세로 배치한다.
- 양 팀은 동일한 최소 폭과 동일한 정렬 규칙을 갖는다.
- 핵심 identity에 `truncate`를 사용할 때는 약칭 자체가 6~8자 안에 들어온다는 데이터 계약이 있어야 한다.
- 공식명 전체를 보여야 한다면 2줄 clamp를 허용하고 양 카드 높이를 동일하게 맞춘다.

### 17.6 이 사례의 완료 조건

- [ ] 헤더와 sticky 사이로 어떤 콘텐츠도 비치지 않는다.
- [ ] 320, 360, 390, 430, 480px 모두 target 날짜 제목이 sticky 아래 12px 이상 떨어져 보인다.
- [ ] 필터는 handset에서 항상 한 행이며 56px을 넘지 않는다.
- [ ] 필터 dropdown, reset, filter sheet action이 모두 44px 이상이다.
- [ ] 320px에서 양 팀을 서로 구분할 수 있는 약칭이 온전히 보인다.
- [ ] `Gen.G`, `Karmine Corp`, `Team Secret`, `Sentinels`, `Bilibili Gaming`, `Movistar KOI` fixture가 모두 통과한다.
- [ ] 뒤로가기 후 scroll 위치가 auto-scroll 때문에 다시 이동하지 않는다.
- [ ] 200% zoom에서 필터와 날짜 제목이 겹치지 않는다.

## 18. 미세 레이아웃 내구성 계약

페이지별 큰 구성을 정해도 아래 계약이 없으면 “괜한 줄내림”, 겹침, 말줄임 남발은 계속 생긴다. 모든 공통 컴포넌트와 신규 화면에 적용한다.

## 18.1 먼저 폭 예산을 계산한다

한 행을 만들기 전에 다음을 숫자로 계산한다.

```text
텍스트 가용 폭 = 컨테이너 폭
               - 좌우 padding
               - 고정 아이콘/로고 폭
               - 고정 badge/score/action 폭
               - gap 총합
```

예를 들어 333px 카드에 좌우 padding 32px, 로고 88px, VS 64px, gap 30px이 있으면 팀명 두 개에 남는 폭은 119px, 한 팀당 약 59.5px뿐이다. 이 상태에서 긴 공식 팀명을 쓰는 설계는 CSS 문제가 아니라 **폭 예산 자체가 성립하지 않는 설계**다.

규칙:

- 텍스트에 필요한 최소 폭을 먼저 정하고 남는 공간에 장식을 배치한다.
- 필수 identity가 80px 미만이면 약칭·세로 재배치·다음 행 이동 중 하나를 선택한다.
- `flex-1`을 두 개 줬다는 이유로 정보가 공평하게 보존된다고 가정하지 않는다.
- 고정 폭이 3개 이상인 행은 320px에서 반드시 실제 폭 예산표를 작성한다.

## 18.2 텍스트 종류별 줄바꿈 정책

`truncate`, `line-clamp`, `whitespace-nowrap`, `flex-wrap`은 서로 바꿔 쓸 수 있는 장식 클래스가 아니다.

| 텍스트 종류 | 기본 정책 | 허용되는 축약 | 금지 |
|---|---|---|---|
| 팀·선수 identity | 1줄 약칭 또는 2줄 전체명 | 데이터 기반 shortName | 첫 글자만 남는 truncate |
| 페이지 제목 | 1~2줄 natural wrap | 없음 | 3줄 이상, action과 충돌 |
| 카드 제목 | 2줄 clamp | 말줄임표 | 높이 미예약으로 카드마다 흔들림 |
| 탭 라벨 | 1줄 no-wrap | 짧은 정식 라벨 | 글자 크기 축소, 2줄 탭 |
| 버튼 라벨 | 1줄 no-wrap | 더 짧은 동사형 라벨 | 버튼 안 임의 줄바꿈 |
| 사용자 닉네임 | 1줄 truncate | 말줄임표 | 등급 badge를 밀어냄 |
| 대회/라운드 메타 | 1줄 truncate 또는 2개 행 분리 | short label | 핵심 팀명보다 넓은 폭 점유 |
| 한국어 본문 | 자연 줄바꿈 | 문단 접기 | 임의 truncate |
| 숫자/스코어 | no-wrap, tabular nums | 단위 축약 | 숫자 중간 줄바꿈 |
| URL/코드 | break-anywhere 또는 local scroll | 표시 라벨 | 문서 전체 overflow |

### 의도하지 않은 줄바꿈 판정

- 1줄이어야 하는 컨트롤이 2줄이 되면 실패다.
- 제목의 마지막 줄에 한 글자/한 짧은 조사만 남으면 orphan으로 본다.
- 같은 grid 행의 카드 중 하나만 제목 때문에 24px 이상 높아지면 고정 clamp 또는 행 정렬을 재검토한다.
- 줄바꿈을 막았더니 핵심 단어가 잘리면 폰트를 줄이지 말고 구조를 바꾼다.

## 18.3 flex/grid 안전 규칙

- `min-w-0`는 flex item이 줄어들게 할 뿐, 정보가 읽히게 보장하지 않는다.
- 핵심 텍스트와 고정 action을 같은 flex row에 둘 때 텍스트 최소 폭을 명시한다.
- `justify-between`은 중간 공간이 충분하다는 보장이 있을 때만 사용한다.
- 3영역 비교는 `grid-template-columns: minmax(0,1fr) auto minmax(0,1fr)`로 대칭성을 보장한다.
- 320px에서 성립하지 않는 grid는 breakpoint에서 열만 줄이는 것이 아니라 카드 내부 순서를 바꾼다.
- `flex-wrap`을 fallback으로 사용하지 않는다. wrap 후 각 행의 의미와 정렬을 별도로 설계한 경우만 허용한다.
- divider, bullet, `VS`, slash 같은 구분자가 단독 행/줄에 남지 않게 인접 항목과 한 묶음으로 처리한다.
- action row가 wrap될 때 primary action은 독립 full-width 다음 행으로 이동한다.

## 18.4 fixed·sticky·anchor 단일 좌표계

모든 고정 요소는 같은 CSS 변수에서 높이와 위치를 읽는다.

```css
--shell-header-h: 56px;
--context-nav-h: 0px;
--sticky-filter-h: 0px;
--shell-bottom-nav-h: 56px;
--sticky-stack-h: calc(
  var(--shell-header-h) +
  var(--context-nav-h) +
  var(--sticky-filter-h)
);
```

- sticky `top`, content `scroll-padding-top`, section `scroll-margin-top`, overlay `top`을 같은 `--sticky-stack-h`로 계산한다.
- 모바일 56px 헤더에 `top-16`을 섞지 않는다.
- 두 sticky가 겹치면 z-index만 올려 해결하지 않는다. stack 순서와 높이를 합산한다.
- 높이가 content wrap에 따라 달라지는 sticky는 `ResizeObserver`로 측정하거나 구조를 고정 높이로 바꾼다.
- anchor 이동, filter 변경, hydration, font load 뒤에도 target이 가려지지 않는지 확인한다.
- bottom nav가 있는 화면의 마지막 action에는 `padding-bottom: calc(nav + safe area + 16px)`를 둔다.

## 18.5 잘림과 overflow 판정

### 허용

- 영상/이미지 crop이 의도되고 focal point가 정의됨.
- 대진표·코드·비교표가 해당 컴포넌트 내부에서 명시적으로 가로 스크롤됨.
- 카드 제목이 2줄 clamp되고 전체 제목 접근 경로가 있음.

### 실패

- `overflow-x: hidden`으로 문서 폭 문제를 감춤.
- 팀명·선수명·버튼 라벨이 의미를 잃을 정도로 잘림.
- focus ring, dropdown, tooltip이 `overflow-hidden` 부모에 잘림.
- scrollbar가 카드 경계나 fixed action 위에 겹침.
- `scrollWidth > clientWidth`인데 사용자가 스크롤 가능성을 알 수 없음.
- transform/absolute 요소가 레이아웃 폭 검사에는 잡히지 않지만 화면 밖으로 나감.

## 18.6 dropdown·popover·modal 경계

- trigger는 44×44px 이상이고, popup은 viewport 좌우 12px 안에 머문다.
- `left: 0` 고정 popup이 우측 화면을 넘으면 collision detection으로 정렬을 뒤집는다.
- handset의 3개 이상 선택지는 bottom sheet가 기본이다.
- popup의 max-height는 `visualViewport` 기준이며 내부 스크롤 가능해야 한다.
- sticky/filter 내부 popup은 부모 `overflow-hidden`에 잘리지 않아야 한다.
- modal footer action은 콘텐츠 길이와 키보드에 밀려 viewport 밖으로 사라지지 않는다.

## 18.7 로딩·이미지·폰트 변화

- fallback 폰트와 실제 웹폰트의 폭 차이로 header/action이 밀리는지 확인한다.
- 로고가 로드되기 전에도 동일한 width/height를 예약한다.
- 이미지 실패 시 alt 텍스트가 44px 로고 박스 밖으로 overflow하지 않게 fallback mark를 사용한다.
- skeleton은 실제 콘텐츠와 같은 열·높이를 사용한다.
- 숫자가 1자리에서 5~7자리로 커져도 badge/action이 밀리지 않게 `tabular-nums`와 최대 폭 정책을 둔다.
- hydration 전후에 sticky 높이와 scroll target이 달라지면 자동 스크롤을 hydration 이후 한 번만 수행한다.

## 18.8 동적 콘텐츠 스트레스 fixture

모든 주요 카드와 헤더를 최소 다음 데이터로 검사한다.

| 유형 | fixture |
|---|---|
| 긴 영문 팀 | `Bilibili Gaming`, `Karmine Corp`, `Movistar KOI`, `Hanwha Life Esports` |
| 긴 한국어 제목 | 28~36자 한국어 제목+숫자+괄호 |
| 선수명 | 2자, 8자, 영문 14자, 한글+영문 혼합 |
| 닉네임 | 2자, 12자, emoji 포함, 공백 포함 |
| 숫자 | `0`, `999`, `99,999`, `9,999,999 LP`, `100%` |
| 상태 | 예정, LIVE, 종료, 연기, 취소, 데이터 없음 |
| 경기 | TBD vs TBD, 로고 없음, 긴 대회명, 5세트, 동점/미정 |
| 게시글 | 제목 없음 방어, 1자, 80자, 썸네일 없음/4장 |
| 오류 | 한국어 2줄 validation, 네트워크 재시도 action |

실제 운영 데이터의 현재 최장 문자열도 주기적으로 fixture에 추가한다.

## 19. 전 페이지 미세 레이아웃 전수검사 방법

### 결론

**전부 분석해서 기록해야 한다.** 다만 페이지마다 스크린샷 한 장을 보고 임시 CSS를 추가하는 방식이 아니라, `공통 컴포넌트 계약 → 페이지별 예외 → 브라우저 회귀 검사`의 세 층으로 관리해야 한다.

## 19.1 검사 축

각 공개 경로는 최소 다음 조합을 가진다.

| 축 | 값 |
|---|---|
| viewport | 320, 360, 390, 768, 1024, 1280, 1440 + 500~1100 drag |
| zoom | 100%, 200% |
| content | 최소, 일반, 최장, 누락/오류 |
| auth | 비로그인, 로그인, 관리자 표시가 섞이는 일반 사용자 셸 |
| state | 기본, loading, empty, error, open, selected, disabled |
| interaction | scroll, sticky, dropdown, dialog, keyboard, back navigation |
| theme | light, dark |

모든 조합을 곱해 수천 장을 수동 확인할 필요는 없다. 공통 컴포넌트는 story/fixture에서 전체 조합을 검사하고, 페이지는 가장 위험한 조합을 선택해 검사한다.

## 19.2 페이지군별 위험 요소

| 페이지군 | 우선 검사할 미세 결함 |
|---|---|
| 전역 셸 | 로고·검색·계정·badge 충돌, fixed 높이, bottom nav, 메뉴 drawer |
| 홈 | hero 비율, 캐러셀 peek, 긴 섹션 제목, 내부 스크롤, 카드 높이 불균형 |
| 일정/경기 | sticky stack, 팀명 폭, score/상태, 자동 스크롤, set 탭 |
| 예측 | 양 팀 대칭, 퍼센트/배당 큰 숫자, CTA 줄바꿈, keyboard+dialog |
| 대회/대진표 | local scroll, sticky round, 긴 팀명, connector clipping |
| 팀/선수 상세 | 큰 이미지, SNS action, stat label, table→card 전환 |
| 리포트 | 장문 orphan, section anchor, 카드 높이, position tab |
| 커뮤니티 | 게시판 chip wrap, 긴 제목/닉네임, 썸네일 유무, editor toolbar |
| 팬 | 전역/팬 nav 중복, 5+More, 팀 테마 대비, media modal |
| 계정/폼 | label/error wrap, input suffix, keyboard, 하단 저장 action |

## 19.3 자동 탐지할 항목

브라우저 검사 스크립트에서 다음을 수치로 수집한다.

- `documentElement.scrollWidth > clientWidth`: 문서 전체 수평 overflow.
- `[data-ui="text"]` 또는 지정 selector에서 `scrollWidth > clientWidth`: 실제 잘림.
- single-line 계약 요소의 `getClientRects().length > 1`: 원치 않는 줄바꿈.
- fixed/sticky와 다음 heading/card의 `DOMRect` 교차: 겹침.
- viewport 밖 popup/modal: `left < 0`, `right > innerWidth`, `bottom > visualViewport.height`.
- 실제 버튼/링크 rect가 44×44px 미만: touch target 실패.
- 동일 grid 행 카드 높이 편차가 24px 초과: 내용 압력 가능성.
- 클릭 가능한 요소가 다른 fixed 요소 아래에 가려지는지 `elementsFromPoint()`로 확인.
- 이미지 natural ratio와 렌더 ratio 차이: 의도하지 않은 왜곡.
- section anchor 이동 후 heading top이 sticky stack보다 작은지 확인.

자동 탐지는 후보를 찾는 장치다. `truncate`가 의도인지, 정보가 의미를 잃었는지는 사람이 스크린샷을 보고 최종 판정한다.

## 19.4 breakpoint 경계 검사

각 구조 변경점은 정확한 폭 한 점이 아니라 전후를 검사한다.

- 359 / 360 / 361
- 599 / 600 / 601
- 767 / 768 / 769
- 899 / 900 / 901
- 1199 / 1200 / 1201

추가로 컴포넌트가 처음 깨지는 실측 폭을 찾고 그 폭의 `-1 / exact / +1`을 회귀 fixture로 남긴다. 일정 필터처럼 415px client에서 2행→1행으로 바뀌는 구성은 임의 breakpoint가 아니라 모바일 전용 컨트롤로 교체해 경계 자체를 없앤다.

## 19.5 전수검사 순서

1. 전역 셸을 빈 페이지와 최장 사용자 정보로 검사.
2. 공통 `PageHeader`, filter, tabs, card, table, dialog를 fixture로 검사.
3. 공개 경로 39개를 기본 상태에서 필수 viewport로 순회.
4. 데이터 밀도가 높은 경로는 최장 문자열/큰 숫자 fixture로 재검사.
5. dropdown, sheet, modal, editor 등 열림 상태를 별도 캡처.
6. sticky 경로는 페이지 진입 직후, 중간 scroll, anchor 이동, 뒤로가기 상태를 각각 검사.
7. 실패를 source component 단위로 묶고 공통 수정부터 한다.
8. 수정 뒤 해당 페이지 한 장만 보지 않고 전체 viewport matrix를 다시 돈다.

## 19.6 페이지별 defect ledger 형식

각 발견 사항은 다음 형식으로 기록한다.

## 20. 미세 QA 완료 기준

한 페이지의 반응형 구현은 아래 조건을 모두 만족해야 완료다.

### 구조

- [ ] 320px부터 1440px까지 문서 전체 수평 overflow가 없다.
- [ ] 500~1100px drag 중 요소가 순간적으로 겹치거나 빈 행이 생기지 않는다.
- [ ] breakpoint 전후 1px에서 구조가 예측 가능하게 전환된다.
- [ ] fixed/sticky/anchor가 같은 높이 변수를 사용한다.

### 텍스트

- [ ] 팀·선수·페이지명 같은 identity가 의미를 잃게 잘리지 않는다.
- [ ] 버튼·탭·숫자는 의도하지 않게 줄바꿈되지 않는다.
- [ ] 카드 제목 clamp와 카드 높이가 일관된다.
- [ ] 한국어 본문을 줄여서 폭 문제를 숨기지 않는다.
- [ ] 최장 문자열 fixture와 실제 운영 최장 데이터가 통과한다.

### 상호작용

- [ ] 44×44px touch target.
- [ ] dropdown/popover/modal이 viewport 안에 있다.
- [ ] virtual keyboard가 입력과 primary action을 가리지 않는다.
- [ ] scroll restoration과 자동 스크롤이 서로 싸우지 않는다.
- [ ] loading→loaded 전환에서 레이아웃이 눈에 띄게 튀지 않는다.

### 시각 검증

- [ ] 필수 7개 viewport 스크린샷 확인.
- [ ] light/dark 확인.
- [ ] 200% zoom 확인.
- [ ] open/loading/empty/error 중 해당 페이지 상태 확인.
- [ ] 실제 이미지와 fallback 이미지 양쪽 확인.

### 금지되는 완료 판단

- `overflow-x-hidden`을 넣었으니 완료.
- 390px 한 장이 괜찮으니 완료.
- 말줄임표가 보이니 완료.
- Tailwind breakpoint가 있으니 완료.
