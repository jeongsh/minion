# 챔피언 페이지 제품·UI·구현 명세

- 문서 상태: 구현 기준 확정안
- 작성일: 2026-08-24
- 대상 서비스: MINION 웹
- 대상 라우트: `/champions`, `/champions/[championSlug]`
- 구현 원칙: 축소 버전을 먼저 공개하지 않고, 이 문서의 완료 조건을 모두 충족한 뒤 공개한다.
- 데이터 원칙: 현재 프로젝트에 이미 적재하거나 적재 가능한 실제 대회 데이터만 사용한다.

## 1. 목적

챔피언 페이지는 챔피언 설명을 제공하는 백과사전이 아니다. 실제 프로 대회에서 해당 챔피언이 어떻게 선택되고 어떤 결과를 냈는지 탐색하는 통계 페이지다.

사용자는 이 페이지에서 다음 질문에 답을 얻을 수 있어야 한다.

- 이 챔피언은 선택한 대회 범위에서 몇 번 픽되고 밴됐는가?
- 픽됐을 때 실제 승률은 얼마인가?
- 어느 포지션에서 사용됐는가?
- 같은 포지션의 어떤 상대 챔피언을 만났고 결과가 어땠는가?
- BOT 또는 SUP으로 사용됐을 때 어떤 바텀 파트너와 실제로 함께 출전했는가?
- 해당 조합이 실제로 함께 출전했을 때의 승률은 얼마인가?
- 어떤 프로 선수가 이 챔피언을 많이 사용했는가?
- 현재 확보한 데이터 안에서 어떤 핵심 룬, 보조 룬 계열, 소환사 주문, 종료 아이템을 선호했는가?
- 각 통계가 몇 경기의 표본과 어느 정도의 데이터 커버리지를 가지는가?

## 2. 확정 범위

### 2.1 포함

- 챔피언 목록 및 챔피언 검색
- 챔피언 상세 페이지
- 시즌, 대회 구간, 세부 대회, 패치 필터
- 포지션별 실제 픽 기록
- 전체 챔피언 기준 픽·밴·픽밴률
- 포지션별 승–패·승률·경기 지표
- 동일 세트·동일 포지션 기반 상대 전적
- 동일 세트·동일 팀 기반 바텀 듀오 전적
- 선수별 사용 기록
- 핵심 룬과 보조 룬 계열
- 소환사 주문 조합
- 경기 종료 시점 아이템과 실제 종료 아이템 조합
- 드래프트 선택 순서와 1·2차 밴 단계 분포
- 실제 경기 목록 및 세트 상세 연결
- 모바일·태블릿·데스크톱 반응형 UI
- 로딩, 빈 상태, 부분 데이터, 오류 상태
- URL 공유 및 브라우저 뒤로 가기 복원
- 검색 노출을 위한 메타데이터

### 2.2 현재 데이터로 제공하지 않는 항목

아래 항목은 현재 원천 데이터로 사실을 보장할 수 없으므로 구현 대상에서 제외한다. UI에 자리만 만들거나 `준비 중`으로 노출하지 않는다.

- 전체 룬 페이지의 모든 일반 룬과 능력치 파편
- 첫 코어, 2코어, 3코어 등 실제 아이템 구매 순서
- 아이템 구매·판매·되돌리기 시각
- 스킬 레벨업 순서
- 인게임 좌표와 교전 위치
- 솔로 랭크 데이터
- 승률만으로 단정한 절대적인 챔피언 상성 등급
- 모델이 추정한 승리 확률 또는 보정 승률

아이템은 반드시 `빌드 순서`가 아니라 `종료 아이템`으로 표기한다. 룬은 반드시 `핵심 룬`과 `보조 계열`로 표기하고 `전체 룬 세팅`이라고 부르지 않는다.

## 4. 통계 원칙

### 4.1 모든 비율은 분자와 분모에서 계산한다

저장된 승률끼리 평균 내지 않는다.

```text
승률 = 승리 세트 수 / 픽된 세트 수
픽률 = 픽된 세트 수 / 픽밴 데이터가 완전한 세트 수
밴률 = 밴된 세트 수 / 픽밴 데이터가 완전한 세트 수
픽밴률 = (픽된 세트 수 + 밴된 세트 수) / 픽밴 데이터가 완전한 세트 수
```

집계 캐시를 만들더라도 `win_rate` 같은 비율보다 `wins`, `games`, `picks`, `bans`, `eligible_sets`를 저장한다.

### 4.2 밴은 포지션에 귀속하지 않는다

밴된 챔피언은 그 경기에서 실제 포지션이 결정되지 않는다. 따라서 `TOP 밴률`, `BOT 밴률` 같은 수치를 만들지 않는다.

- 전체 챔피언 지표: 픽, 밴, 픽률, 밴률, 픽밴률
- 포지션 지표: 해당 포지션 픽 수, 승–패, 승률, 경기 지표
- 포지션 탭 안에서도 밴 수치는 `전체 포지션 공통`임을 명시하거나 상단 전체 지표에만 둔다.
- 포지션별 픽 수에 전체 밴 수를 더해 포지션별 픽밴률을 만들지 않는다.

### 4.3 상대 전적은 실제 동일 포지션끼리만 계산한다

선택 챔피언의 선수 통계 행과 같은 `set_id`, 반대 `team_id`, 같은 `position`의 행을 연결한다.

```text
자기 챔피언 행
  set_id = 상대 챔피언 행 set_id
  position = 상대 챔피언 행 position
  team_id != 상대 챔피언 행 team_id
```

화면 명칭은 `유리한 상대/불리한 상대`보다 `상대 전적`을 기본으로 사용한다. 정렬 옵션으로 `승률 높은 순`, `승률 낮은 순`을 제공할 수 있지만 챔피언 자체의 절대 상성이라고 설명하지 않는다.

### 4.4 바텀 듀오는 실제 동시 출전 조합만 계산한다

BOT 행과 SUP 행이 같은 `set_id`, 같은 `team_id`일 때만 하나의 듀오 기록으로 인정한다.

```text
듀오 경기 수 = BOT A와 SUP B가 같은 팀으로 함께 픽된 세트 수
듀오 승리 수 = 위 세트 중 winner_team_id가 두 선수의 team_id인 세트 수
듀오 승률 = 듀오 승리 수 / 듀오 경기 수
```

BOT A의 개별 승률과 SUP B의 개별 승률을 평균 내지 않는다. 룬·주문·아이템도 개별 최빈값을 조립해 존재하지 않았던 조합을 만들지 않는다.

### 4.5 표본 수를 숨기지 않는다

- 모든 승률 옆에 경기 수를 표시한다.
- 기본 정렬은 승률이 아니라 경기 수 또는 픽 수다.
- 1~2경기: `표본 매우 적음`
- 3~4경기: `표본 적음`
- 5경기 이상: 별도 경고 없음
- 승률 정렬을 선택해도 표본 경고는 유지한다.
- 0경기인 포지션은 선택 불가 상태와 `0`을 함께 표시한다.

### 4.6 누락된 데이터는 0으로 계산하지 않는다

- 룬이 없는 행은 다른 룬의 분모에 넣지 않는다.
- 아이템이 없는 행은 아이템 선택률의 분모에 넣지 않는다.
- 15분 지표가 없는 행은 평균 계산에서 제외한다.
- 각 영역에 `기록 보유 경기 / 전체 픽 경기` 커버리지를 표시한다.

## 5. 정보 구조와 진입 경로

### 5.1 라우트

```text
/champions
/champions/[championSlug]
```

상세 페이지 상태는 쿼리스트링으로 보존한다.

```text
/champions/kaisa?season=2026&segment=lck&patch=all&position=BOT&tab=duos
```

지원 파라미터:

| 파라미터 | 값 | 기본값 |
| --- | --- | --- |
| `season` | 적재된 시즌 연도 | 가장 최신 시즌 |
| `segment` | `all`, `lck-cup`, `lck`, `first-stand`, `msi`, `ewc`, `worlds`, `enc`, `kespa-cup` | `all` |
| `tournament` | 선택 구간 안의 대회 ID 또는 `all` | `all` |
| `patch` | 정규화한 패치 또는 `all` | `all` |
| `position` | `TOP`, `JGL`, `MID`, `BOT`, `SUP` | 현재 범위에서 픽 수가 가장 많은 포지션 |
| `tab` | `overview`, `matchups`, `duos`, `pros`, `games` | `overview` |
| `sort` | 각 탭에서 허용한 정렬 키 | 탭별 기본 정렬 |

유효하지 않은 값은 서버에서 검증하고 안전한 기본값으로 정규화한다. 정규화 결과가 원래 URL과 다르면 canonical URL을 사용한다.

### 5.2 서비스 진입점

- 데스크톱 전역 메뉴의 `선수` 다음에 `챔피언`을 추가한다.
- 모바일 하단 5개 메뉴는 그대로 유지하고 전체 메뉴 안에 `챔피언`을 추가한다.
- 전역 검색 placeholder를 `팀, 선수, 챔피언, 대회 검색`으로 변경한다.
- 전역 검색 결과에 챔피언 타입과 챔피언 이미지를 추가한다.
- 선수 상세의 챔피언 사용표, 경기 상세의 픽밴·선수 챔피언 이미지를 상세 페이지 링크로 연결한다.
- 챔피언 상세의 경기 행은 기존 세트 상세 페이지로 연결한다.

## 6. 챔피언 선택 UX

사용자가 챔피언을 선택하는 방법은 네 가지다.

1. `/champions` 목록에서 선택
2. 전역 검색에서 챔피언 검색
3. 챔피언 상세 상단의 챔피언 전환기에서 선택
4. 선수·경기 페이지의 챔피언 이미지 또는 이름에서 진입

### 6.1 챔피언 목록 페이지

상단부터 다음 순서로 배치한다.

1. `PageHeader`: 제목 `챔피언`, 설명 `실제 대회 경기 기준 챔피언 기록`
2. 시즌·대회·패치 범위 필터
3. 챔피언 이름 검색
4. 포지션 필터: `전체`, `TOP`, `JGL`, `MID`, `BOT`, `SUP`
5. 정렬: `픽밴률`, `픽 수`, `밴 수`, `승률`, `이름`
6. 챔피언 결과 목록

목록 카드에 표시할 정보:

- 챔피언 이미지와 한글 이름
- 실제 픽된 포지션 배지와 포지션별 픽 수
- 전체 픽 수와 전체 밴 수
- 전체 픽밴률
- 선택 포지션이 있으면 해당 포지션의 승–패와 승률
- 표본 경고

포지션 필터가 `전체`일 때 승률은 모든 실제 픽 포지션을 합친 수치다. 특정 포지션을 선택하면 픽 수와 승률만 해당 포지션으로 바뀌고 밴 수는 `전체 밴`으로 명시한다.

데스크톱은 4~6열 카드 그리드, 태블릿은 3열, 모바일은 이미지와 핵심 수치를 가로로 배치한 단일 열 목록을 사용한다. 모바일에서 작은 정사각형 카드 여러 열로 이름과 표본을 숨기지 않는다.

### 6.2 상세 페이지 챔피언 전환기

- 데스크톱: 페이지 제목 오른쪽에 검색 가능한 combobox 버튼
- 모바일: 제목 오른쪽 `챔피언 변경` 아이콘 버튼을 누르면 전체 화면에 가까운 bottom sheet
- 한글명, 영문 Data Dragon ID, slug로 검색
- 최근 선택 5개를 로컬에만 저장해 상단에 표시
- 키보드 방향키, Enter, Escape 지원

챔피언을 바꿀 때 시즌·대회·패치 범위는 유지한다. 현재 선택한 포지션에 새 챔피언의 픽 기록이 없으면 해당 범위에서 가장 많이 픽된 포지션으로 이동하고 `선택한 포지션 기록이 없어 주 포지션으로 변경했습니다` 안내를 한 번 표시한다. 선택한 범위 자체에 기록이 없다면 범위를 자동으로 넓히지 않고 빈 상태를 보여준다.

## 7. 상세 페이지 전체 배치

### 7.1 공통 순서

```text
브레드크럼 / 페이지 제목 / 챔피언 전환기
시즌·대회·패치 범위 필터
챔피언 요약 헤더
포지션 선택기
콘텐츠 탭
선택 탭 콘텐츠
집계 기준·데이터 커버리지 안내
```

필터가 바뀌면 챔피언 요약, 포지션 픽 수, 모든 탭 통계를 같은 범위로 다시 계산한다.

### 7.2 범위 필터

데스크톱:

- 한 줄의 `SurfacePanel` 안에 시즌 select, 대회 구간 select, 세부 대회 select, 패치 select, 적용 버튼을 배치한다.
- 세부 대회가 하나뿐이면 select를 숨기지 않고 비활성화해 현재 범위를 알 수 있게 한다.
- 적용 전과 적용 후 상태가 구분되도록 URL 이동 방식의 form을 사용한다.

모바일:

- `2026 전체 · 모든 패치` 형태의 범위 요약 버튼 하나를 표시한다.
- 버튼을 누르면 bottom sheet에서 시즌, 대회 구간, 세부 대회, 패치를 고른다.
- 하단 고정 영역에 `초기화`, `적용` 버튼을 둔다.
- 선택 결과 수를 알 수 있으면 `128세트 보기`로 표시한다.

패치는 단일 선택을 기본으로 한다. 여러 패치를 비교하려면 `전체 패치`를 사용하고 패치별 추이 영역에서 비교한다. 임의의 여러 패치 multi-select는 URL과 캐시 조합을 불필요하게 복잡하게 만들므로 제공하지 않는다.

### 7.3 챔피언 요약 헤더

왼쪽:

- 챔피언 정사각형 이미지
- 챔피언 한글 이름
- 현재 범위에서 실제 픽된 포지션과 픽 수
- 범위 문구: `2026 LCK · 전체 패치 · 픽밴 완전 세트 128`

오른쪽 핵심 수치:

- 전체 픽
- 전체 밴
- 전체 픽밴률
- 실제 픽 기준 전체 승–패와 승률

이 영역은 전체 포지션 지표다. 아래 포지션 탭이 바뀌어도 전체 밴과 전체 픽밴률은 변하지 않는다. 대신 선택 포지션의 기록은 포지션 선택기 바로 아래에 별도 요약한다.

큰 배경 splash 이미지는 사용하지 않는다. 현재 프로젝트가 안정적으로 보유한 정사각형 챔피언 이미지를 사용하고, 통계 가독성을 우선한다.

### 7.4 포지션 선택기

- 순서: `TOP`, `JGL`, `MID`, `BOT`, `SUP`
- 각 항목에 픽 수 표시: `BOT 24`
- 0픽 포지션도 숨기지 않고 `MID 0`으로 비활성 표시
- 기본 포지션은 현재 필터 범위에서 픽 수가 가장 많은 포지션
- 동률이면 `TOP → JGL → MID → BOT → SUP` 순서
- 포지션 변경 시 `position` 쿼리를 갱신하고 현재 콘텐츠 탭을 최대한 유지한다.
- `duos` 탭에서 TOP/JGL/MID로 바꾸면 `overview`로 이동한다.

선택 포지션 요약:

- 픽 수
- 승–패와 승률
- 해당 챔피언 전체 픽 중 포지션 비중
- 포지션별 핵심 경기 지표 4개

### 7.5 콘텐츠 탭

기본 탭:

- `종합`
- `상대 전적`
- `선수·세팅`
- `경기 기록`

BOT 또는 SUP 선택 시 `상대 전적` 다음에 `바텀 조합`을 추가한다.

탭은 URL 링크로 동작하며 새로고침과 공유가 가능해야 한다. 모바일에서 한 줄 가로 스크롤을 허용하되 활성 탭이 자동으로 보이는 위치에 오도록 한다.

## 8. 포지션별 지표

모든 포지션에 동일한 숫자를 억지로 배치하지 않는다. 현재 데이터로 설명력이 있는 지표를 사용한다.

| 포지션 | 기본 지표 |
| --- | --- |
| TOP | KDA, DPM, GD@15, CSD@15 |
| JGL | KDA, DPM, GD@15, XPD@15 |
| MID | KDA, DPM, GD@15, CSD@15 |
| BOT | KDA, DPM, GD@15, CSD@15 |
| SUP | KDA, VSPM, XPD@15, 평균 와드 설치 |

공통 규칙:

- 평균은 해당 값이 존재하는 경기만 분모로 사용한다.
- `GD@15`, `CSD@15`, `XPD@15`에는 양수 `+` 기호를 표시한다.
- 지표명 tooltip에 계산 기준을 제공한다.
- 포지션 간 레이더 차트나 임의의 100점 환산 점수는 만들지 않는다.

## 9. 탭별 상세 명세

### 9.1 종합

배치 순서:

1. 선택 포지션 기록 카드
2. 패치별 픽·승률 추이
3. 진영별 성적
4. 드래프트 우선순위
5. 많이 만난 상대 TOP 5
6. 많이 사용한 선수 TOP 5
7. BOT/SUP이면 많이 사용한 바텀 파트너 TOP 5

#### 패치별 추이

- X축: 정규화된 패치
- 막대: 픽 수
- 선 또는 점: 승률
- 승률 점에는 경기 수 tooltip 제공
- 0픽 패치는 표시하지 않는다.
- 패치가 1개뿐이면 차트 대신 단일 패치 요약 카드를 표시한다.

#### 진영별 성적

- 블루: 픽 수, 승–패, 승률
- 레드: 픽 수, 승–패, 승률
- 픽 수가 적은 쪽은 표본 경고

#### 드래프트 우선순위

현재 `set_picks_bans.phase`와 `order_index`를 사용한다.

- 1차 픽 단계와 2차 픽 단계 사용 비중
- 실제 선택 슬롯 분포
- 1차 밴과 2차 밴 비중
- 블루/레드 진영 분리 toggle

밴 단계는 전체 챔피언 기준이며 선택 포지션에 귀속하지 않는다.

### 9.2 상대 전적

상단 컨트롤:

- 정렬: `많이 만난 순`, `승률 높은 순`, `승률 낮은 순`, `GD@15 높은 순`, `GD@15 낮은 순`
- 최소 표본: `전체`, `3경기 이상`, `5경기 이상`
- 상대 챔피언 이름 검색

데스크톱 표:

| 열 | 내용 |
| --- | --- |
| 상대 | 이미지, 챔피언 이름 |
| 경기 | 실제 맞대결 세트 수 |
| 전적 | 승–패 |
| 승률 | 선택 챔피언 팀의 승률 |
| GD@15 | 선택 챔피언 선수의 평균 값 |
| XPD@15 | 선택 챔피언 선수의 평균 값 |
| CSD@15 | 선택 챔피언 선수의 평균 값 |
| 최근 | 최근 5경기 W/L |

모바일은 상대 챔피언별 카드로 바꾸고 첫 줄에 상대·전적·승률, 두 번째 줄에 15분 지표를 배치한다.

행을 누르면 펼침 영역 또는 모바일 상세 sheet에서 다음을 보여준다.

- 양쪽 챔피언과 전적
- 실제 경기 목록
- 선수, 팀, 대회, 패치
- 세트 상세 링크

빈 상태 문구: `선택한 범위와 포지션에서 집계 가능한 상대 전적이 없습니다.`

### 9.3 바텀 조합

BOT 선택 시 파트너 SUP 챔피언을, SUP 선택 시 파트너 BOT 챔피언을 보여준다.

상단 컨트롤:

- 파트너 챔피언 검색
- 정렬: `많이 함께한 순`, `승률 높은 순`, `승률 낮은 순`, `듀오 GD@15 높은 순`
- 최소 표본: `전체`, `3경기 이상`, `5경기 이상`

기본 행/카드:

- 선택 챔피언 + 파트너 챔피언 이미지
- 실제 동시 출전 경기 수
- 승–패와 승률
- 두 선수의 `gold_diff_at_15` 합계 평균인 듀오 GD@15
- 함께 사용한 선수 조합 상위 3개
- 표본 경고

`듀오 GD@15`는 두 포지션 값이 모두 존재하는 경기만 계산하고 커버리지를 tooltip에 표시한다.

파트너 행을 선택하면 실제 상대 바텀 조합을 보여준다.

| 열 | 내용 |
| --- | --- |
| 상대 BOT | 챔피언 |
| 상대 SUP | 챔피언 |
| 경기 | 네 챔피언 조합이 동시에 성립한 세트 수 |
| 전적 | 선택 듀오 기준 승–패 |
| 승률 | 선택 듀오 기준 |
| 최근 경기 | 세트 링크 |

이 2단계 상세에서도 개별 챔피언 승률을 섞지 않고 네 챔피언이 실제로 함께 등장한 세트만 사용한다.

### 9.4 선수·세팅

다음 네 영역으로 구성한다.

1. 사용 선수
2. 핵심 룬·보조 계열
3. 소환사 주문 조합
4. 종료 아이템

#### 사용 선수

| 열 | 내용 |
| --- | --- |
| 선수 | 이름, 현재 팀 또는 경기 당시 팀 |
| 경기 | 선택 챔피언·포지션 사용 세트 수 |
| 전적 | 승–패 |
| 승률 | 실제 사용 경기 기준 |
| KDA | 해당 경기 합산 기준 |
| DPM | 값이 있는 경기 평균 |
| GD@15 | 값이 있는 경기 평균 |
| 최근 사용 | 마지막 경기 날짜 |

기본 정렬은 경기 수다. 현재 선수 소속과 경기 당시 `team_id`가 다를 수 있으므로 통계 행에서는 경기 당시 팀을 기준으로 한다.

#### 핵심 룬·보조 계열

- 핵심 룬별 경기 수와 선택률
- 핵심 룬 + 보조 계열의 실제 동시 선택 조합
- 각 조합의 경기 수와 승–패
- 룬 데이터 커버리지

`rune1`은 보조 계열 ID이므로 일반 룬 아이콘처럼 표현하지 않고 계열 이름과 아이콘을 사용한다.

#### 소환사 주문

- 두 주문을 순서와 무관한 한 조합으로 정규화한다.
- 실제 조합별 경기 수와 선택률을 표시한다.
- 데이터가 없는 경기는 분모에서 제외한다.

#### 종료 아이템

세 영역으로 나눈다.

- 자주 보유한 완성 아이템
- 신발 선택
- 실제 종료 아이템 조합

처리 규칙:

- 장신구와 `role_bound_item`은 일반 완성 아이템 집계에서 분리한다.
- 동일 아이템을 한 경기에서 여러 칸에 보유해도 아이템 선택 경기 수는 한 번만 센다.
- 아이템 선택률 분모는 아이템 기록이 하나 이상 있는 경기다.
- 종료 아이템 조합은 아이템 ID를 정렬한 집합으로 만들되 신발 포함 여부를 명시한다.
- 원본 슬롯 순서를 구매 순서로 해석하지 않는다.
- 섹션 제목과 설명에 `경기 종료 시점 보유 아이템이며 구매 순서가 아닙니다.`를 표시한다.

### 9.5 경기 기록

기본 정렬은 최신 경기순이다.

데스크톱 표:

| 열 | 내용 |
| --- | --- |
| 날짜 | KST 기준 경기 날짜 |
| 대회 | 대회명 |
| 패치 | 세트 패치 |
| 선수·팀 | 해당 챔피언 사용자와 당시 팀 |
| 상대 | 같은 포지션 상대 챔피언과 선수 |
| 진영 | 블루/레드 |
| 결과 | W/L |
| KDA | 킬/데스/어시스트 |
| 지표 | 포지션별 대표 지표 |

모바일은 경기별 카드로 표시한다. 행 또는 카드를 누르면 기존 `/matches/[matchId]/sets/[setId]`로 이동한다.

페이지네이션은 `(match_date, set_id)` 커서를 사용하는 더 보기 방식으로 구현한다. 깊은 `OFFSET` 페이지네이션을 사용하지 않는다.

## 10. 집계 대상 세트와 데이터 완전성

### 10.1 결과 집계 가능 세트

다음 조건을 모두 만족해야 승–패 집계에 포함한다.

- 선택한 시즌·대회·패치 범위에 속함
- `winner_team_id`가 존재함
- 해당 챔피언의 `set_player_stats` 행에 `team_id`, `position`, `champion_id`가 존재함

### 10.2 픽밴 집계 가능 세트

- 해당 세트에 양 팀 픽 10개가 존재함
- 현재 10밴 규칙 대회에서는 밴 10개가 존재함
- 불완전한 세트는 픽률·밴률·픽밴률 분모에서 제외함
- 불완전한 픽밴 세트 수는 페이지 하단 데이터 안내에 표시함

현재 서비스가 2026 대회를 대상으로 하므로 10픽·10밴 검증을 사용한다. 다른 규칙의 과거 시즌을 적재할 때는 대회별 기대 밴 수를 별도 정의하기 전까지 자동 포함하지 않는다.

### 10.3 세팅 데이터 커버리지

영역별로 다음 형식의 안내를 표시한다.

```text
핵심 룬 기록 18/24경기 · 소환사 주문 21/24경기 · 종료 아이템 17/24경기
```

커버리지가 50% 미만이면 영역 상단에 `일부 경기만 기록됨` 경고를 표시한다. 0이면 차트를 숨기고 정확한 빈 상태를 표시한다.

## 11. 데이터 조회 구조

### 11.1 원천 테이블

```text
tournaments
  └─ matches
      └─ sets
          ├─ set_picks_bans
          └─ set_player_stats
               ├─ 같은 set + 반대 team + 같은 position → 상대 전적
               └─ 같은 set + 같은 team + BOT/SUP → 바텀 듀오
```

원천 데이터는 기존 테이블을 사용한다. 새로운 외부 데이터 소스를 전제하지 않는다.

### 11.2 서버 조회 경계

브라우저에서 수만 행을 내려받아 집계하지 않는다. Next.js 서버 계층 또는 Postgres의 `SECURITY INVOKER` SQL 함수에서 집계한다.

권장 조회 단위:

- 챔피언 목록 요약
- 챔피언 전체·포지션 요약
- 상대 전적
- 바텀 듀오와 상대 듀오
- 선수·세팅
- 경기 기록 페이지

탭별 데이터를 분리해 첫 화면에서 사용하지 않는 전체 경기 기록까지 한 번에 조회하지 않는다. 서버 컴포넌트는 현재 탭에 필요한 데이터만 요청한다.

### 11.3 권장 함수 계약

```text
get_champion_directory(scope, position, sort)
get_champion_summary(champion_id, scope, position)
get_champion_matchups(champion_id, scope, position, min_games, sort)
get_champion_bot_duos(champion_id, scope, position, min_games, sort)
get_champion_pro_preferences(champion_id, scope, position)
get_champion_games(champion_id, scope, position, cursor, limit)
```

`scope`는 서버 내부에서 다음 값으로 풀어낸다.

```text
season
segment
tournament_id | all
patch | all
eligible tournament_ids
eligible match_ids
eligible set_ids
```

### 11.4 인덱스

실제 쿼리를 작성한 뒤 `EXPLAIN (ANALYZE, BUFFERS)`로 확인하고 다음 복합 인덱스를 우선 검토한다.

```sql
create index on public.set_player_stats
  (champion_id, position, set_id, team_id);

create index on public.set_player_stats
  (set_id, team_id, position)
  include (champion_id, player_id);

create index on public.set_picks_bans
  (champion_id, action_type, set_id)
  include (phase, order_index, side, team_id);

create index on public.sets
  (match_id, patch)
  include (winner_team_id, blue_team_id, red_team_id);
```

기존 단일 인덱스와 실제 실행 계획이 충분하면 중복 인덱스를 만들지 않는다.

### 11.5 Supabase 공개 접근

- 공개 통계 조회 함수와 view는 `SECURITY INVOKER`를 사용한다.
- `SECURITY DEFINER`로 RLS를 우회하지 않는다.
- 새 public 테이블을 만들 경우 RLS를 활성화하고 `anon`, `authenticated`에 필요한 `SELECT`만 명시적으로 부여한다.
- 브라우저에 `service_role` 키를 노출하지 않는다.
- 통계 원천은 공개 대회 데이터이며 사용자별 쓰기 정책은 만들지 않는다.

## 12. 캐시와 갱신

- 시즌·대회·패치·챔피언·포지션·탭을 캐시 키에 포함한다.
- 경기 또는 세트 데이터 동기화 완료 후 `champions`, `champion:{id}`, `tournament:{id}` 태그를 무효화한다.
- 빈 결과도 짧게 캐시해 반복적인 동일 쿼리를 막는다.
- Data Dragon 카탈로그는 버전별 캐시를 유지한다.
- 현재 데이터 규모에서는 먼저 올바른 복합 인덱스와 서버 캐시를 사용한다.
- 실행 계획이 충분한데도 느릴 때만 원자 건수 기반 materialized view를 도입한다.
- 캐시나 view에는 백분율이 아니라 합산 가능한 건수를 저장한다.

## 14. 반응형 배치

### 14.1 데스크톱 `>= 1200px`

- `layout-wide-max` 사용
- 범위 필터 한 줄
- 챔피언 요약은 이미지/정보와 핵심 수치의 2열
- 종합 탭의 보조 영역은 최대 2열
- 상대 전적·선수·경기 기록은 표
- 콘텐츠 최대 폭을 지나치게 넓히지 않고 숫자 열은 우측 정렬

### 14.2 태블릿 `768px~1199px`

- 범위 필터 2행 허용
- 챔피언 요약 1~2열 자동 전환
- 표는 핵심 열만 유지하고 보조 열은 행 펼침 영역으로 이동
- 포지션과 콘텐츠 탭은 가로 스크롤 가능

### 14.3 모바일 `< 768px`

- 좌우 여백 16~20px
- 범위 필터는 요약 버튼 + bottom sheet
- 챔피언 요약은 이미지와 이름을 한 줄, 핵심 수치는 2×2 grid
- 포지션 선택기는 가로 스크롤
- 콘텐츠 탭은 sticky가 가능하되 앱 헤더와 겹치지 않음
- 데이터 표 대신 카드
- 카드 첫 화면에 상대/파트너, 경기 수, 전적, 승률을 반드시 표시
- 추가 지표는 두 번째 행 또는 펼침 영역
- 가로 스크롤 표를 기본 해법으로 사용하지 않음

## 16. 로딩·빈 상태·오류 상태

### 16.1 로딩

- 챔피언 목록 전용 스켈레톤
- 챔피언 상세 전용 스켈레톤
- 상세 스켈레톤은 요약 헤더, 포지션 탭, 현재 콘텐츠 탭 구조를 그대로 반영
- 탭 변경 시 페이지 전체를 덮지 않고 콘텐츠 영역만 로딩
- 이미지 로딩이 페이지 전환 완료를 막지 않음

### 16.2 빈 상태

빈 상태는 이유를 구분한다.

- 챔피언 자체가 없음: 404
- 선택 범위에 픽·밴 모두 없음: `선택한 대회 범위에서 이 챔피언의 기록이 없습니다.`
- 밴만 있고 픽이 없음: 전체 밴 지표는 보여주고 포지션 탭은 모두 0으로 표시
- 선택 포지션에 픽이 없음: `이 포지션으로 출전한 기록이 없습니다.`
- 룬만 없음: 다른 통계는 유지하고 룬 영역만 빈 상태
- 종료 아이템만 없음: 다른 세팅은 유지하고 아이템 영역만 빈 상태
- 상대 전적 없음: 해당 탭에만 빈 상태
- 바텀 파트너 없음: 해당 탭에만 빈 상태

빈 상태에는 가능한 경우 `전체 대회로 보기`, `모든 패치로 보기`, `주 포지션 보기` 동작을 제공한다. 사용자의 필터를 자동 변경하지 않는다.

### 16.3 오류

- 한 탭 조회 실패가 페이지 전체 500으로 이어지지 않도록 영역 오류 경계를 둔다.
- 오류 문구에 내부 DB 메시지나 원천 URL을 노출하지 않는다.
- 재시도는 현재 URL과 필터를 유지한다.

## 17. 접근성

- 챔피언 전환기는 `combobox`, 결과는 `listbox` 패턴 사용
- 모든 select와 filter sheet 그룹에 보이는 label 제공
- 탭에 `aria-current` 또는 올바른 tab semantics 제공
- 비활성 포지션에 `0경기` 이유 제공
- 차트 정보는 표 또는 텍스트 요약으로도 접근 가능
- tooltip에만 핵심 정보를 두지 않음
- 터치 대상 최소 44×44px
- 키보드만으로 챔피언 변경, 범위 필터, 탭 이동, 행 열기 가능
- 다크모드에서 텍스트·테두리 대비 확인

## 18. SEO와 공유

## 19. 검증 항목

### 19.1 집계 단위 테스트

- 승률이 `wins / games`로 계산됨
- 패치 또는 대회별 승률을 단순 평균하지 않음
- 밴을 포지션에 귀속하지 않음
- 상대 전적이 같은 세트·같은 포지션·반대 팀만 연결함
- BOT/SUP 듀오가 같은 세트·같은 팀만 연결함
- 상대 바텀 조합이 네 챔피언 모두 실제 등장한 세트만 포함함
- 누락된 15분 지표를 0으로 평균 내지 않음
- 룬·주문·아이템 선택률의 분모가 각 데이터 보유 경기 수임
- 동일 아이템 중복 보유를 선택 경기 수에서 한 번만 계산함
- 아이템 슬롯 순서를 구매 순서로 사용하지 않음
- 픽밴 불완전 세트를 픽밴률 분모에서 제외함

### 19.2 화면 테스트

- 목록 검색과 필터 조합
- 상세 챔피언 전환 시 범위 유지
- 없는 포지션으로 전환 시 처리
- BOT/SUP에서만 바텀 조합 탭 노출
- URL 직접 진입과 새로고침 상태 복원
- 뒤로 가기 시 필터와 스크롤 복원
- 데스크톱 표와 모바일 카드 수치 일치
- 부분 데이터 커버리지 표시
- 빈 상태별 복구 동작
- 라이트·다크 모드
- 390×844, 768px, 1280px 이상 레이아웃
- 키보드 탐색과 스크린리더 label

### 19.3 데이터 검증

- `set_player_stats`의 세트·선수 중복 여부
- 완료 세트의 선수 행 수
- 픽밴 완전 세트의 10픽·10밴 여부
- 선수 통계 픽과 `set_picks_bans` 픽의 챔피언 일치 여부
- 세트 winner가 참가 두 팀 중 하나인지
- BOT과 SUP이 한 팀에 각각 하나씩 존재하는지
- 패치 값 정규화 여부
- Data Dragon 챔피언·룬·주문·아이템 ID 해석 성공률

## 20. 성능 완료 기준

- 초기 페이지가 브라우저로 전체 `set_player_stats` 또는 `set_picks_bans` 원본을 내려보내지 않음
