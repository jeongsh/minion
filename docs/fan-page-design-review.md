# 팬페이지 하위 영역 디자인 컨펌

작성일: 2026-07-11  
검토 범위: `/fan/[teamSlug]` 홈과 일정, 선수, 커뮤니티, 비난양파, 소셜, 영상 화면  
검토 방식: 현재 소스, 실제 `/fan/t1` 계열 라우트 렌더링, 첨부 화면 비교

## 1. 결론

전체 방향은 맞지만 아직 최종 디자인 컨펌 단계는 아니다.

팬 홈은 팀 컬러와 경기 중심 정보 구조를 사용해 스포츠 팬 허브의 성격이 분명하다. 반면 하위 화면은 일반 MINION 서브페이지, 인스타그램형 피드, 메신저형 양파 보드가 서로 다른 표면색과 제목 체계, 라운드 규칙을 사용한다. 현재 완성도는 약 75%로 판단한다.

레이아웃을 전면 재설계할 필요는 없다. 색상 토큰, 페이지 제목, 카드 표면, 버튼과 라운드 규칙을 먼저 통일하는 보존형 정리가 적절하다.

디자인 기준은 다음과 같이 본다.

- 디자인 변주: 5/10
- 모션 강도: 3/10
- 정보 밀도: 6/10
- 방향: 팀 브랜드가 들어간 MINION 정보형 팬 허브
- 원칙: 메인 서비스의 중성 UI 위에 팀 컬러만 명확하게 얹는다

## 2. 첨부 화면의 이상한 회색

### 현상

첨부된 소셜 게시물 카드에서 이미지 아래 계정, 시간, 캡션 영역이 푸른 회색 띠처럼 보인다. 이미지가 밝은 핑크색이고 주변 페이지가 흰색이라 회색 패널이 더 강하게 튄다. 게시물 내용 영역이 비활성 상태나 입력 불가 영역처럼 읽히며, 카드가 이미지와 설명으로 자연스럽게 이어지지 않는다.

### 원인

`components/fan/fan-instagram-feed.tsx`의 일반 게시물 카드가 카드 전체에 `bg-surface-muted`를 사용한다.

- 카드 외곽: `bg-surface-muted` 사용, 213줄
- 이미지 영역: `bg-surface-muted` 사용, 215줄
- 설명 영역: 별도 표면색이 없어 부모의 muted 배경을 그대로 상속, 236줄

라이트 모드에서 `surface-muted`는 푸른 기가 있는 회색 계열이다. 이 토큰은 빈 상태, 플레이스홀더, 보조 구역, hover 배경에는 적절하지만 실제 콘텐츠 카드의 기본 표면에는 적절하지 않다.

### 수정 기준

- 게시물 카드 기본 배경: `bg-[var(--ui-surface)]`
- 이미지 fallback에만: `bg-[var(--ui-surface-muted)]`
- 설명 패널: `bg-[var(--ui-surface)]`
- 이미지와 설명 사이: 필요하면 `border-t border-[var(--ui-border)]`
- 카드 외곽선: `border-[var(--ui-border)]`
- hover: 배경 전체를 회색으로 바꾸지 말고 border 또는 이미지 scale만 사용

### 같은 계열로 함께 점검할 회색

| 위치 | 현재 표현 | 판단 | 권장 처리 |
| --- | --- | --- | --- |
| 소셜 게시물 카드 | `bg-surface-muted` | 실제 콘텐츠가 비활성 영역처럼 보임 | 기본 surface로 변경 |
| 선수 프로필 카드 | `bg-surface-muted`, `#eef1f6` | 이미지 fallback에는 적절, 카드 전체에는 과함 | 카드와 정보 영역은 surface |
| 영상 빈 상태 | `#e5e5e5`, `#f2f2f2` | 빈 상태이므로 회색 사용 가능 | UI 토큰으로 치환 |
| 피드 광고·빈 상태 | `#f9fafb` | 역할상 회색 사용 가능 | `--ui-surface-muted`로 통일 |
| 비난양파 배경 | `#f4f2ee` | 따뜻한 베이지가 전체 중성 팔레트와 분리됨 | 중성 surface-muted 또는 team soft accent |
| 팬온도 보조 지표 | `--ui-surface-muted` | 정보 그룹 구분 역할이 명확함 | 유지 가능 |

회색 자체를 없애는 것이 목표는 아니다. 회색의 역할을 빈 상태, 보조 정보, hover, 입력 배경으로 제한해야 한다. 실제 콘텐츠 본문과 카드 기본 표면은 흰색 또는 `--ui-surface`가 기준이다.

## 3. 우선순위별 디자인 이슈

### P1. 팀 컬러 대비 체계가 없다

`components/fan/fan-site-layout.tsx`는 `--team-primary`, `--team-secondary`만 제공한다. 헤더와 액션은 모든 팀 컬러 위에 흰색 전경을 고정 사용한다.

흰색과 팀 기본색의 대비율 예시는 다음과 같다.

| 팀 | 흰색 대비율 | 작은 텍스트 판단 |
| --- | ---: | --- |
| T1 | 4.85:1 | 통과 |
| GEN | 3.31:1 | 미달 |
| HLE | 2.88:1 | 미달 |
| DK | 2.87:1 | 미달 |
| KT | 4.38:1 | 근소 미달 |
| DRX | 3.51:1 | 미달 |
| NS | 5.19:1 | 통과 |
| BRO | 2.56:1 | 미달 |
| FOX | 3.39:1 | 미달 |
| SOOP | 3.68:1 | 미달 |

헤더의 `text-white/80`, `text-white/85`는 실제 대비를 더 낮춘다. 활성 탭에서 팀 컬러를 작은 글자색으로 사용하는 경우도 라이트 모드에서 같은 문제가 발생한다.

필요한 토큰:

```css
--team-primary;
--team-secondary;
--team-on-primary;
--team-accent-text;
--team-accent-soft;
```

`--team-on-primary`는 헤더와 채워진 버튼 전경에 사용한다. `--team-accent-text`는 흰 배경 위의 활성 탭, 링크, 작은 라벨에 사용한다. 두 토큰은 같은 값으로 처리하면 안 된다.

### P1. 팬온도에 고정 주황색이 섞인다

`components/fan/fan-temperature-card.tsx`의 진행 표시가 팀 컬러에서 `#ff6b35`로 이어진다. T1에는 자연스럽지만 DK, GEN, DRX, SOOP에서는 별도 캠페인 색상처럼 보인다.

권장 기준:

- 팀 컬러 단색 진행 표시
- 또는 팀 컬러와 같은 hue의 밝기 차이만 사용
- 상태 라벨과 액션 버튼도 `--team-on-primary` 적용
- 고정 주황색은 실제 온도 경고 상태에만 제한

### P1. 비난양파가 별도 메신저 제품처럼 보인다

`components/fan/fan-onion-board.tsx`는 `#f4f2ee` 배경과 흰색 말풍선을 사용한다. 팬 홈의 차가운 중성 회색 계열과 다르고 팀 컬러 연결도 전송 버튼에만 나타난다.

권장 기준:

- 보드 배경: `--ui-surface-muted`
- 말풍선: `--ui-surface`
- 선택된 유지 시간 또는 입력 focus: `--team-accent-text`
- 팀 특화 표현이 필요하면 `--team-accent-soft`를 약하게 사용

### P2. 하위 페이지 제목 체계가 서로 다르다

현재 렌더링 기준:

| 화면 | 최상위 제목 상태 |
| --- | --- |
| 커뮤니티 | 32px 페이지 제목 |
| 비난양파 | 20px 제목 |
| 일정 | 페이지 제목 없이 18px 날짜 제목부터 시작 |
| 선수 | 페이지 제목 없이 선수 카드부터 시작 |
| 소셜 | 페이지 제목 없이 필터부터 시작 |
| 영상 | 페이지 제목 없이 15px 영상 제목만 존재 |

공통 `FanSubpageHeader`가 필요하다.

- 페이지 제목: 32px
- 섹션 제목: 20px 또는 24px
- 카드 제목: 15px 또는 16px
- 메타 정보: 12px
- 제목 글꼴: 기존 `home-section-title` 계열 유지
- 영문 eyebrow는 필요한 화면에만 제한

### P2. 디자인 토큰을 하드코딩 색상이 우회한다

팬 컴포넌트에 `#0f0f0f`, `#606060`, `#e5e5e5`, `#e6e9ef`, `#f9fafb` 같은 별도 회색이 남아 있다. 다크 모드는 `app/globals.css`의 광범위한 클래스 선택자로 이를 덮어쓴다.

이 방식은 새 하드코딩 색상이 추가될 때마다 전역 예외를 늘려야 한다. 팬 컴포넌트에서 의미 기반 토큰을 직접 사용해야 한다.

| 목적 | 사용할 토큰 |
| --- | --- |
| 기본 배경 | `--ui-surface` |
| 보조·빈 상태 배경 | `--ui-surface-muted` |
| 기본 제목 | `--ui-ink` |
| 본문 | `--ui-text` |
| 메타·보조 텍스트 | `--ui-muted` |
| 카드 경계 | `--ui-border` |
| 팀 강조 | `--team-accent-text` |

### P2. 카드 라운드와 버튼 문법이 정리되지 않았다

현재 주요 라운드는 6px, 12px, 16px, 24px, pill이 혼재한다.

권장 규칙:

- 일반 카드: 16px
- 미디어 썸네일: 12px 또는 16px 중 하나로 통일
- 입력과 일반 버튼: 8px
- 팬 액션, 필터, 탭: pill
- 모달: 16px

팬 전용 pill 액션은 모두 공용 `Button`으로 강제하기보다 공용 버튼 시스템에 `fanAction` 변형을 추가하는 편이 적절하다. 탭, 미디어 오버레이, 아이콘 컨트롤은 특수 컴포넌트로 유지한다.

### P2. 키보드 포커스 표현이 없다

팬 컴포넌트에는 명시적인 `focus-visible` 스타일이 거의 없다. 비난양파의 select와 textarea는 `outline-none`을 사용한다.

권장 기준:

```text
focus-visible:ring-2
focus-visible:ring-[var(--team-accent-text)]
focus-visible:ring-offset-2
```

링 색상이 배경과 충분한 대비를 갖도록 라이트와 다크 모드에서 각각 확인해야 한다.

## 4. UI 자체 구성 점검

색상과 토큰을 제외하고 컴포넌트의 정보 구조, 배치, 반응형 동작 자체가 어색한 부분을 정리한다.

### P1. 팬온도는 숫자의 의미가 바로 이해되지 않는다

현재 팬온도 카드는 큰 숫자, 진행 막대, 상태 라벨, `온도 올리기` 버튼, 4개의 지표를 한 카드에 배치한다. 시각적으로는 완성된 대시보드 카드처럼 보이지만 핵심 수치가 무엇인지 설명하는 정보가 부족하다.

문제점:

- 큰 숫자 `0`에 단위나 범위가 없다. 온도인지 점수인지 바로 알 수 없다.
- 진행 막대에 0과 100, 상태 구간, 현재 위치에 대한 기준이 없다.
- 점수가 0이면 채워진 부분이 완전히 사라져 로딩 실패나 데이터 누락처럼 보일 수 있다.
- `열기`, `양파`, `출석`은 24시간 또는 오늘 지표지만 `팬`은 누적 지표다. 서로 다른 시간 범위가 같은 그룹에 섞여 있다.
- 모바일에서는 `팬` 지표만 `hidden md:block`으로 숨겨져 데스크톱과 정보가 달라진다.
- `Fan Temperature`와 `T1 팬온도`가 같은 의미를 반복한다.
- `온도 올리기`는 클릭 결과, 제한, 반영 시점이 보이지 않아 단순 클릭 게임처럼 느껴질 수 있다.
- 지표 아이콘의 `bg-white`는 다크 모드에서 밝은 원으로 튈 수 있다.

권장 구조:

```text
T1 팬온도                         차분함
0 / 100
[현재 위치가 항상 보이는 진행 표시]
최근 24시간 팬 반응을 종합한 점수

[열기 0] [양파 0] [출석 0]
누적 팬 2

[온도 올리기]
```

개선 기준:

- 큰 숫자를 `0 / 100` 또는 `0점`처럼 표시한다.
- 진행 표시가 0일 때도 시작점 marker가 보이게 한다.
- `열기·양파·출석`과 `누적 팬`을 시각적으로 분리한다.
- 모바일은 4개를 숨기지 말고 2x2 또는 3개 + 별도 한 줄로 표시한다.
- 버튼을 누른 뒤 `반영됨`, `오늘 참여 완료`, `다시 참여 가능 시간` 중 실제 상태를 보여준다.
- 영문 eyebrow는 제거하거나 `팬온도` 제목과 다른 정보를 제공할 때만 유지한다.
- 데이터가 모두 0일 때는 단순 0 나열보다 `아직 팬 반응이 쌓이지 않았어요`라는 초기 상태를 제공한다.

관련 위치:

- `components/fan/fan-temperature-card.tsx:41-94`
- `components/fan/fan-temperature-card.tsx:108-118`

### P1. 소셜 화면이 프로필 그리드와 콘텐츠 카드 사이에 걸쳐 있다

전체 소셜 화면은 3열 그리드에 간격이 없다. 각 항목은 정사각형 이미지 아래 84px 캡션 패널을 가진 카드다. 프로필형 이미지 그리드라면 캡션 패널이 없어야 하고, 콘텐츠 카드라면 카드 사이 간격과 라운드가 있어야 한다.

현재는 두 패턴이 섞여 다음과 같은 문제가 생긴다.

- 카드 경계가 서로 붙어 첨부 화면 오른쪽처럼 다음 카드의 일부가 끼어 보인다.
- 회색 캡션 띠가 행 전체에 반복되어 표 형태처럼 보인다.
- 이미지가 강한데 계정, 시간, 본문은 10-12px로 작아 정보 위계가 급격히 무너진다.
- hover에서 카드 전체가 이동하지만 카드 간격이 없어 인접 카드와 충돌해 보일 수 있다.

추천안은 캡션을 유지하는 카드형이다.

- 데스크톱 3열, 카드 간격 16px
- 카드 라운드 16px
- 이미지와 설명 영역 모두 `--ui-surface`
- 계정과 시간 12px, 캡션 13-14px
- hover는 border 강조와 이미지 scale만 사용
- 모바일 1열 또는 2열은 캡션 길이를 줄여 높이를 맞춘다

이미지만 빠르게 탐색하는 것이 목적이라면 반대로 캡션 패널을 제거하고 순수 정사각형 그리드로 가야 한다. 현재의 혼합형은 유지하지 않는 것이 좋다.

관련 위치:

- `components/fan/fan-instagram-feed.tsx:210-248`
- `components/fan/fan-instagram-feed.tsx:470-475`

### P1. 선수 화면은 5인 팀인데 5열 규칙이 없다

선수 화면은 공용 `.page-grid`를 사용한다. 이 그리드는 최소 폭 18rem 기준 auto-fit이라 1400px 콘텐츠에서도 일반적으로 4열 + 마지막 1장 또는 3열 + 2장 형태가 된다. 실제 T1의 5명 구성이 마지막 카드 한 장만 다음 행에 남을 수 있다.

또한 팬 홈의 선수 카드는 16px 라운드와 가로형 정보 카드인데, 선수 전체 화면은 6px 라운드의 일반 선수 카드여서 같은 선수단의 확장 화면처럼 보이지 않는다.

개선 기준:

- 주전 5명은 `xl:grid-cols-5`를 우선 사용한다.
- 후보와 코칭스태프가 있으면 별도 섹션으로 분리한다.
- 모바일 2열, 태블릿 3열, 데스크톱 5열로 명시한다.
- 팬 홈과 전체 선수 화면의 이미지 비율, 라운드, 포지션 라벨을 맞춘다.
- 선수가 없거나 로스터가 미완성일 때 빈 상태를 제공한다.

관련 위치:

- `app/fan/[teamSlug]/players/page.tsx:20-27`
- `app/globals.css:347-351`
- `components/domain/player-card.tsx:40-61`

### P2. 팬 헤더에 한 번에 너무 많은 행동이 있다

팬 헤더에는 팬 되기, 알람, 홈페이지, YouTube, X, Instagram, 승부예측이 동시에 노출된다. 데스크톱에서는 스포츠 포털의 풍부함으로 읽히지만 모바일에서는 여러 줄로 감기고 승부예측 카드까지 아래로 내려가 첫 화면이 액션으로 가득 찰 가능성이 높다.

개선 기준:

- 1차 행동: `팬 되기`
- 2차 행동: `알람`
- 외부 링크: `공식 채널` 메뉴 또는 아이콘 그룹으로 축약
- 승부예측은 헤더에서 유지하되 모바일에서는 요약형으로 축소
- 모바일의 팀명 VS 팀명은 크기를 낮추고 한 줄 scoreboard 형태로 고정
- 경기 정보가 없을 때 큰 VS 조형 대신 팀 소개형 fallback을 제공

관련 위치:

- `components/fan/fan-channel-header.tsx:52-64`
- `components/fan/fan-prediction-card.tsx:18-22`

### P2. 승부예측 카드의 100% 막대는 과장되어 보일 수 있다

참여자가 적거나 한쪽만 참여한 상태에서도 막대가 100%로 꽉 차 보인다. 숫자상 맞더라도 정보 신뢰도가 높아 보이는 착시가 생긴다. 참여 인원이 0일 때와 1-2명일 때를 동일한 완성형 비율 막대로 보여주지 않는 편이 좋다.

개선 기준:

- 참여가 적으면 `집계 중` 상태를 사용한다.
- 최소 표본 전에는 퍼센트보다 참여 수를 우선 표시한다.
- 0% 영역도 최소 시각 폭을 주거나 양쪽 팀 이름을 고정 배치한다.
- 예측 마감 상태를 큰 비활성 pill 하나로 끝내지 말고 결과 확인 경로를 함께 제공한다.

### P2. 일정 필터에서 고정된 팀이 비활성 버튼처럼 보인다

팬 일정 화면은 이미 T1 컨텍스트인데 팀 필터를 disabled dropdown으로 남긴다. 사용자는 비활성된 기능이나 로딩 중 컨트롤로 인식할 수 있다. 페이지 제목도 없어 필터가 화면의 첫 정보가 된다.

개선 기준:

- 잠긴 팀 dropdown은 제거한다.
- 필요하면 제목 또는 작은 context label에서 팀명을 표시한다.
- `T1 경기 일정` 페이지 제목을 먼저 제공한다.
- 초기화 링크는 실제 query가 기본값과 다를 때만 표시한다.
- 년, 월, 대회 필터는 하나의 compact toolbar로 묶는다.

관련 위치:

- `app/fan/[teamSlug]/matches/page.tsx:56-78`
- `app/schedule/schedule-filters.tsx:58-103`

### P2. 비난양파 입력부가 모바일에서 지나치게 압축된다

유지 시간 select, textarea, 글자 수, 전송 버튼이 한 줄에 모두 들어간다. 작은 화면에서는 실제 입력 폭이 크게 줄고 select의 의미도 처음 보는 사용자에게 명확하지 않다.

개선 기준:

- 모바일에서 유지 시간은 입력 위의 작은 설정 행로 분리한다.
- `10분`, `30분`처럼 값 옆에 의미를 명시한다.
- 빈 상태에 `작성한 양파는 선택한 시간 후 사라집니다` 설명을 제공한다.
- 입력 focus와 오류 상태를 시각적으로 표시한다.
- 전송 후 남은 시간과 삭제 정책을 즉시 확인할 수 있게 한다.

관련 위치:

- `components/fan/fan-onion-board.tsx:128-175`

### P2. 팬 탭은 가로 스크롤이 가능하지만 탐색 단서가 없다

7개 탭을 `overflow-x-auto`로 처리하지만 오른쪽에 더 많은 메뉴가 있다는 fade나 화살표가 없다. 현재 활성 탭이 뒤쪽에 있을 때 자동으로 화면 안에 들어오게 하는 처리도 보이지 않는다.

개선 기준:

- 좌우 끝에 약한 fade mask를 제공한다.
- route 변경 후 활성 탭을 `scrollIntoView`한다.
- 스크롤바 노출 여부를 서비스 전체 규칙과 맞춘다.
- 모바일에서 탭 간격을 28px보다 조금 줄여 첫 화면에 더 많은 항목을 보여준다.

관련 위치:

- `components/fan/fan-channel-navigation.tsx:20-44`

### P2. 영상 상세 화면에 내부 스크롤 영역이 두 개 생긴다

영상 상세는 데스크톱에서 전체 영역 높이를 `100vh - 130px`으로 고정하고 본문과 관련 영상에 각각 overflow를 적용한다. 페이지 자체 스크롤과 별개로 내부 스크롤이 생겨 휠 이동 위치를 예측하기 어렵다.

개선 기준:

- 본문은 일반 문서 스크롤을 사용한다.
- 관련 영상만 sticky sidebar로 유지한다.
- 높이를 viewport에 강제로 맞추지 않는다.
- 메타 설명의 회색 패널은 실제 보조 정보일 때만 유지한다.
- 영상 목록과 동일한 제목, 채널, 메타 타이포를 사용한다.

관련 위치:

- `app/fan/[teamSlug]/videos/[videoId]/page.tsx:72-140`

### P3. 커뮤니티만 완성된 페이지 헤더를 가지고 있다

커뮤니티는 32px 페이지 제목과 2열 콘텐츠 구조를 갖고 있어 일반 MINION 서브페이지와 가장 잘 연결된다. 반대로 선수, 일정, 소셜, 영상은 제목 없이 콘텐츠가 바로 시작된다. 커뮤니티를 기준으로 다른 하위 화면의 상단 구조를 맞추는 것이 좋다.

단, 모든 화면에 같은 영문 eyebrow를 반복할 필요는 없다. 제목과 짧은 설명 또는 액션만 일관되게 배치하면 충분하다.

## 8. 최종 컨펌 기준

- 실제 콘텐츠 카드의 기본 배경에 muted 회색이 사용되지 않는다.
- 회색은 빈 상태, fallback, hover, 입력과 보조 구역에만 사용한다.
- 모든 팀에서 헤더와 버튼 전경이 WCAG AA 대비를 만족한다.
- 활성 탭 팀 컬러가 라이트와 다크 모드 모두에서 읽힌다.
- 모든 팬 하위 화면에 동일한 페이지 제목 계층이 있다.
- 카드 라운드와 버튼 형태가 정의된 규칙 안에서만 사용된다.
- 팬온도와 비난양파가 같은 팬 허브의 기능으로 보인다.
- 팬온도 점수의 단위, 범위, 갱신 기준을 처음 보는 사용자도 이해할 수 있다.
- 팬온도의 모바일 화면에서도 데스크톱과 동일한 핵심 지표를 확인할 수 있다.
- 선수 5명이 마지막 한 장만 다음 행에 남지 않는다.
- 일정 화면에 disabled 팀 필터가 노출되지 않는다.
- 소셜 화면이 카드형 또는 이미지 그리드형 중 하나의 명확한 문법을 사용한다.
- 영상 상세에서 본문과 관련 영상이 서로 다른 내부 스크롤을 만들지 않는다.
- 소셜과 영상 화면이 외부 플랫폼 복제품이 아니라 MINION의 콘텐츠 화면으로 보인다.
- 키보드 포커스가 모든 인터랙션에서 명확하게 보인다.

## 9. 최종 판단

전체 컨셉과 정보 구조는 유지해도 된다. 가장 먼저 해결해야 할 시각적 이질감은 첨부 화면처럼 실제 콘텐츠 영역에 사용된 muted 회색과 팬온도·비난양파의 별도 팔레트다. UI 구조에서는 팬온도의 의미가 불분명한 점, 소셜 화면이 두 가지 카드 문법을 섞은 점, 선수 5인 배치와 일정의 disabled 팀 필터가 우선 개선 대상이다. 이 항목들과 공통 페이지 제목을 정리하면 팬페이지 전체가 하나의 제품군으로 인식될 가능성이 높다.
