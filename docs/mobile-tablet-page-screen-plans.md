> 작성일: 2026-07-14  
> 대상: `admin`, `records`를 제외한 공개 경로 39개  
> 성격: 반응형 수정 지침이 아니라 모바일·태블릿 제품의 신규 화면기획  
> 관련 기술 규격: `docs/mobile-tablet-responsive-rearchitecture.md`

---

## 0. 기획 전제

이 문서는 데스크톱 화면을 작은 폭에 재배치하는 문서가 아니다.

- 기존 PC 화면은 **데이터와 기능의 목록**으로만 참고한다.
- 기존 모바일 화면은 **개선안의 시각적 출발점으로 사용하지 않는다**.
- 모바일과 태블릿은 별도의 화면 목적, 내비게이션, 컴포넌트 트리를 가진다.
- PC에서 보이던 섹션을 모바일에 전부 세로 적층하지 않는다.
- 첫 화면은 페이지마다 한 가지 핵심 과업만 수행한다.
- 부가 정보는 상세 화면, 탭, 모달, 바텀시트, 아코디언으로 이동한다.
- 단순히 `hidden`, `grid-cols-1`, `flex-col`만 적용한 결과는 이 기획의 구현으로 인정하지 않는다.

## 0.1 기기 범위

| 모드 | 폭 | 제품 역할 |
|---|---:|---|
| Handset | 320~767px | 한 손 조작, 핵심 정보 1개, 짧은 탐색 흐름 |
| Tablet | 768~1199px | 터치 중심, master-detail, 2열 비교, 긴 읽기 |
| Desktop | 1200px 이상 | 현재 데스크톱 정보 밀도 유지, 이 문서의 주 설계 대상 아님 |

## 0.2 구현 원칙

```text
데이터 fetch / server action / route
               ↓ 재사용
모바일 화면 모델과 태블릿 화면 모델
               ↓ 별도 렌더링
HandsetScreen / TabletScreen / DesktopScreen
```

- `DesktopScreen`의 DOM을 CSS로 줄여 `HandsetScreen`을 만들지 않는다.
- 같은 데이터라도 기기별 view model에서 노출량과 우선순위를 바꾼다.
- 모바일 전용 컴포넌트가 필요하면 새 컴포넌트를 만든다.
- 데스크톱 전용 table, bracket, calendar는 모바일에서 다른 컴포넌트로 대체한다.

## 1. 공통 화면 셸

## 1.1 모바일 허브 셸

```text
┌──────────────────────────┐
│ 메뉴  MINION       검색 MY │ 56
├──────────────────────────┤
│                          │
│       현재 페이지         │
│                          │
├──────────────────────────┤
│ 홈  일정  예측  커뮤니티  MY │ 56 + safe area
└──────────────────────────┘
```

- 상단 app bar 56px.
- 하단 탭은 `홈 / 일정 / 예측 / 커뮤니티 / MY`.
- 대회, 팀, 선수, 리포트는 전체 메뉴와 홈의 빠른 이동에서 접근한다.
- 페이지 제목은 app bar에 넣거나 본문 상단에 넣는다. 두 곳에 중복하지 않는다.
- 검색은 full-screen 검색 화면으로 전환한다.

## 1.2 태블릿 허브 셸

```text
┌────┬──────────────────────────────────┐
│ 로고│ 페이지 제목          검색   MY    │ 64
├────┼──────────────────────────────────┤
│ 홈 │                                  │
│ 일정│          현재 페이지              │
│ 예측│                                  │
│ 커뮤│                                  │
│ MY │                                  │
│ ⋯  │                                  │
└────┴──────────────────────────────────┘
 64px navigation rail
```

- 64px 아이콘 navigation rail을 사용한다.
- 216px 데스크톱 LNB는 사용하지 않는다.
- 하단 탭은 사용하지 않는다.
- 본문은 2열 또는 master-detail 구성을 적극 사용한다.
- 검색과 사용자 메뉴는 app bar에 직접 넣되 계정 세부 정보는 popover로 연다.

## 1.3 팬 셸

```text
모바일
┌──────────────────────────┐
│ 뒤로  팀명          검색  ⋯ │ 56
├──────────────────────────┤
│ 팀 로고  이름  팔로우       │ 104~120
├──────────────────────────┤
│ 홈 일정 선수 커뮤니티 영상 ⋯ │ 44
├──────────────────────────┤
│ 팬 페이지 본문             │
└──────────────────────────┘
```

- 허브 하단 탭을 팬 페이지에서 제거한다.
- 팬 탭은 `홈 / 일정 / 선수 / 커뮤니티 / 영상 / 더보기`.
- `인스타그램 / 비난양파 / 팀 정보`는 더보기 바텀시트.
- 팀 전환은 프로필 영역의 팀명/로고에서 연다.
- 태블릿 팬 셸은 상단 프로필 96px+가로 팬 탭을 사용하고 본문만 2열화한다.

## 1.4 집중 셸

적용 경로:

- 로그인·회원가입
- 게시글 작성·수정
- 프로필 수정
- 스냅샷 viewer
- 영상 재생 집중 상태

```text
┌──────────────────────────┐
│ 취소/뒤로   화면명      보조 │ 56
├──────────────────────────┤
│                          │
│        집중 콘텐츠         │
│                          │
├──────────────────────────┤
│ 취소             주요 행동 │ 64 + safe area
└──────────────────────────┘
```

- 허브/팬 내비게이션을 모두 숨긴다.
- 현재 작업을 끝내거나 취소하는 행동만 남긴다.

## 3. 공통 상태 화면

모든 페이지 기획은 다음 상태를 가진다.

- **Loading:** 최종 화면과 같은 크기의 skeleton. 전체 spinner 금지.
- **Empty:** 왜 비어 있는지, 다음 행동이 무엇인지 한 화면 안에서 설명.
- **Error:** 오류 문장+재시도. 이전 데이터가 있으면 유지한 채 inline error.
- **Offline:** 읽을 수 있는 캐시 데이터 유지, 쓰기 action disabled.
- **Auth required:** 현재 페이지를 유지하고 로그인 sheet/화면으로 이동.
- **Long content:** 최장 팀명·선수명·닉네임·제목 fixture로 검증.

## 4. 허브·데이터 페이지 화면기획

## 4.1 홈 `/`

### 화면 목적

오늘 가장 중요한 경기와 사용자가 바로 할 행동을 10초 안에 보여준다.

### 모바일 와이어프레임

```text
┌──────────────────────────┐
│ App bar                  │
├──────────────────────────┤
│ 대표 소식 1장             │ 16:9, 최대 210
│ 제목 2줄        [바로가기] │
├──────────────────────────┤
│ NEXT MATCH               │
│ 팀 A        VS       팀 B │
│ 오늘 18:00     [예측하기] │
├──────────────────────────┤
│ 일정  대회  팀  선수  리포트 │ quick rail
├──────────────────────────┤
│ 오늘의 경기       전체보기  │
│ 경기 1행                  │
│ 경기 1행                  │ 최대 3개
├──────────────────────────┤
│ 커뮤니티  최신 | 인기       │
│ 게시글 5개                │
├──────────────────────────┤
│ 최신 영상  가로 rail        │
├──────────────────────────┤
│ 이번 주 주요 일정 3개       │
└──────────────────────────┘
```

### 화면 구성

1. 대표 소식 1장. 여러 장은 swipe, 한 화면 동시 노출 금지.
2. 다음 경기 1건. 예측 가능 여부와 CTA를 함께 표시.
3. 빠른 이동 5개.
4. 오늘의 경기 최대 3개.
5. 커뮤니티 최신/인기 각 5개.
6. 최신 영상 4개 가로 rail.
7. 월간 달력 대신 이번 주 일정 3개.

### 모바일에서 표시하지 않음

- 전체 월간 달력
- 전체 순위와 최근 폼 동시 노출
- 예측 목록 내부 스크롤
- 광고 여러 개
- 데스크톱 모자이크 hero

### 화면 이동

- 대표 소식 → 연결된 경기/리포트/외부 링크
- 다음 경기 → 경기 상세 또는 예측 sheet
- 오늘 경기 전체보기 → `/schedule`
- 커뮤니티 → `/community`
- 영상 → 영상 원문 또는 팬 영상 상세

### 태블릿 기획

```text
┌───────────────────────┬──────────────┐
│ 대표 소식              │ NEXT MATCH   │
├───────────────────────┴──────────────┤
│ 빠른 이동 6개                          │
├───────────────────────┬──────────────┤
│ 오늘 경기              │ 커뮤니티      │
├───────────────────────┴──────────────┤
│ 최신 영상 3열                          │
├──────────────────────────────────────┤
│ 이번 주 일정                           │
└──────────────────────────────────────┘
```

### 상태

- 경기가 없으면 NEXT MATCH 대신 `다음 일정 미정`+전체 일정 링크.
- hero 데이터가 없으면 영역 자체를 제거하고 NEXT MATCH가 첫 콘텐츠가 된다.
- 비로그인 예측 CTA는 로그인 후 현재 경기로 복귀.

### 완료 조건

- 390×844에서 대표 소식과 NEXT MATCH CTA가 함께 보인다.
- 모바일 기본 문서 길이는 6~8개의 짧은 화면 단위 안에 끝난다.
- 달력과 전체 순위가 홈에 직접 렌더링되지 않는다.

## 4.2 일정 `/schedule`

### 화면 목적

가장 가까운 경기를 확인하고, 필요한 경우 날짜·대회·팀으로 빠르게 좁힌다.

### 모바일 와이어프레임

```text
┌──────────────────────────┐
│ 경기 일정      [달력] [필터] │
├──────────────────────────┤
│ ‹  14  15  [16] 17  18  › │ 주간 strip
├──────────────────────────┤
│ 다음 경기                  │
│ 18:00  팀 A  VS  팀 B      │
│ 대회 · 라운드      [상세]    │
├──────────────────────────┤
│ 선택 날짜 경기              │
│ 경기 compact row           │
│ 경기 compact row           │
└──────────────────────────┘
```

### 화면 구성

1. 제목+달력 아이콘+필터 아이콘.
2. 7일 주간 strip.
3. 오늘 이후 가장 가까운 경기 1건 featured row.
4. 선택 날짜의 나머지 경기 compact rows.
5. 과거 날짜에서는 결과 스코어 우선.

### 달력 modal

- 월간 달력은 본문에서 제거한다.
- 날짜에 경기 존재 dot만 표시.
- 날짜 선택 즉시 modal을 닫고 해당 날짜 목록으로 이동.
- 이전/다음 월, 오늘로 이동.

### 필터 sheet

- 연도, 대회, 팀, 상태.
- `초기화 / 적용` 하단 action.
- 본문에는 적용된 조건 chip 최대 2개만.

### 태블릿 기획

```text
┌──────────────────────────┬─────────────┐
│ 주간 strip + 경기 목록     │ 월간 달력    │
│ 다음 경기 featured         │ 선택일 요약   │
│ 날짜별 rows                │ 필터 요약     │
└──────────────────────────┴─────────────┘
```

- 세로 tablet은 목록 60%, 달력 panel 40%.
- 가로 tablet은 날짜 목록과 선택 경기 master-detail.

### 상태

- 선택 날짜에 경기 없음: `이날 예정된 경기가 없습니다`+가까운 경기 날짜 제안.
- 로고 없음: 약칭 fallback mark.
- TBD 경기: 팀명 자리에 `상대 미정`, CTA는 일정 상세만.

### 완료 조건

- 월간 달력이 모바일 본문 높이를 차지하지 않는다.
- 최초 화면에서 다음 경기 1건이 보인다.
- filter와 calendar는 각각 44px 아이콘으로 진입한다.

## 4.3 대회 목록 `/tournaments`

### 화면 목적

현재 진행 중인 대회를 먼저 찾고, 지난 대회는 시즌 단위로 탐색한다.

### 모바일 와이어프레임

```text
┌──────────────────────────┐
│ 대회            [시즌] [필터]│
├──────────────────────────┤
│ 진행 중                    │
│ Featured tournament       │
│ 이름 · 기간 · 현재 단계     │
├──────────────────────────┤
│ 예정된 대회                 │
│ compact card rail         │
├──────────────────────────┤
│ 종료된 대회                 │
│ 2026  ›                   │
│ 2025  ›                   │
└──────────────────────────┘
```

### 화면 구성

- 진행 중 대회 1개를 featured.
- 동시에 여러 대회가 진행 중이면 가로 rail.
- 예정 대회는 120~148px compact cards.
- 종료 대회는 시즌별 접힌 목록.
- 카드에는 이름, 기간, 상태, 현재 단계만.

### 태블릿 기획

- 진행 중 featured full width.
- 예정/최근 종료 대회는 2열 cards.
- 우측에 시즌 quick filter panel을 둘 수 있다.

### 상태

- 진행 중 대회가 없으면 예정 대회가 첫 섹션.
- 이미지/테마가 없어도 색상 없는 중립 카드가 완성형이어야 한다.

## 4.4 대회 상세 `/tournaments/[segment]`

### 화면 목적

대회의 현재 상황을 파악하고 일정·순위·대진 중 원하는 정보로 이동한다.

### 모바일 와이어프레임

```text
┌──────────────────────────┐
│ ‹ 대회명              공유 │
├──────────────────────────┤
│ 대회명 · 기간 · 진행 상태   │ compact hero
├──────────────────────────┤
│ 개요  일정  순위  대진표     │ sticky tabs
├──────────────────────────┤
│ 선택 탭 콘텐츠              │
└──────────────────────────┘
```

### 탭별 화면

#### 개요

- 현재 단계, 다음 경기 1건, 참가팀 가로 rail, 대회 설명 접기.

#### 일정

- `/schedule`의 compact 경기 rows 재사용.
- 날짜 filter와 완료/예정 segmented control.

#### 순위

- 핵심 3열 `순위 / 팀 / 승패`.
- 행을 누르면 득실·세부 지표가 펼쳐진다.
- 그룹이 있으면 그룹 selector.

#### 대진표

```text
┌ R1 | R2 | 준결승 | 결승 ┐
│ 선택 라운드              │
│ 팀 A        2            │
│ 팀 B        1            │
│ 경기 상세 ›              │
└─────────────────────────┘
```

- 모바일에서 전체 bracket를 축소하지 않는다.
- 라운드 selector+세로 match cards.
- `전체 대진표`는 별도 landscape viewer.

### 태블릿 기획

- 상단 hero+대회 요약 2열.
- 탭 본문은 일정/순위 2열 가능.
- 대진표는 연속 2개 라운드까지만 표시하고 전체 viewer는 별도.

### 상태

- 대진 미정은 빈 bracket 칸을 만들지 않고 `대진 확정 전` 안내.
- 그룹/라운드 데이터가 없으면 해당 탭 숨김.

## 4.5 팀 목록 `/teams`

### 화면 목적

```text

### 탭별 화면

- **개요:** 팀 지표 4개, 팬 평점 요약, 다음 경기 1건.
- **로스터:** 주전 5명 2열 또는 가로 cards, 코치/스태프 접기.
- **경기:** 최근 5경기와 다음 일정, 전체 일정 이동.
- **기록:** 시즌 요약, 수상 timeline 최근 3개, 전체 펼치기.

### 제거·이동

- 4:5 대형 hero 이미지를 첫 화면에서 제거.

### 태블릿 기획

├─────────────────┴────────────────────┤

### 상태

- 현 시즌 기록 없음: identity와 로스터는 유지, 기록 탭에 empty state.
- 팬 페이지 없음: 팬 CTA를 숨기고 공식 링크를 더보기에 유지.

### 상태

├──────────────────────────┤

├──────────────────────────┤
│ 게시글 row                  │
│ 게시글 row                  │
└──────────────────────────┘
```

### 피드 mode

- **최신:** 시간순 compact rows.
- **인기:** 기간 selector `오늘 / 주간`, 추천·댓글 중심.
- **갤러리:** 2열 image cards.

### 게시글 row

- 게시판 13px.
- 제목 16px 최대 2줄.
- 작성자·시간 13px, 댓글/추천 숫자.
- thumbnail이 있으면 72×72px, 없으면 텍스트 full width.

### 제거·이동

- 데스크톱 인기글 aside 제거. `인기` mode로 통합.
- 광고 aside를 목록 아래 적층하지 않음.
- 게시판 탭 2줄 wrap 금지. 가로 rail 또는 board sheet.

### 태블릿 기획

```text

│ feed                    │ 실시간 인기 5 │
│                         │ 게시판 목록   │
└────────────────────────┴──────────────┘
```

- 768~899px는 feed full width.
- 900px 이상에서 우측 280px aside 1개.

### 상태

- empty: 선택 게시판 설명+첫 글 작성 CTA.
- error: 기존 feed 유지+상단 재시도 banner.

## 5.2 게시판 직접 경로 `/community/[board]`

### 화면 목적

### 화면 기획

## 9.1 view model 분리

각 화면은 원본 데이터를 직접 전부 받지 않고 기기별 view model을 만든다.

```ts
type MobileMatchSummary = {
  id: string;
  startsAt: string;
  status: "upcoming" | "live" | "completed";
  teamA: MobileTeamIdentity;
  teamB: MobileTeamIdentity;
  score?: [number, number];
  tournamentShort: string;
  roundShort?: string;
  primaryAction: "predict" | "watch" | "detail";
};
```

- 모바일 component가 전체 tournament/team/match object를 받아 임의로 잘라내지 않는다.
- `shortName`, short tournament label, primary action을 data layer/view-model에서 명시한다.
- tablet은 필요한 추가 metadata를 별도 field로 받는다.

## 11. 화면 단위 검수 기준

각 경로는 다음 질문에 답할 수 있어야 한다.

1. 이 화면의 첫 과업은 무엇인가?
2. 390×844 첫 viewport에서 그 과업이 보이는가?
3. PC에는 있지만 모바일 첫 화면에서 제거한 데이터가 무엇인가?
4. 제거한 데이터는 어디에서 다시 접근하는가?
5. modal/sheet를 닫으면 focus와 scroll이 복원되는가?
6. tablet에서 단순히 모바일 카드가 넓어지기만 하지 않는가?
7. empty/loading/error/long content 상태가 있는가?
8. 이전 화면으로 돌아가면 filter/tab/scroll이 유지되는가?

## 11.1 필수 화면 크기

- 320×568
- 360×800
- 390×844
- 768×1024
- 1024×768
- 1280×800
- 1440×900
- 500~1100px 연속 resize
- 200% browser zoom

## 11.2 화면기획 불이행 판정

다음 중 하나면 구현을 다시 한다.

- desktop component에 `hidden md:block`만 붙이고 mobile card를 일부 추가.
- desktop 섹션 순서를 그대로 1열로 유지.
- 달력·표·bracket를 폭만 줄여 직접 노출.
- `truncate`로 핵심 identity 손실.
- tablet이 handset의 확대판.
- 첫 화면에 CTA 없이 설명·목록만 존재.
- 삭제한 정보에 접근할 경로 없음.
