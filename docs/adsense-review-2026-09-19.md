# AdSense 재심사 기술 점검 — 2026-09-19

## 결론과 상태

해설을 추가하거나 홈·커뮤니티 순서를 바꾸지 않고 경기 대표 URL, 빈 기록 화면, 통계 집계와 표본 표시를 수정했다. 운영 사이트에 배포하고 비로그인 HTTP 요청으로 15개 경로를 검증했다. AdSense 재심사를 제출했으며 현재 상태는 **준비 중 / 사이트의 광고 게재 가능 여부 검토 중 / 리뷰가 요청됨**이다. 승인 완료를 의미하지 않는다.

이 오류가 AdSense 반려의 유일한 원인이라는 근거는 없다. Search Console의 색인 상태와 AdSense 심사는 서로 다르며, 검색 색인 수 자체를 승인 요건으로 해석하지 않는다.

## 후속 검토: 해설을 추가하지 않는 재심사 방향

사용자는 스탯 해설 추가를 제외한 승인 개선 방향을 요청했다. 아래 계정·운영 사이트 진단은 구현 전 검토 당시의 기록이다. 이후 사용자가 홈 재배치를 제외한 실행을 요청해 수정·배포를 진행했다.

**후속 실행 범위:** 사용자가 2번 홈 재배치를 제외하고 진행하도록 요청했다. 커뮤니티의 중요도와 현재 홈 섹션 순서를 유지한다. 아래 홈 재배치 제안은 취소되었으며 실행하지 않는다.

### 계정과 운영에서 재확인한 사실

- AdSense 사이트 상세: **주의 필요 / 가치가 별로 없는 콘텐츠**. 최종 업데이트는 **2026-09-16 00:50 KST**, ads.txt는 **승인됨**. Google은 문제 URL을 개별 지정하지 않았다.
- 운영 홈의 결승·결승 진출전 링크 두 개를 쿠키 없는 HTTP 요청으로 확인했다. 경기 본문은 200이고 스탯이 HTML에 있으나, 선언된 canonical은 두 개 모두 404였다. 기존 로컬 수정이 아직 운영에 반영되지 않은 상태다.
- 운영 사이트맵은 379개 URL이며 `/champions` 목록이 없다. 기존 로컬 수정은 목록을 추가하지만 챔피언 상세 URL까지 추가하지는 않는다. 목록·상세를 사이트맵에 넣는 것은 발견을 돕는 개선이며 승인 필수 조건은 아니다.
- 홈은 최근 매치 다음에 외부 뉴스, 커뮤니티 최신글, POM을 배치한다. 팀 순위가 있는 `LCK 현황` 영역은 `hidden ... xl:grid`라 작은 화면에서는 보이지 않는다. 경기 통계보다 외부 링크·커뮤니티의 비중이 크게 느껴질 수 있다는 것은 구성에 대한 판단이며 Google의 확정 사유가 아니다.
- 챔피언 오리아나 상세에서 실제 픽·밴·승률, 빌드별 세트 수, 대회·패치 필터와 상대 전적·선수·경기·통계 탭을 확인했다. 선수 페이지 코드에도 동 포지션 평균 비교와 시즌·챔피언 기록이 있다. 이미 있는 기능을 새로 만들라고 권하지 않는다.
- 현재 광고 경로 정책은 `/news`, 로그인·설정·고객센터 등을 허용하지 않으며, 선수 상세 수동 광고는 경기 기록이 있을 때만 켜진다. 이미 적용한 광고 차단을 새 필수 작업처럼 반복하지 않는다.

### 정책 해석

- [복제된 콘텐츠 정책](https://support.google.com/publisherpolicies/answer/11190248?hl=en)은 해설뿐 아니라 선별·구성 또는 다른 방식의 부가가치를 언급한다. 해설 글을 필수 요건으로 해석하지 않는다. 데이터 집계·비교·탐색을 개선하는 방향은 이 원칙에 근거한 서비스 개선 제안이며, Google이 MINION의 가치를 인정했다는 뜻은 아니다.
- [콘텐츠와 사용자 경험 안내](https://support.google.com/adsense/answer/10015918?hl=en)는 충분한 고유 콘텐츠, 유사 사이트 대비 가치, 명확한 탐색과 정상 목적지를 요구한다. 글 개수나 글자 수를 임의의 합격 기준으로 만들지 않는다.
- [게시자 콘텐츠가 없는 화면 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=en)에 따라 빈 화면·미완성 화면·오류 화면은 광고 대상에서 제외한다.

## 확인된 URL 오류와 수정

운영 홈페이지는 Leaguepedia 원본 ID를 인코딩한 경기 링크를 사용했다.

```text
정상 페이지:
/matches/LCK%2F2026%20Season%2FSeason%20Playoffs_Finals_1

해당 페이지가 선언한 canonical과 og:url:
/matches/LCK/2026%20Season/Season%20Playoffs_Finals_1
```

Next.js의 디코딩된 `params.matchId`를 메타데이터에 그대로 사용하면서 `/`가 경로 구분자가 됐다. 홈페이지에서 추출한 최근 경기 4개의 대표 주소 모두 직접 HTTP 조회에서 404였다. 사이트맵은 이미 같은 경기의 UUID 주소를 사용해 내부 링크와 대표 주소가 일치하지 않았다.

수정:

- 공개 `matchHref`는 UUID를 사용한다. 이를 사용하는 홈·일정·팀·선수·세트 링크가 같은 주소를 안내한다.
- 경기 canonical과 Open Graph URL도 `matchHref(match)`를 사용한다. UUID·원본 ID·탭 쿼리로 진입해도 같은 정상 대표 주소를 선언한다.
- 기존 인코딩된 원본 ID 주소는 계속 조회할 수 있다. 관리자 원본 ID 링크 규칙은 유지한다.
- 경기 평가의 스냅샷 링크도 UUID를 사용해 디코딩된 원본 ID가 하위 경로로 들어가지 않게 한다.
- 사이트맵은 동일한 링크 함수를 사용하며, 빠져 있던 `/champions` 목록을 추가한다.
- 리디렉션 진입점 `/tournaments` 대신 실제 대회 상세를 제출한다. 최신 시즌에 경기 레코드가 없는 대회는 사이트맵에서 제외한다. 현재 Worlds·ENC 두 항목이 해당하며 사이트 기능은 유지한다.

## 공개 접근과 콘텐츠 표본

로그인 쿠키 없는 HTTP 요청으로 사이트맵 전체 379개 주소를 분류하고, 정적 경로·팀 홈·사이트맵의 선수 상세 전체·경기 표본·챔피언 표본 등을 조회했다. 오류 경로와 폐기 경로를 포함해 113개 URL, 봇 User-Agent 비교 6회를 포함해 총 119회 검사했다.

- `/`, `/robots.txt`, `/sitemap.xml`, `/ads.txt`는 HTTP 200.
- robots.txt는 주요 콘텐츠와 `/_next/static`을 차단하지 않는다.
- Googlebot, Mediapartners-Google, AdsBot-Google User-Agent로 홈·대표 경기 조회 시 모두 200이고 본문 데이터가 HTML에 포함됐다. User-Agent 모방만으로 실제 Google 네트워크 접근을 입증하지 않으며 위 Search Console 실시간 검사로 보완했다.
- 임의의 존재하지 않는 선수·경기·챔피언 주소는 스트리밍 응답 특성상 HTTP 200에 `noindex`를 반환했다. `notFound()` 호출도 확인했다. 이를 정상 콘텐츠로 세지 않았다.
- 폐기된 `/guide`, `/reports`는 410을 유지한다.

- 사이트맵의 선수 상세 **61개 중 5개**는 실제 화면에 경기 지표·최근 경기 데이터가 없었다: Croco, Ellim, FIESTA, Hype, Vincenzo. 로스터 정보 자체의 용도는 있으므로 자동 삭제하거나 일괄 `noindex`하지 않았다. 기록 수집 대상 여부는 별도 데이터 운영 판단이 필요하다.

## 배포 후 확인 계획 — 최초 검토 당시

1. 운영 홈의 경기 링크, 기존 원본 ID 페이지의 canonical과 og:url이 UUID 주소로 통일됐는지 확인한다.
2. 수정된 사이트맵과 대표 경기·선수·챔피언 페이지를 Search Console에서 확인한다. 실시간 테스트와 색인 상태는 구분한다.
3. 필요한 대표 URL만 색인 생성 요청하고, 실제 재크롤링 상태를 확인한다. 모든 URL을 반복 요청하는 방식은 사용하지 않는다.
4. 실제 AdSense 사이트 상세의 최신 사유를 다시 확인한 뒤 변경 사항이 운영에 반영된 상태에서 재심사를 요청한다. 색인 수나 정해진 대기일을 승인 보장 기준으로 삼지 않는다.

- 선수 통계는 승자가 기록된 세트를 기준으로 집계한다. 공식 POM은 선택한 대회 구간의 완료 경기만 계산하며, 승패·챔피언 승률은 현재 소속팀이 아닌 해당 경기 당시 소속팀으로 계산한다.
- 경기 기록 없는 선수는 프로필·팀 정보·팬 평가를 유지하고, 빈 시즌 요약·챔피언 표·최근 경기 틀 대신 하나의 기록 안내와 선수단·일정 링크를 표시한다. 광고 차단 표시도 추가했다.
- 경기가 없는 대회는 일정 등록 전 상태와 저장된 대회 기간(있는 경우), 전체 일정 링크를 표시한다. 대회 광고는 대회 전체 경기 수가 아닌 현재 선택한 순위·POM·대진표의 실제 내용 유무를 기준으로 요청한다.
- 챔피언 목록·상세는 선택한 필터 범위의 세트 수를 표시한다. 상세에서 픽밴률의 완전한 드래프트 표본과 누락 제외 수, 선택 포지션의 승률 표본을 구분한다. 픽·밴 모두 없는 범위는 여러 빈 탭 대신 단일 안내를 표시한다.
- 선수의 집계 구간·경기/세트 수·최근 경기일, 승패·최근 폼·POM 집계 기준을 표시한다. 경기일은 데이터 갱신 시각으로 표현하지 않는다.
- 읽기 전용 Supabase Data API 조회로 Faker의 POM이 LCK Cup 2회 / Rounds 1-2 3회로 구분됨을 확인했다. DB 자료·스키마·권한은 변경하지 않았다.
- `npm.cmd run typecheck`, 변경 파일 ESLint, `npm.cmd run lint:typography`, `npm.cmd run build`, `git diff --check` 통과.
- 실제 선수 페이지 함수를 데이터 fixture로 실행해 대회별 POM, 이적 전 팀의 승리·챔피언 승률, 미결정 세트 제외, 빈 프로필의 팬 평가 유지·광고 제외를 검증했다. 검증 스크립트는 git 제외 경로 `.tmp/verify-player-review.cjs`에 있다.
- 로컬 프로덕션 서버 실행은 자동 승인 검토에서 차단됐고 구체적인 사유가 제공되지 않았다. 빌드는 통과했지만 로컬 브라우저 확인은 수행하지 못했다.
