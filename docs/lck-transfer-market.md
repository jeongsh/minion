# LCK 이적시장

- 공개 화면: `/transfers`
- 관리자 화면: `/admin/transfers`
- 연도 선택: `?season=2026` (스토브리그가 시작되는 해)
- 저장소: `public.lck_transfer_markets`. 현재 선수 소속과 경기 로스터는 변경하지 않는다.

## 데이터와 표시

`LCK 스토브리그/{연도}` 원문의 팀별 엔트리 표, 타임라인 표, FA 현황 표를 읽는다. 팀별 화면은 포지션별 첫 줄의 주전과 감독을 비교한다. 계약 종료 예정자는 실제 계약 종료 발표와 구분한다. 본문 서술과 전망, 루머를 자동으로 공식 발표로 분류하지 않는다.

LCK 팀으로 들어오거나 나가는 이적과 기존 LCK 선수의 후속 이동을 포함한다. 따라서 `LCK → FA → 해외 팀` 이동도 추적한다. 선수 이동 목록은 팀, 포지션, 변동 종류와 이름으로 검색할 수 있다. 보도 기록은 선택해서 표시하며 다음 시즌 로스터에는 반영하지 않는다.

변동 소식은 원문의 구조화된 표에서 수집한다. 본문에만 먼저 올라온 소식은 표에 반영될 때까지 자동 수집에 포함되지 않을 수 있다. 이 경우 관리자가 출처 링크와 함께 직접 등록할 수 있다. 가져온 기록은 `나무위키`로 표시한다. 관리자가 확인한 기록은 `공식` 또는 `보도`로 지정할 수 있다.

팀마다 한 행을 사용하고 왼쪽에는 탑부터 감독까지 세로 로스터, 오른쪽에는 합류와 이탈 명단을 나란히 배치한다. 좁은 화면에서는 로스터 아래로 이동 현황을 배치한다. 팬톡과 공용 버튼 디자인을 사용해 전체 팀 또는 특정 팀을 선택하며, 합류와 이탈 명단은 인원 제한 없이 모두 표시한다. 상단 최근 변동은 선택한 팀과 관련된 확인된 소식 중 최신 3건을 보여준다.

개발 서버의 기본 `/transfers` 화면에는 기인의 GEN → HLE 이동 하나를 화면에만 추가한다. 별도 예시 배너를 노출하지 않으며 최근 변동, 로스터, 양 팀 이동 현황에서 같은 UI를 검토할 수 있다. `?preview=off`로 실제 데이터만 확인할 수 있다. 이 값은 DB에 저장하지 않으며 프로덕션에서는 무시한다.

계약 종료일은 최신 재계약 발표를 우선하고, 발표가 없으면 해당 팀 선수의 등록된 계약 종료일을 사용한다. 원문에 연도만 적혀 있거나 FA 예정 목록만 확인되면 연도를 표시하고 툴팁에서 종료 예정임을 알린다. 새 팀 계약에 이전 팀의 계약일을 붙이지 않는다. 그 외는 공란으로 표시한다. 날짜 뒤의 `까지`와 로스터 비교 열의 연도 제목은 표시하지 않는다.

## 동기화

관리자의 **나무위키 동기화** 버튼은 해당 연도 원문을 직접 요청한다. URL을 임의로 입력받지 않는다. 관리자 인증은 모든 서버 액션에서 다시 확인하며 일반 사용자에게는 DB 읽기 권한만 부여한다.

`snapshot`은 문서 수집값이고 `manual_events`는 수동 수정값이다. 수집으로 수동 수정값을 덮어쓰지 않는다. 가져온 기록을 수정한 경우 같은 ID의 원문보다 수동 기록을 우선한다. 수동으로 먼저 등록한 공식 기록과 나중에 수집된 동일 발표는 중복 표시하지 않는다. **원문으로 복원**하면 해당 수동 수정만 제거한다.

원문 제목, 10개 팀, 타임라인, 병합 셀과 날짜를 검증한다. HTTP 오류, 응답 제한, 구조 오류, 과거 문서 응답 시 저장하지 않는다. 마지막 정상 데이터를 유지한다. 시간 제한은 20초, 응답 제한은 2MB, 버튼 재확인 간격은 60초다. 동시 실행은 이전 확인 시각을 비교하여 오래된 응답의 덮어쓰기를 방지한다.

## 자동 실행

`.github/workflows/sync-transfers.yml`은 매년 9~2월에 매시간 실행한다. GitHub 예약 실행은 지연될 수 있다. 워크플로가 기본 브랜치에 반영되고 Actions가 활성화되어야 자동 실행이 시작된다.

필요한 저장소 Secrets는 기존 수집 작업과 같은 `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`다. 서비스 키는 브라우저로 보내지 않는다. 관리자 화면의 **자동 동기화 허용**을 끄면 예약 작업이 해당 시즌을 건너뛴다. 수동 동기화 버튼은 계속 사용할 수 있다.

로컬 실행:

```powershell
node --experimental-strip-types scripts/sync-transfers.ts --season=2026
```

스크립트는 로컬 `.env.local` 또는 CI 환경변수를 사용한다. `--scheduled`를 붙이면 자동 동기화 허용 상태를 따른다. 1~2월에는 전년도 스토브리그 문서를 사용한다.

나무위키의 공개 HTML을 읽는 방식이므로 원문 구조 또는 접근 정책 변경 시 수정이 필요하다. 수동 동기화도 동일한 원문 접근 제한을 받으며 제한을 우회하지 않는다. 실패 원인은 관리자 버튼 결과 또는 GitHub Actions 로그에서 확인한다.

## 확인 기록

2026-10-11 원문 수집과 초기 저장 완료: 10개 팀, 재계약 6건, 계약 종료 예정 39명. 합성 문서로 병합 셀, FA 이후 해외 이적, 문서 오류, 수동 수정 우선, 중복 제거, 동시 동기화와 실패 보존을 검증한다.

마이그레이션 `20261011052113_add_lck_transfer_market.sql`은 CLI로 생성한 파일을 적용 후 서버가 부여한 버전에 맞춰 정렬한 것이다. 원격 적용과 RLS, 공개 조회, 일반 사용자 쓰기 차단, 문서 제약, advisor 확인을 완료했다. 로컬 Docker 데몬은 실행 중이 아니어서 로컬 DB 재생 검증은 하지 않았다.
